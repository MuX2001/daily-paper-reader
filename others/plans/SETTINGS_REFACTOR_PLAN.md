# 工作台设置重构计划

状态：用户确认后已实施，验证与交付记录见文末。

## 1. 目标与现状

以用户提供的五个Tab规范为主：账户与同步、网页AI聊天、云端精读、导出与Obsidian、数据与维护。设置弹窗改名“工作台设置”。本次解决信息组织、配置生效位置、保存反馈和重复输入问题。

当前实现集中在reader/src/main.tsx的单个Modal中；表单直接绑定应用运行状态，尚无真正的草稿/已保存分离。AccountLogin同时包含登录和本地测试入口；DeepReadSetup的可编辑字段实际只是Secrets参考；refresh捕获异常但不返回结果，不能直接用于“立即同步成功”的判断。重构需要拆组件与状态，不只是更换CSS。

## 2. 布局与通用交互

- 桌面宽度820px，受视口宽度限制；最大高度82vh，导航190px。标题/状态摘要固定，右侧内容独立滚动。
- 小于640px时导航改为顶部横向滚动Tab条，内容单列；表单宽度不得撑出屏幕，适配手机键盘。
- 每张可保存卡片有自己的操作栏、提交中状态、成功/失败反馈。无需网络的本地保存也处理存储失败，不使用假延迟模拟加载。
- 弹窗支持焦点约束、Escape、关闭后归还触发按钮焦点；Tab支持键盘导航、aria-selected、对应tabpanel。状态点配文字/可访问标签，不只靠颜色。
- 默认进入账户Tab；论文聊天的配置按钮直达聊天Tab，精读缺配置直达精读Tab，Obsidian缺配置直达导出Tab。
- 每个Tab独立维护草稿与已保存配置。切Tab保留草稿并显示“未保存”；测试草稿不自动保存、不改变正在使用的连接。
- 关闭存在未保存草稿的弹窗时，提供“继续编辑/放弃更改”，不默默丢失，也不自动保存。Secrets助手选项属于参考偏好，不标成“云端未保存”。
- 修改任何参与验证的字段，立即失效该字段组合的验证结果；迟到响应不得给新配置标绿。

## 3. 状态语义

- 绿：相关操作已验证成功，而不只是填了文本。
- 黄：已保存但缺少本次密钥、尚未验证，或只完成一部分；显示具体缺项。
- 灰：可选功能未启用。
- 补充红色错误状态：验证/同步失败；保留可读错误和重试操作。
- 顶部只有当前账户状态读取成功且无待完成状态写入时显示“云端已同步（邮箱前缀）”；否则分别显示“未登录/已登录，待同步/正在同步/同步失败”。另显示最近成功同步时间。云端同步不包括未保存的个人笔记草稿。
- 云端精读分开显示调度检查与Secrets状态。网页无法确认Secrets实际值时，明确显示“云端模型待实际任务验证”，不宣称整条精读链路可用。
- 导出Tab只表示偏好已配置，不把Obsidian URI发出当作桌面保存成功。维护Tab不因为“没有历史记录要迁移”而显示警告。

## 4. 五个Tab

### 4.1 账户与同步

账户主卡：已登录显示邮箱、同步状态、立即同步、退出登录；未登录显示邮箱密码和登录，保留低调的注册入口，避免新用户无法开始。GitHub登录仅在实际检测到provider开启时显示，检测失败不阻塞邮箱登录。

数据库卡：已验证时默认折叠，显示实际项目域名和“修改配置”；首次未配置自动展开。字段沿用Supabase URL和Publishable/anon key，按钮改“保存并验证连接”。

验证先使用候选连接，不立即替换当前有效客户端。区分配置格式、Auth服务可达、当前账户读取paper_states三个阶段；未登录时只能报告连接验证通过、等待登录，不声称状态表同步成功。失败保留原连接和会话。成功更换项目才清理旧项目内存状态，并要求在新项目登录。

“立即同步”复用现有状态加载和隔离逻辑，但返回明确结果；失败不显示成功。不提交个人笔记草稿。退出登录必须处理错误，不能本地清空后假装退出成功。

### 4.2 网页AI聊天

顶部说明请求由浏览器直接发出，与Actions精读独立。预设为OpenAI、DeepSeek、OpenRouter、自定义；填入Base URL，仍允许修改，模型按已核实的兼容选项或手动ID填写。切换预设清除旧验证结果，不把其他服务的密钥自动用于新端点测试。

字段：预设、Base URL、模型ID、API Key（显示/隐藏）、“在当前浏览器记住API Key（仅限个人设备）”。

操作：“测试连接”“保存聊天设置”。测试为用户主动点击的一次最小Chat Completions请求，固定短输入，不携带论文或个人笔记，有超时和取消；提示可能有极少量API费用。只有取得有效模型响应才标记成功。显示401/403、余额或配额、模型不存在、限流、网络/CORS等可辨识错误；浏览器无法区分的网络问题不猜测根因。

默认不记住密钥。勾选后明确保存到当前浏览器localStorage；取消勾选立即移除已持久化密钥，本次已保存的内存密钥可继续用到刷新或清除。

### 4.3 云端精读（GitHub Actions）

顶部说明必须同时完成网页调度与云端Secrets。

A卡——GitHub调度连接：仓库、分支、Token、显示/隐藏、记住Token；保存任务设置与验证仓库/权限入口。权限说明保留Actions读写；研究管理保存配置另外需要Contents写权限，不扩大本次精读必需权限。

验证检查Token有效身份、仓库访问、指定分支、已注册的daily-paper-reader.yml入口和Actions可读性；精读沿用pipeline_action=deep-read，不恢复只在dev的新workflow直派缺陷。GitHub读取接口成功不保证fine-grained Token拥有Actions写权限，因此反馈“仓库与工作流可访问，触发权限待首次任务确认”。不为测试权限偷偷启动付费任务或更改工作流。

B卡——云端模型配置：标注“只读参考 · 在GitHub仓库中生效”。预设下方显示三个变量的只读行，逐行复制；API_KEY行只展示“填写服务商密钥”，复制操作复制变量名，绝不将提示文本当真实密钥。模型/地址行明确区分复制变量名与复制值。自定义服务提供单独的参考值编辑区域，结果仍渲染成只读Secrets清单，无“保存到云端”按钮。动态生成Secrets链接，仓库格式无效时禁用并解释。

C卡——提示词：默认折叠，只读、等宽、复制提示词、当前仓库/分支源码链接。继续与src/deep_read_prompt.txt共用，说明长文有分段提取流程，不承诺页面能修改后台提示词。

### 4.4 导出与Obsidian

模式卡片：仅下载Markdown、直接发送Obsidian、两者同时显示。选择确实控制论文页知识库的导出按钮；BibTeX和聊天客户端精读材料独立保留。即使选择仅Obsidian，URI过长时仍保留完整Markdown下载兜底。

仅Markdown时Obsidian参数折叠；其他模式展开Vault、收件箱目录、笔记命名格式。只下载不需要Vault；启用Obsidian但未填Vault时明确提示缺项，不标为已就绪。

命名格式包含原有稳定ID（兼容默认）、日期-标题、arXivID-标题。预览使用当前论文，未选论文时标明示例。日期优先论文已知精确公布日，无完整日期时用明确的“日期未知”占位，不用导出当天冒充论文日期；会议论文不伪造arXiv ID。清理非法字符和路径段、控制长度，标题格式附稳定论文/版本标识以避免重名，预览与实际下载/URI共用同一函数。

“测试打开Obsidian”只打开指定Vault，不创建或覆盖笔记；提示“已请求打开，请在桌面确认”，不标成同步成功。“保存导出偏好”按选中模式验证；Actions私有笔记库的目录仍由OBSIDIAN_NOTES_FOLDER控制，不混用。

### 4.5 数据与维护

迁移流程：选择浏览器/文件来源 → 选择旧用户名（有需要时）并预览 → 导入当前账户。复用legacyBackup/planMigration/importMigration，不重写解析或改变1/2/3/4映射。展示真实可导入/跳过/冲突数量，收藏与已读计数允许重叠并说明；当前旧格式不包含可迁移笔记时，不编造“发现N条笔记”。未登录禁用导入并提供跳到账户Tab按钮。保留原始JSON备份下载。

本机密钥清除：一键清除新功能保存的聊天API Key、GitHub Token、记住开关，以及对应运行内存与尚未保存的密钥草稿；使密钥验证结果失效。保留Supabase公开连接、登录会话、阅读数据、笔记、仓库/模型地址和导出偏好。不声称撤销已经发送到服务器的请求或清除其他旧应用的独立加密文件。

开发者选项：底部默认折叠，本地测试入口移入此处，保留只在已有合法回环配置可用时展示的限制；警示切换后是独立数据库，不自动覆盖线上配置。

## 5. 存储兼容与组件拆分

现有键全部保留：dpr.cloud.url/key、dpr.chat.endpoint/model、dpr.github.repository/ref、dpr.obsidian.vault/folder。Supabase表结构、论文身份和状态迁移契约不变。

新增键建议：

| 键 | 内容与默认 |
| --- | --- |
| dpr.settings.remember_secrets | {chat:false, github:false}，分别控制，不合并成全局开关 |
| dpr.chat.api_key | 仅明确勾选时存储 |
| dpr.github.token | 仅明确勾选时存储 |
| dpr.settings.export_mode | markdown / obsidian / both |
| dpr.obsidian.naming | stable-id / date-title / id-title，缺省stable-id |

remember_secrets缺失或格式非法时按false处理，不自动读取遗留密钥。export_mode缺失时：已有非空Vault的老用户保持both，其他用户默认markdown。清除/取消记住后刷新不会恢复旧密钥。所有持久化处理存储被禁用、写入失败和损坏JSON，显示可操作反馈，不静默假保存。

计划组件：settings/SettingsDialog、AccountSettings、ChatSettings、DeepReadSettings、ExportSettings、MaintenanceSettings；settings/config.ts与验证模块负责读写、默认值和请求。main.tsx只保留实际运行配置/状态和入口，不继续累加长JSX。拆出LocalTestConnection，复用AccountLogin、迁移工具、错误格式化和notes工具。五个Tab草稿由设置层统一持有，防止卸载丢失；应用只接收保存成功后的配置。

## 6. 分步实施与验收

1. 布局与状态基础：抽出SettingsDialog，五Tab、响应式、焦点、草稿/保存分离、独立结果反馈。先把现有功能正确归位。
2. 账户与维护：登录态主卡、实际同步状态、候选连接验证、隐藏未启用OAuth、本地入口下移、迁移步骤化。复验已有邮箱登录/收藏/笔记正常。
3. AI聊天与云端精读：共用预设、眼睛按钮、独立记住选项、最小聊天测试、只读GitHub验证、Secrets复制清单、提示词源码链接。
4. 导出与收尾：导出模式真正控制按钮、命名预览与落地、一键清除密钥、未保存提示、使用指南。
5. 集成验收：类型/构建与相关单元测试；浏览器真实DOM和下载/剪贴板/URI验证；更新旧测试选择器与导航步骤。桌面820px与390px手机验证内部滚动、Tab、错误可见和无横向溢出。

必须覆盖的行为：保存不等于验证；切Tab不丢草稿；未保存配置不影响实际请求；默认密钥刷新清除、主动记住后恢复、取消记住与一键清除有效；Secrets助手不触发任务；GitHub只读成功不标写权限成功；现有收藏/归档/笔记仍保持；命名不会覆盖已有笔记。

外部结果分别报告：mock浏览器验证不是真实模型调用；Obsidian URI测试不是vault已入库；真实模型测试待用户已配置凭据后执行。按用户已有要求，不额外扩展双页面冲突验收。
