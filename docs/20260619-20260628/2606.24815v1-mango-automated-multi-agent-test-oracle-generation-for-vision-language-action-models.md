## 摘要
视觉-语言-动作（VLA）模型是新兴的机器人控制系统，它们将感知、语言理解和动作生成集成在统一架构中。现有的针对VLA机器人的测试方法依赖于手动构建的符号化测试预言，这些预言通过最终环境状态判断任务成功与否。这些预言构建成本高、需要领域专业知识，并且通常与特定任务和环境紧密耦合，限制了可扩展性和复用性。此外，它们仅提供任务结果的终态评估，对中间行为和故障定位的洞察有限。为解决这些局限，我们提出了MANGO，一个多智能体框架，能够从机器人任务的自然语言描述中自动生成细粒度预言。MANGO首先生成一个可复用的原子任务库，然后为每个原子任务生成基于模拟器的预言定义，最后通过将复杂指令分解为有序的原子动作序列和相应的预言，生成可执行的细粒度预言。该框架使用协作的生成器、评估器和裁判智能体，通过结构化反馈迭代改进生成的产物。我们在LIBERO_10和RoboCasa人形桌面基准上评估了MANGO。结果表明，MANGO生成了可执行的细粒度预言，能够检测到与符号预言相似数量的失败，同时精确定位失败并提供更丰富的诊断信息。通过消融研究，我们进一步分析了各组件的贡献以及初始任务集的影响，同时保持了预言质量。总体而言，结果显示了针对VLA机器人测试的测试预言生成的可行性和有效性。

## Abstract
Vision-Language-Action (VLA) models are emerging robotic control systems that integrate perception, language understanding, and action generation in a unified architecture. Existing testing approaches for VLA-enabled robots rely on manually constructed symbolic test oracles that determine task success from final environment states. These oracles are costly to construct, require domain expertise, and are often tightly coupled to specific tasks and environments, limiting scalability and reuse. Furthermore, they provide only end-state assessments of task outcomes, offering limited insight into intermediate behavior and fault localization. To address these limitations, we introduce MANGO, a multi-agent framework that automatically generates fine-grained oracles from natural-language descriptions of robotic tasks. MANGO first generates a reusable library of atomic tasks, then generates simulator-grounded oracle definitions for each atomic task, and finally produces executable fine-grained oracles by decomposing complex instructions into ordered sequences of atomic actions and corresponding oracles. The framework uses collaborative Generator, Assessor, and Judge agents that iteratively refine generated artifacts through structured feedback. We evaluate MANGO on the LIBERO_10 and RoboCasa Humanoid Tabletop benchmarks. Results show that MANGO generates executable, fine-grained oracles that detect a similar number of failures as symbolic oracles while accurately localizing them and providing richer diagnostic information. Through ablation studies, we further analyzed component contributions and the effect of initial task set, while preserving oracle quality. Overall, the results show the feasibility and effectiveness of test oracle generation for VLA-enabled robots testing.

## 2. 论文提出的方法论

### 2.1 核心思想
- **细粒度预言定义**：将自然语言指令 `I` 分解为有序的原子任务序列 `D(I) = ⟨a1(θ1), a2(θ2), ..., an(θn)⟩`，每个原子任务对应一个参数化的符号预言 `Oa(θ)`，最终细粒度预言为这些原子预言的组合，可包含并行（∥）和严格时序（≺）约束。
- **多智能体迭代生成框架**：MANGO 基于三个专用智能体角色——**生成器（Generator）**、**评估器（Assessor）**、**裁判（Judge）**，通过结构化反馈进行多轮迭代优化，确保生成产物正确、一致且可执行。

### 2.2 关键技术细节
MANGO 分为三个模块：

#### 模块 I：原子任务库生成
- **输入**：初始复杂任务集合（自然语言描述）。
- **输出**：可复用的原子任务库，每个原子任务包含ID、描述、参数、前置条件和后置条件。
- **流程**：
  1. **生成器（World Model，如Gemini Robotics ER）** 根据任务集生成候选原子任务库。
  2. **评估板（Assessment Board）** 由三个并行评估器组成：
     - 原子性评估器：检查每个任务是否为不可分割的基本操作。
     - 冗余性评估器：检查是否存在功能重复或可被更通用任务替代的任务。
     - 重复性评估器：检测语义等效的重复任务并提议合并。
  3. **裁判（Reasoning LLM）** 汇总评估报告，决定接受或拒绝。若拒绝，生成细化指令指导下一轮迭代。
- **终止条件**：最多10次迭代或获得批准。

#### 模块 II：原子任务预言库生成
- **输入**：原子任务库 + 模拟器可用功能（Simulator Functions）。
- **输出**：每个原子任务的参数化预言（如 `is_held(robot, obj_id) and is_lifted(obj_id)`）。
- **流程**：
  1. **生成器（World Model）** 为每个原子任务生成候选预言。
  2. **Oracle Hacker（基础LLM）** 评估预言逻辑完整性、参数匹配等问题，产出Hacker报告。
  3. **全局裁判** 检查整个预言库的一致性，提出整合建议（如统一冗余谓词）。
- **终止条件**：最多10次迭代或全部批准。

#### 模块 III：细粒度预言生成
- **输入**：复杂指令 + 原子任务库 + 原子预言库 + 环境中可用对象。
- **输出**：可执行的细粒度预言（JSON格式），包含执行模式（sequential / any_order）、步骤序列、每个动作对应的预言逻辑表达式。
- **流程**：
  1. **生成器（World Model）** 生成候选细粒度预言。
  2. **评估板** 包含四个并行评估器：
     - 逻辑评估器：检查动作序列逻辑和排序正确性。
     - 合规评估器：检查是否满足用户指令、正确引用了原子任务和预言。
     - 接地评估器：验证所有对象、区域等参数是否在环境中真实存在。
     - 执行可靠性评估器（规则+代码）：检查预言格式是否可被模拟器正确解析和执行。
  3. **裁判（Reasoning LLM）** 决定是否批准；若拒绝，生成具体修改指令（如更正 `handle_as` 字段的逻辑表达式）。
- **终止条件**：最多25次迭代或批准。

## 7. 优点

1. **创新性强**：首次提出针对 VLA 模型的细粒度测试预言自动生成方法，填补了该领域空白。
2. **工程完善**：采用多智能体协作+迭代优化机制，有效克服了大模型幻觉和不稳定性；设计了三个专用模块，使原子任务库和预言库可复用，降低重复计算开销。
3. **评估充分**：在两种不同类型基准（桌面固定机器人 + 人形机器人）上验证，涵盖10种+24种任务，实验设计包含重复、统计检验、手动错误分析。
4. **可解释性与诊断能力**：细粒度预言可精确定位到原子步骤的失败，为调试提供直接指导。
5. **资源效率**：通过进化算法证明了初始任务集可大幅缩减，使方法适用于增量式场景。

## 8. 不足与局限

1. **基准覆盖有限**：仅测试了家庭/桌面操作场景，未涉及工业制造、户外等复杂环境；也未在真实物理机器人上验证，存在仿真到现实的鸿沟。
2. **对模拟器函数质量敏感**：实验显示，当模拟器函数存在物理不稳定性（如物体弹跳、抓取粘滞）或谓词缺失时，定位准确率下降。这并非方法本身问题，但限制了实际部署效果。
3. **生成时间较长**：多智能体迭代在模块 II 和 III 耗时较高（LIBERO 模块 II 平均634秒，模块 III 347秒），尽管离线运行可接受，但若需快速迭代可能成为瓶颈。
4. **依赖专有模型**：最佳性能依赖 Gemini Robotics ER（闭源）和特定 World Model，开源模型（MANGO_o）性能下降显著，影响可复现性。
5. **人工验证仍有必要**：作者承认在模拟器函数不可靠时，仍需人工核查生成的预言，尚未完全自动化（尤其是跨基准的适配）。
6. **未见泛化性分析**：未测试当任务超出初始库原子能力范围时（如全新的动作类型）会发生什么，可能需重新运行模块 I 和 II。
