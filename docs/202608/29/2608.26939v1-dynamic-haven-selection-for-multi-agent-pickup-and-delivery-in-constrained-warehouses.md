## 摘要
空间高效的仓库布局通常包含仅容单智能体通过的通道和死胡同式工作站，在这些地方机器人几乎没有可等待而不阻塞他人的位置。在此类受限布局的多智能体取送货（MAPD）问题中，机器人必须接受在线取送货任务，同时保留称为避难所（Haven）的受保护等待位置。安全避难所撤退规划器（SHARP）引入了一种机制，为每个已承诺的任务路径扩展一条经过验证的撤退路径，通往该智能体专用的初始避难所，但固定避难所的承诺可能会在配送完成后将智能体派往远处的避难所。我们提出了A-sharp（自适应SHARP），它在任务分配时改变智能体的撤退目标。简单的切换可能导致两个智能体依赖同一等待位置，或让另一条已承诺路径穿过仍被占用或预留的位置。A-sharp通过候选避难所的可用性测试和待释放规则来防止这些失败，该规则保持先前避难所受保护直至智能体离开。在显式避难所结构和安全间隔路径规划（SIPP）假设下，我们证明了不变量保持和有限释放完备性：任何有限释放序列中的每个任务都能在有限时间内完成配送。在四个地图上的14,400个配对地图-智能体数量-速率-种子案例中进行的72,000次运行中，SHARP和A-sharp均完成了各自的14,400次运行。对于完工时间（最终配送时间），对所有138个避难所数量多于智能体数量的配置进行预先指定的配对比较（Holm校正），发现A-sharp在107个配置中显著优于SHARP，且从未显著差于SHARP；在测试的树状地图上，中位数减少为16.7%。

## Abstract
Space-efficient warehouse layouts often contain single-agent-width aisles and dead-end workstations where robots have few places to wait without blocking others. In Multi-Agent Pickup and Delivery (MAPD) on such constrained layouts, robots must accept online pickup-delivery tasks while preserving protected waiting locations called Havens. The Safe HAven Retreat Planner (SHARP) introduced a mechanism that extends each committed task path with a validated retreat to the agent's dedicated initial Haven, but fixed-Haven commitments can send agents toward distant Havens after deliveries. We present A-sharp (Adaptive SHARP), which changes an agent's retreat target at task assignment time. A naive switch can cause two agents to rely on the same waiting location or let another committed path pass through a location that is still occupied or reserved. A-sharp prevents these failures with an availability test for candidate Havens and a pending-release rule that keeps the previous Haven protected until the agent departs. Under explicit Haven-structure and Safe Interval Path Planning (SIPP) assumptions, we prove invariant preservation and finite-release completeness: every task in any finite release sequence is delivered in finite time. Across 72,000 runs on 14,400 paired map-agent-count-rate-seed cases over four maps, both SHARP and A-sharp complete their respective 14,400 runs. For makespan (final delivery time), a prespecified paired comparison with Holm correction over all 138 configurations with more Havens than agents finds A-sharp significantly better in 107 configurations and never significantly worse than SHARP; on the tested tree map, the median reduction is 16.7%.

## 1. 核心问题与整体含义

- **研究动机**：空间高效的仓库布局常包含仅容单智能体通过的窄通道和死胡同式工作站，机器人缺少安全等待位置。在多智能体取送货（MAPD）问题中，机器人需要在线接受任务，同时保留受保护的等待位置（Haven），以避免碰撞和死锁。
- **已有方案与局限**：SHARP（Safe HAven Retreat Planner）为每个已承诺任务路径附加一条验证过的撤退路径，通往智能体专属的**固定初始 Haven**。该设计虽能保证安全，但固定 Haven 会在配送完成后将智能体送往较远的等待点，产生不必要的绕路和时间浪费。
- **核心科学问题**：能否在保持安全撤退机制的前提下，于任务分配时**动态改变撤退 Haven 的目标**？这涉及多智能体之间等待位置的独占所有权转移，以及未来路径预留的一致更新。
- **论文含义**：提出 A♯（Adaptive SHARP），通过“可用性测试 + 待释放规则”实现安全的动态 Haven 转移，在保证有限释放完备性的同时降低绕路成本。

## 2. 方法论

- **核心思想**：在任务分配时，为每个智能体选择一个附近的可用 Haven 并提交完整路径（当前位置 → 取货点 → 送货点 → 所选 Haven），路径由三段 SIPP（Safe Interval Path Planning）段拼接而成。
- **可用性测试（Availability Test）**：候选 Haven 必须满足
  1. 不被其他智能体的独占集合（exclusive set）拥有；
  2. 没有其他智能体在任意未来时间对其有已提交的占用预留。
- **待释放规则（Pending-Release Rule）**：当智能体从旧 Haven 切换到新 Haven 时，若它仍物理占据旧 Haven，则旧 Haven 继续保留在其独占集合中，直到智能体实际离开，避免其他智能体规划穿过仍被占用的顶点。
- **原子提交**：验证成功后，一次性替换智能体自身的未来预留、更新当前 Haven 分配和独占集合；避免陈旧自预留导致的自我冲突。
- **算法流程**（每个时间步）：
  1. 将新释放任务加入待处理集合；
  2. 对所有空闲或撤退中且无待释放旧 Haven 的智能体，分别选择最近取货任务和最近可用 Haven；
  3. 调用 `PlanFullPath` 进行三段 SIPP 验证；
  4. 选择全局最优的候选提交；重复直到无可提交候选。
- **理论保证**：
  - 执行不变量：Haven 分配单射、独占集合互斥、待释放旧 Haven 至多一个；
  - 预留不变量：顶点-时间无冲突、无边交换、非空闲智能体有终止于当前 Haven 的有限路径、预留排除；
  - 在 Haven 结构条件（任务核心诱导子图连通、每个 Haven 邻接核心、任务端点均在核心内）和 SIPP 完备性假设下，证明**有限释放完备性**：任何有限释放序列中的每个任务最终都会被送达。

- **完备性与安全性**：SHARP 和 A♯ 在所有 14,400 个配对案例中均 100% 成功配送，动态 Haven 转移未削弱固定 Haven 基线的鲁棒性。
- **完工时间**：在 138 个 Haven 富余配置中，A♯ 在 **107 个配置显著优于 SHARP**，且经 Holm 校正后 **没有任何配置显著差于 SHARP**；树状地图中位数降低 **16.7%**。

## 7. 优点

- **理论贡献明确**：形式化定义了 Haven 结构条件、执行/预留不变量，并给出完整的有限释放完备性证明；区分了“算法安全”与“选择器启发式”的层次。
- **协议设计精巧**：可用性测试结合所有权与未来预留，待释放规则解决了“物理占据但逻辑释放”的不一致问题；原子更新避免了陈旧预留造成的自我阻塞。
- **实验规模大且统计规范**：72,000 次运行、配对设计、预指定主比较、Holm 校正，对比基线多样，结论可靠。
- **应用导向**：针对真实仓库中的窄通道、死胡同、树状路径等结构，弥补了传统 well-formed/biconnectivity 假设的不足。

## 8. 不足与局限

- **Haven 密度限制**：要求初始 Haven 互异且 |A| ≤ |H|，不支持共享停车或更密集的智能体编队。
- **执行模型理想化**：假设确定性离散时间执行、中央预留表、无延迟/故障/定位误差；对随机扰动、外部智能体等需要额外修复策略。
- **选择器依赖**：最近取货 + 最近 Haven 的贪心策略不是安全机制的组成部分，但在窄双连通地图上会导致服务时间的局部变差；换用更优选择器可能改善。
- **地图/需求覆盖有限**：每类结构仅一个实例，任务分布均匀，未检验不同拓扑和需求模式下的泛化性。
- **数据报告限制**：受限地图的绝对性能数值未公开（工业保密），削弱了跨环境可比性；但代码和配置文件已开源，允许独立复现。
