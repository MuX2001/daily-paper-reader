## 摘要
视觉-语言-动作（VLA）模型通常通过自回归文本坐标或不透明的动作令牌来暴露空间接地，这在多模态推理与机器人执行之间形成了脆弱的接口。我们提出了Pointing-VLA，一种基于Embodied-R1构建的类型化隐藏状态空间读出机制。几何专用头预测归一化点、对象功能接地（OFG）热图以及视觉轨迹，而无需将几何序列化为文本。在评估的Bridge/WidowX和物理抓取-放置部署中，一个显式的执行契约将PICK分配给源条件OFG，将PLACE分配给Pointing，从而提供直接的阶段对齐空间目标。Pointing-VLA在Bridge/WidowX上达到了SOTA性能，在启用碰撞的CuRobo执行下，无需Bridge特定微调，在评估的四个任务集上平均达到72.9%。Pointing和OFG在原生和跨数据集评估中表现出互补的优势。OFG/接触读出可迁移至NORA-1.5，在保持或提升成功率的同时，将记录的控制时间减少超过20倍；类型化头在共享外部套件上比Embodied-R1文本解码快6.68--6.90倍。当作为π_{0.5}动作策略的空间引导集成时，Pointing-VLA在三种视觉场景下将自主真实机器人成功率从52.7%提升至80.7%。这些结果确立了类型化空间读出作为具身推理与机器人执行之间高效、可检查接口的有效性。

## Abstract
Vision-language-action (VLA) models often expose spatial grounding through autoregressive text coordinates or opaque action tokens, creating brittle interfaces between multimodal reasoning and robot execution. We present Pointing-VLA, a typed hidden-state spatial readout built on Embodied-R1. Geometry-specific heads predict normalized points, object-functional grounding (OFG) heatmaps, and visual trajectories without serializing geometry as text. For the evaluated Bridge/WidowX and physical pick-place deployments, an explicit execution contract assigns PICK to source-conditioned OFG and PLACE to Pointing, providing direct stage-aligned spatial targets. Pointing-VLA achieves SOTA performance on Bridge/WidowX, averaging 72.9\% across the evaluated four-task set without Bridge-specific finetuning under collision-enabled CuRobo execution. Pointing and OFG show complementary strengths across native and cross-dataset evaluations. The OFG/contact readout transfers to NORA-1.5, preserving or improving success while reducing recorded controller time by more than 20$\times$; typed heads are also 6.68--6.90$\times$ faster than Embodied-R1 text decoding on a shared external suite. When integrated as spatial guidance for a $π_{0.5}$ action policy, Pointing-VLA raises autonomous real-robot success from 52.7\% to 80.7\% across three visual contexts. These results establish typed spatial readouts as an efficient, inspectable interface between embodied reasoning and robot execution.

# 1. 论文的核心问题与整体含义

- **问题背景**：视觉-语言-动作（VLA）模型常将空间接地（spatial grounding）序列化为文本坐标（如自回归生成数字）或不透明的动作令牌。前者需要解析字符串、浪费 token、丢弃细粒度部件级证据；后者虽然无需解析，但隐藏了空间决策的依据，不利于调试和审计。作者指出：**文本坐标生成可能失败于“无法解析”或“语法正确但空间错误”两种典型情况**，因而解析本身不是空间正确性的保证。
- **核心主张**：具身接地应被建模为**类型化接口预测（typed interface prediction）**，而不是文本坐标生成。指向点（sparse point）、功能区域（dense affordance region）、视觉轨迹（temporally structured trajectory）三类空间目标具有不同几何性质，应分别用专用头输出其原生几何，而非统一序列化为文本。
- **整体含义**：该工作将“输出什么空间格式供执行消费”作为 VLA 系统的核心设计问题，强调“执行契约”（execution contract）可以在推理与机器人动作之间建立可检查、确定性的接口，从而使空间推理更高效、更可控、更可解释。

# 2. 论文提出的方法论

## 2.1 核心思想：隐藏状态读出（Hidden-State Spatial Readout）

- 复用 Embodied-R1 的共享多模态状态 $H_{mm}$，不要求模型“说出”坐标。
- 将空间目标视为从分布式内部表示中解码出的连续/图像空间变量，而非通过文本系统序列化（受 Goodale & Milner、Andersen & Buneo、Cisek 等神经科学“视觉-动作双通路”与“总体读出”观点启发）。
- 三类专用头：
  - **Pointing head**：通过学习的指针查询 qpt 从 grounding tokens 中选取信息，直接输出归一化点坐标 $(\hat{x},\hat{y})\in[0,1]^2$；对应像素通过 $(W-1)\hat{x},(H-1)\hat{y}$ 得到。
  - **OFG head（对象功能接地）**：利用视觉塔的 2D 特征图 $F_{vis}$，用全局 grounding 摘要通过 FiLM 调制，再经卷积热图解码器输出热图 $\hat{H}_{ofg}$，取其峰值作为功能接触点；保留空间范围而不是坍缩为单点。
  - **VTG head（视觉轨迹）**：使用 8 个时态 waypoint 查询，按顺序从多模态序列中读取归一化图像空间轨迹点 $\hat{\tau}_t$，用于描述可视轨迹而非低级动作。

## 2.2 部署契约（Execution Contracts）

- 对 pick-place 任务，固定为：
  - **PICK = 源条件 OFG**（source-conditioned OFG）：由指令、源描述构造查询 $q_{pick}$，OFG 输出功能接触热图及峰值。
  - **PLACE = Pointing**：由指令、目标描述构造查询 $q_{place}$，Pointing 输出归一化放置坐标。
- 外部 wrapper 通过标定深度、相机内参、机器人变换将图像空间输出映射到机器人坐标系：
  - $X_c = D(\hat{u},\hat{v}) K^{-1} \tilde{p}$，$\bar{X}_r = T_{r\leftarrow c} \bar{X}_c$。
- 该契约固定、确定，无推理时选择器，减少系统复杂度。

## 2.3 训练策略

- **统一目标**：$L = \lambda_{pt} L_{pt} + \lambda_{box} L_{box} + \lambda_{ofg} L_{ofg} + \lambda_{vtg} L_{vtg} + \lambda_{aux} L_{aux}$；点/轨迹用 SmoothL1，OFG 用 MSE 或 class-balanced BCE。
- **三阶段训练**：
  1. **几何热身（Geometry Warm-up）**：训练 grounding adapter、查询与几何头。
  2. **LoRA 特化（LoRA Specialization）**：仅更新低秩 backbone 参数。
  3. **任务延续（Task Continuation）**：只更新任务所需子集。
- **GRPO 精细化**：Pointing 模型还使用策略中心 $\mu=\hat{p}$、学习方差 $\sigma=\exp(s)$ 采样候选点，以目标框内命中与否定义奖励，并做 group-normalized advantage 更新，同时保留对监督点的 SmoothL1 约束。这使连续空间头部直接受益于强化式细化。
- **OFG 源条件特化**：保持 base 与 Pointing/VTG 模块冻结，联合更新 OFG LoRA、共享 adapter、OFG 查询与热图解码器；使用“源 mask 重建 + 源-干扰物排序 + 干扰物抑制”使其在 PICK 读出中直接分辨源实例。

# 6. 论文的主要结论与发现

- **类型化头部优于文本生成**：Pointing 保持稀疏点接地精度（64.3% vs Embodied-R1 63.7%），OFG 显著提升 Part-Affordance-2K 全量精度到 57.3%（比 Embodied-R1 高 16.4 点）。
- **几何互补**：跨数据集显示 Pointing 在 RefCOCO/RoboAff 更强，OFG 在 AGD20K/Part-Affordance-2K 更强，表明不同任务应选择不同几何输出接口。
- **固定契约有效**：OFG-PICK/Pointing-PLACE 在 Bridge/WidowX 上平均 72.9%，优于其他组合 14.6 个百分点；源条件 OFG 在所有 48 个在线 Stack 案例中正确选择源实例，完成率 43/48 vs Attention PICK 的 40/48。
- **效率显著提升**：Pointing/OFG 头比 Embodied-R1 文本解码快 6.68–6.90 倍；NORA-1.5 转移后控制器时间从约 107/111s 降至 4.85/5.44s（20 倍以上），横放成功率 100%，竖放成功率从 89% 提高到 95%。
- **真实机器人收益稳定**：作为 π0.5 的空间引导后，整体成功率从 52.7% 提升至 80.7%（三种场景分别 +32.0、+32.0、+20.0 个百分点）；主要减少的是抓取前失败（47→16）和到达托盘失败（13→4），而转移/掉落仍是主要瓶颈。
- 整体结论：类型化空间读出是“高效且可检查”的具身接口，能显著提升基准、模拟与真实部署性能，同时降低延迟。

# 7. 优点

- **问题定位清晰**：直接击中 VLA 中“输出接口”这一被忽视的瓶颈，用神经科学的“动作通路/总体读出”类比提供理论动机。
- **设计简洁而系统**：三类头共享 backbone 与其 adapter 主体，但各自有独立查询与解码状态，实现“相关但不相同”的目标，避免负干扰。
- **部署契约确定性强**：无推理时选择器，固定 OFG→PICK、Pointing→PLACE，使执行阶段与几何类型逐一对应，便于审计与替换。
- **轻量高效**：不生成文本、无需解析，直接输出几何；运行时间提升明确，且迁移到新 backbone（NORA-1.5）时只需转移读出接口，效率改进约 20 倍。
- **实验证据链完整**：从原生精度、跨数据集、机制消融、跨 backbone、模拟部署到真实机器人，覆盖组件到系统各层级；相同 episode 身份、相同执行器保证对比客观。
- **GRPO 细化应用自然**：在连续空间头部上进行策略优化，而非对文本 token 采样，展示了强化式空间细化的可行性。
- **失败阶段分析**：真实机器人实验不仅报告成功率，还按失败阶段定位改进来源，说明方法收益集中在预期控制边界。

# 8. 不足与局限

- **任务范围有限**：Bridge/WidowX 只有 4 个任务，真实部署只包含单白色复合物体的抓取-放置任务，未覆盖更复杂的多阶段、双臂、可变形物体或更长程任务。
- **未报告统计不确定性**：结果以百分比点估计给出，未给置信区间或显著性检验；24 episodes 和 50 次试验虽然可用，但点估计波动仍可能较大。
- **少数任务表现波动**：如 spoon-on-towel 仍偏低（50.0%），论文将其归因于“薄物体接触和闭环几何感知”难题，但这说明识别与执行在细粒度场景仍有局限。
- **跨数据集比较存在公平性风险**：将文本生成的多个候选点统一为单点计数，可能低估文本方式的多候选能力；尽管作者强调“sample-level”比较，但其协议对文本形式不完全友好。
- **GPU 与训练时间细节缺失**：论文未公开精确的算力消耗、训练 step 数、优化超参数，可复现性依赖补充材料。
- **模块依赖**：真实机器人仍依赖 π0.5 作为动作生成器，Pointing-VLA 只做空间引导，若动作策略本身不开放，则集成路径受限；这也意味着其“自主性”是混合式而非端到端。
- **固定契约的扩展性**：虽然确定性好，但 OFG-PICK/Pointing-PLACE 只适用于 pick-place；对其他任务类型（如开柜、插孔、倒水）需要重新设计契约与查询构造，通用性尚未证明。
- **潜在偏向**：论文由同一团队基于 Embodied-R1 生态开发，对比方法中部分（如 FSD、Embodied-R1）与自身算法高度相关，虽然结果差异明显，仍需第三方复现验证。
