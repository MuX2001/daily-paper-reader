## 摘要
在分层视觉-语言-动作（VLA）系统的每个重新观测点，需要做出两个接口决策：何时终止当前子任务，以及执行所提议的动作分块到何种程度。这两个决策相互依赖——最优停止点取决于执行器计划做什么，而最优执行长度取决于子任务边界位于何处——然而现有架构孤立地评估它们，这种不对称性是任何单一模块都无法独自克服的。我们提出SparkVLA，一种停止感知的分层VLA，通过将两个决策统一为单一排序来解决这种相互依赖：停止与每个动作前缀长度在统一候选集中竞争，系统选择得分最高的选项，从而消除了阈值调优且仅需离线排序偏好。锚定条件上下文编码模块缓存历史感知的子任务锚定编码、起始状态记忆和目标语义，引导视觉标记剪枝朝向任务相关区域；停止感知动作前缀选择头通过块边界处的全自注意力对所有候选进行评分以提高效率。在RoboCerebra上，SparkVLA实现了47.12%的成功率，超越官方分层基线30.57%，超越最强可复现方法26.83%。在多步任务上的真实机器人实验进一步验证了这些增益在物理硬件上的有效性。

## Abstract
At every re-observation point in a hierarchical Vision-Language-Action (VLA) system, two interface decisions must be made: when to terminate the current subtask and how far to execute the proposed action chunk. These decisions are mutually dependent---the optimal stopping point depends on what the executor plans to do, while the optimal execution length depends on where the subtask boundary lies---yet existing architectures evaluate them in isolation, an asymmetry neither module can overcome alone. We present SparkVLA, a stop-aware hierarchical VLA that resolves this mutual dependency by formulating both decisions as a single ranking: Stop competes against every action-prefix length in a unified candidate set, and the system selects the highest-scoring option, eliminating threshold tuning and requiring only offline ordinal preferences. An Anchor-Conditioned Context Encoding module caches a history-aware subtask anchor encoding onset-state memory and goal semantics, guiding visual-token pruning toward task-relevant regions; a Stop-Aware Action-Prefix Selection head scores all candidates via full self bnattention at chunk boundaries for efficiency. On RoboCerebra, SparkVLA achieves 47.12% success rate, surpassing the official hierarchical baseline by 30.57% and the strongest reproducible method by 26.83% Real-robot experiments on multi-step tasks further validate these gains on physical hardware.

## 1. 核心问题与整体含义（研究动机与背景）

长时程（long-horizon）机器人操作任务要求机器人依次完成多个子任务。分层视觉-语言-动作（Hierarchical VLA）架构通过高层VLM规划器生成子任务指令、低层VLA执行器生成动作序列，来应对这类任务。然而，在每一个“重新观测点”（decision boundary），系统必须同时回答两个相互依赖的接口决策问题：

- **何时终止当前子任务**（是否选择 Stop）；
- **执行动作分块（action chunk）到多长**（选择哪个动作前缀长度）。

论文指出，这两个决策存在**结构性相互依赖**：最优停止点取决于执行器将要执行的动作内容，而最优执行长度也取决于子任务边界所在位置。但现有方法存在明显的“信息不对称”：

- 终止侧（termination）方法：使用二分类器、VLM预测长度或进度信号，**无法利用未来动作计划**；
- 动作分块侧（horizon）方法：如 DEHP、ACH、AQC、AAC，能自适应选择执行长度，但**不能显式判断子任务完成**。

这种割裂导致：过早停止丢弃进度、过晚停止导致过冲、过度承诺导致漂移、过早重规划浪费预算。论文的核心洞察是：**两个决策可以统一为“候选评分排名”问题**——让 Stop 与所有动作前缀长度在同一个候选集中竞争，选择得分最高者，从而在共享表征中同时利用计划内容与子任务边界信息，消除独立模块间的信息盲区。

## 2. 提出的方法论

### 2.1 总体框架

SparkVLA 基于预训练的 π0.5 VLA 构建两个分支：

- **高层分支**：保留 VLM 骨干，用于自动回归生成子任务命令，并承载选择器（selector）；
- **低层分支**：使用完整的 π0.5 VLA（含动作专家）生成动作块。

在决策边界，选择器将 Stop 和所有动作前缀长度（1 到 H）组成统一候选集，输出 H+1 个分数，选择分数最高的候选执行。

### 2.2 统一候选集与问题形式化

定义候选集 C = {0, 1, ..., H}，其中 0 表示 Stop，n≥1 表示执行动作块 At 的前 n 个动作。选择器学习映射：

```
f_sel(At, αk, mt) → C
```

其中 αk 为历史感知的子任务锚（subtask anchor），mt 为高层隐藏特征。

### 2.3 锚定条件上下文编码（Anchor-Conditioned Context Encoding）

三个步骤构建选择器上下文：

1. **历史感知子任务锚（History-Aware Subtask Anchor）**：
   - 子任务开始时，从 VLM 倒数第二层提取原始锚（raw anchor）：对生成命令最后一个 token 的隐藏状态做 MLP 映射；
   - 维护锚历史池 A_k，通过自注意力融合当前锚与历史锚，得到 αk。该锚编码了起始状态记忆、目标语义以及先前子任务已改变工作区的上下文信息。

2. **锚引导视觉剪枝（Anchor-Guided Visual Pruning）**：
   - 使用冻结的 SigLIP 视觉编码器获得密集视觉 token；
   - 利用可微分的 Grid-Sampler 操作，以锚 αk 为条件，预测 K 个归一化 2D 坐标，通过双线性插值采样出 K 个任务相关视觉 token，将每相机的 token 数从 N 压缩到 K。

3. **高层隐藏特征编码（High-Level Hidden Feature Encoding）**：
   - 将剪枝后的视觉 token 与状态嵌入、子任务命令嵌入拼接，经过高层 VLM 骨干的前 8 层（带 LoRA）得到当前决策边界的隐藏特征 mt。

### 2.4 停止感知动作前缀选择头（Stop-Aware Action-Prefix Selection）

- **统一候选评分**：使用一个全自注意力 Transformer 作为评分头。候选 token 包括：
  - 上下文 token：锚投影 eα 和隐藏特征投影 em；
  - Stop 候选：可学习嵌入 e0；
  - 动作前缀候选：每个长度 n 的 token 由该前缀最后一个动作的 MLP 映射加上长度嵌入得到。
  - 全部 token 通过多层自注意力交互，再经 MLP 映射为标量分数。
- 这样，Stop 的表示会因自注意力而具备上下文依赖性，动作前缀候选也能感知到 Stop 的语义边界。

### 2.5 训练目标（Stop-Aware Ranking Objective）

- **排序损失（ranking loss）**：根据离线执行结果构造每个候选的排序优先级 ρi：
  - 成功轨迹且已越过子任务边界（t≥τ）时，Stop 优先级最高；
  - 未越过边界时，覆盖剩余动作（n≥n*）的前缀优先于不覆盖的，且越接近边界的覆盖前缀优先级越高；
  - 失败轨迹中，所有动作前缀优先级都高于 Stop，鼓励继续探索。
  - 训练时对边界 τ 加均匀随机扰动（±2），提升标注噪声鲁棒性。
  - 对所有优先级不同的候选对构造二进制比较标签，训练 BCE 排序损失。

- **停止辅助损失（stop-aware auxiliary loss）**：
  - 使用 u = s_stop − logsumexp(s_1..s_H) 对比 Stop 分数与连续动作分数的聚合；
  - 加上 BCE 损失强化停止边界。

- 总损失 L = L_rank + λ_stop L_stop，λ_stop=1。推断时仍使用统一的 argmax 规则，辅助损失不引入独立推断路径。

### 2.6 推理调度

- 子任务锚 αk 在每个子任务开始时计算一次并缓存；
- 选择器仅在决策边界（块边界）调用，而非每步调用；
- 实际系统运行约 4.14 Hz（每秒 41.4 动作步），约为 standalone π0.5 吞吐的 88%。

## 6. 主要结论与发现

1. **统一候选集有效**：将 Stop 与动作前缀长度放入同一排序显著优于独立模块。RoboCerebra 上 Stop Acc. 从 80.37% 提升到 96.65%（+16.28 pp），SR 从 42.53% 提升到 47.12%，证明两个决策相互提供有用信息。
2. **整体性能领先**：SparkVLA 在 RoboCerebra 上平均 SR 47.12%，超过独立 π0.5 34.83%，超过官方分层基线 HPE 30.57%，超过可复现的 Mem-0 26.83%。
3. **动态执行长度带来增益**：在 Dynamic Observation 和 Memory Execution 条件下，自适应短前缀与频繁重观测显著提升性能（分别 +34.78% 和 +47.69%）。
4. **历史感知锚是关键**：历史感知锚相比原始锚在记忆依赖任务中带来额外 1.94% SR 增益，说明跨子任务上下文对空间歧义消解重要。
5. **高层规划器作为选择器骨干更优**：选择器放在高层规划器上比放在低层执行器上高出 9.84%，因为规划器保留了任务进度和子任务历史。
6. **系统级泛化**：SparkVLA 的高层系统可适配不同低层执行器（OpenVLA-OFT、SmolVLA），均带来显著提升。
7. **真实世界迁移**：真实机器人上平均成功率 69.3%，超过 π0.5 的 48.0%，其中 12 子任务的茶制备任务提升最大（+30.0%）。
