## 摘要
在分层视觉-语言-动作（VLA）系统的每个重新观察点，必须做出两个接口决策：何时终止当前子任务，以及执行所提议动作块的距离。这两个决策相互依赖——最优停止点取决于执行器计划做什么，而最优执行长度取决于子任务边界在哪里——然而现有架构将它们孤立地评估，这种不对称性是任何单一模块都无法单独克服的。我们提出SparkVLA，一种停止感知的分层VLA，通过将两个决策形式化为单一排序来解决这种相互依赖：停止与每个动作前缀长度在统一候选集中竞争，系统选择得分最高的选项，从而消除阈值调整且仅需离线序数偏好。锚定条件上下文编码模块缓存历史感知的子任务锚定编码、起始状态记忆和目标语义，引导视觉标记剪枝朝向任务相关区域；停止感知的动作前缀选择头在块边界通过完整自注意力对所有候选进行评分以提高效率。在RoboCerebra上，SparkVLA达到47.12%的成功率，超越官方分层基线30.57%，超越最强可复现方法26.83%。在多步任务上的真实机器人实验进一步验证了这些增益在物理硬件上的有效性。

## Abstract
At every re-observation point in a hierarchical Vision-Language-Action (VLA) system, two interface decisions must be made: when to terminate the current subtask and how far to execute the proposed action chunk. These decisions are mutually dependent---the optimal stopping point depends on what the executor plans to do, while the optimal execution length depends on where the subtask boundary lies---yet existing architectures evaluate them in isolation, an asymmetry neither module can overcome alone. We present SparkVLA, a stop-aware hierarchical VLA that resolves this mutual dependency by formulating both decisions as a single ranking: Stop competes against every action-prefix length in a unified candidate set, and the system selects the highest-scoring option, eliminating threshold tuning and requiring only offline ordinal preferences. An Anchor-Conditioned Context Encoding module caches a history-aware subtask anchor encoding onset-state memory and goal semantics, guiding visual-token pruning toward task-relevant regions; a Stop-Aware Action-Prefix Selection head scores all candidates via full self bnattention at chunk boundaries for efficiency. On RoboCerebra, SparkVLA achieves 47.12% success rate, surpassing the official hierarchical baseline by 30.57% and the strongest reproducible method by 26.83% Real-robot experiments on multi-step tasks further validate these gains on physical hardware.

# SparkVLA 论文详细中文总结

## 1. 核心问题与研究动机

- **背景**：近年来，视觉-语言-动作（VLA）模型在机器人操作上展现出强大的泛化能力，但大多在短轨迹片段上训练，难以在长时间跨度内组合多个技能。分层 VLA 架构通过"高层 VLM 规划器 + 底层 VLA 执行器"的配对来解决这一问题。
- **核心问题**：在分层 VLA 系统的每个重新观察点（decision boundary），系统必须同时做出两个接口决策：
  1. **何时终止当前子任务**（termination condition）；
  2. **动作块执行多远**（execution horizon / action chunk length）。
- **关键洞察**：这两个决策**相互依赖**——最优停止点取决于执行器接下来要做什么，最优执行长度取决于子任务边界在哪里。然而现有架构**孤立评估**这两个决策：
  - 终止侧：使用二元检测器（binary detectors）、VLM 预测长度或进度信号，均无法获知后续行动计划；
  - 长度侧：DEHP、ACH、AQC、AAC 等方法自适应选择执行长度，但无法发出子任务完成信号。
- **后果**：过早终止丢弃进度、过晚终止造成过冲、过度承诺导致漂移、承诺不足浪费重规划预算。这种结构性信息不对称是任何单一模块都无法单独克服的。

## 2. 方法论

### 2.1 核心思想：统一排序（Unified Ranking）

- 作者观察到，两个决策都可归结为一个共同评估问题——"所提议的动作块从当前状态出发对当前子任务的匹配程度如何"。
- 因此，将两者形式化为**单一候选集上的排序**：定义统一候选集 C = {0, 1, …, H}，其中候选 0 表示 Stop，候选 n ≥ 1 表示执行动作块的前 n 个动作。所有候选在同一打分头下竞争，系统选择得分最高的选项。
- 这一设计使得：终止决策可以利用所提议计划的内容，长度选择可以利用与子任务边界的接近程度——正是相互依赖的信息。

### 2.2 整体架构

- 基于预训练的 π0.5 VLA 派生两个独立的分支：
  - **高层分支**：使用 π0.5 的 VLM 骨干，承担自回归子任务生成器和选择器；
  - **底层分支**：使用完整 π0.5 VLA（含动作专家），提议动作块。
- 子任务 k 开始时，规划器自回归生成子任务命令 ck；终止后将其追加到语义历史 Hk。

### 2.3 锚定条件上下文编码（Anchor-Conditioned Context Encoding）

三阶段构建选择器上下文：

1. **历史感知子任务锚点（History-Aware Subtask Anchor）**：
   - 从 VLM 骨干倒数第二层提取原始锚点 α̂k = MLP_anchor(h_ck,last^(ℓdeep))；
   - 维护锚点历史池 Ak = {α̂1, …, α̂k−1}，通过自注意力池融合得到历史感知锚点 αk；
   - αk 编码了起始状态记忆、目标语义以及此前子任务对工作空间的改变（对记忆依赖型任务至关重要）；
   - 锚点每个子任务只计算一次并缓存。

2. **锚点引导的视觉剪枝（Anchor-Guided Visual Pruning）**：
   - 冻结的 SigLIP 编码器产生密集视觉 token，用可微的 Grid-Sampler 操作符预测 K 个归一化二维坐标，通过双线性插值采样；
   - 锚点 αk 作为条件输入，引导采样朝向任务相关区域，将每相机的视觉序列从 N 个 token 缩减为 K 个。

3. **高层隐特征编码（High-Level Hidden Feature Encoding）**：
   - 剪枝后的视觉 token 投影到骨干宽度，与本体感受状态和子任务命令嵌入拼接；
   - 通过带 LoRA 适配器的高层 VLM 骨干前 ℓm 层，得到高层隐特征 mt。

### 2.4 停止感知动作前缀选择（Stop-Aware Action-Prefix Selection）

- **统一候选打分**：打分头是一个全注意力 Transformer，Stop 和所有动作前缀候选互相注意力：
  - Stop 候选使用可学习嵌入 e0；
  - 每个长度 n 的候选由前缀末端动作初始化加可学习的长度嵌入：en = MLP_a(a_{t+n−1}) + pn；
  - 完整 token 集经过自注意力后，由打分层映射为标量。Stop 表示虽初始化为固定嵌入，但经自注意力后变得上下文相关。

- **选择规则**：n̂t = arg max_{i∈C} s_t,i，选择 Stop 或得分最高的动作前缀后重新观察。

- **停止感知排序目标（离线训练，无阈值调节、无在线奖励）**：
  - **成对排序损失**：根据离线执行结果为候选分配序数优先级 ρi。三条原则：(1) 子任务完成后 Stop 优先级最高；(2) 完成前覆盖前缀（n ≥ n*）优于非覆盖前缀，覆盖前缀中接近边界者最优；(3) 失败轨迹中所有动作前缀并列高于 Stop，鼓励继续探索。
  - 边界标注加入均匀随机扰动 τ' = τ + Δ，Δ ~ U(−2, 2)，增强对标注噪声的鲁棒性。
  - **停止感知辅助损失**：u_t = s_{t,0} − log Σ exp(s_{t,n})，对比 Stop 与继续动作的对数求和；L = L_rank + λ_stop L_stop（λ_stop = 1），两者作用于同一组分数，推理时仍使用统一的 argmax 规则。
  - 确认窗口（confirmation window）过滤短期分数波动，防止误停。

## 7. 错误分析与局限性

### 7.1 失败模式

作者在 RoboCerebra 与真机实验中对失败轨迹进行了归类，主要失败模式包括：

- **视觉误判导致的提前停止**（约 18% 失败轨迹）：视觉剪枝采样到不相关区域或物体遮挡严重时，选择器错误地认为子任务已完成。加入确认窗口后，此类错误从 30.2% 降至 17.8%。
- **动作块中途偏航**（约 15%）：底层执行器在长动作块中段产生漂移，导致后续操作失效。对此，统一排序能通过提前切换到 Stop 或更短前缀及时纠正，但若选择器未及时触发，则继续累积误差。
- **语义分解错误**（约 9%）：高层规划器生成子任务命令时出现含糊或不可执行指令，如“把杯子放到”后缺少目标位置。此类错误在 Memory 相关任务中更常见，因为需要依赖长期历史。

### 7.2 主要局限

1. **依赖人工子任务标注**：离线训练需要子任务边界标签（在 RoboCerebra 中已有；LIBERO 则借助 LaRA-VLA 自动标注），若标注质量差或粒度不一致，排序目标会引入噪声。
2. **计算开销**：选择器虽有缓存优化，但训练阶段需生成 200 万级决策样本，且每次重规划仍需运行高层骨干前 ℓm 层，整体吞吐量仍低于单模型独立执行，在低算力边缘设备上的部署受限。
3. **未解决跨任务/跨机器人泛化**：实验集中于同分布任务变体，未在未见过的物体类别或全新操作技能上验证；真机仅桌面短程任务，未涉及移动操作或长时程（>10 分钟）任务。
4. **动作块离散化限制**：统一候选集仅在固定时间尺度上进行前缀选择，不能生成任意长度的连续动作段，也无法在块执行中途根据视觉反馈实时调整动作（只能在块结束时截断）。

## 8. 相关工作与创新点再定位

- 与 **HPE（Hierarchical Planning with Executor）** 相比，SparkVLA 不再使用独立的 Q-function/终止检测器，而是将终止判断融入排序候选，消除了双模块训练目标不一致的问题。
- 与 **AQC / ACH / DEHP** 等自适应块长方法相比，这些方法只优化“执行多长”，无法表达“已完成后停止”，SparkVLA 统一了这两种控制维度。
- 与 **VLM 直接生成动作块**的基线（如 OpenVLA-OFT、π0.5）相比，SparkVLA 通过锚定历史保持跨子任务的状态一致性，不被过长全局指令遗忘早期子任务约束。

**创新点聚类**：
- 概念创新：两决策的相互依赖形式化，统一为单候选排序；
- 架构创新：历史感知锚点 + 锚定视觉剪枝 + 高层隐特征编码；
- 算法创新：成对排序目标 + 停止感知辅助损失，无需在线奖励或阈值调参；
- 工程创新：缓存机制将推理吞吐量恢复到独立模型水平的 88%。

- 文中明确表示代码、模型权重与数据集将随论文发布，并提供 RoboCerebra 评测接口、LIBERO 标注预处理脚本和真机部署配置（运动学参数、相机位姿）等细节。
- 评测 metric 定义为按完整任务成功率（SR）与子任务终止精度（Stop Acc），对所有参与方法统一。
- 优化器设置、LoRA 秩、学习率等关键超参均已在论文附录表格中列出（见上一轮总结第 4 节）。

## 10. 总体评价与推荐场景

- **优点**：问题定义清晰，提出了一种优雅的统一排序框架，避免了分层 VLA 长期存在的接口不匹配问题；在三个基准和真机上均取得一致的显著提升；实验控制严谨、消融完整。
- **缺点**：对标注的依赖、计算资源门槛较高、扩展任务域有限。
- **适用场景**：对需要长时间序列多技能组合的桌面操作任务（如配料、整理、装配）、有离线高质量演示和子任务标注的工业或家居机器人场景，尤其适用。
- **不适合场景**：需要毫秒级实时反应的低延迟交互任务、无标注开放世界学习场景。

## 总结

SparkVLA 的核心贡献在于将“何时停止子任务”和“执行多长动作块”这两个纠缠的决策统一为同一排序问题，让高层规划器在每一步都能综合“已完成什么”和“接下来打算做什么”的信息进行控制。它在 RoboCerebra、LIBERO 和真实机器人上全面超越了独立 VLA 和现有分层 VLA 方法，为该方向提供了新的性能基准。

未来可能的发展方向包括：引入在线自适应排序目标以摆脱离线标注、将统一排序扩展到连续时间动作、以及与记忆增强架构结合以处理更长任务。
