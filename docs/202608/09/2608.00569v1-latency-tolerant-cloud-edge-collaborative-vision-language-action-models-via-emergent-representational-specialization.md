## 摘要
在移动机器人上部署十亿参数的视觉-语言-动作（VLA）策略会产生系统冲突：语义推理受益于云端GPU，而闭环控制必须在本地响应，尽管存在网络延迟和抖动。现有的分层和异步策略提高了吞吐量，但其慢路径表示仍然可能过时到达，或需要显式调度和延迟提示。我们提出了CloudEdgeVLA，一种云-边策略，它将时间错位视为表示学习问题。云端VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头将最新可用的云特征与当前本地视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和过时路径中与相同的当前动作目标配对。这一目标鼓励云表示保留任务级信息，而边缘路径提供状态敏感的修正。在四个LIBERO套件上，CloudEdgeVLA在40步均匀延迟窗口内保持63.8%至78.0%的成功率，而VLASH最多达到6.4%，评估的单路径基线最多达到3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 二、方法论

### 2.1 核心思想

借鉴 Kahneman 的“系统1 / 系统2”双系统理论：

- **云侧 VLA 骨干（System 2，延迟不敏感）**：负责高层次任务规划，从观测与语言指令中提取慢变的规划特征 `h = fθ(o, ℓ)`。该特征应编码“做什么”（任务目标、操作策略、物体语义），而非“具体何时做”。
- **边缘视觉编码器（System 1 感知，延迟敏感）**：轻量级视觉编码器（如 SigLIP-Base）从当前观测提取实时特征 `zt = vψ(ot)`，始终来自最新帧，无延迟。
- **边缘动作头（System 1 控制，延迟敏感）**：融合可能过时的云规划特征与实时视觉特征，输出动作 `â_t = gϕ(h_{t-k}, z_t)`。动作头不阻塞等待云端，使用最新收到的云特征即可。

### 2.2 关键技术：配对帧双路径训练（Paired-Frame Dual-Path Training）

- **训练样本构造**：从同一演示轨迹中取长度为 W 的窗口，得到：
  - 当前帧 `o_t`
  - 延迟帧 `o_{t-d}`，其中 `d ~ Uniform(1, W-1)`
- **双前向传播**：两个帧分别经过云骨干：
  - `h_fresh = fθ(o_t, ℓ)`
  - `h_stale = fθ(o_{t-d}, ℓ)`
  - 注意 `h_stale` 不 detached，两条路径均接收梯度。
- **视觉增强的动作预测**：两组规划特征分别与同一实时视觉特征 `z_t` 融合：
  - `â_fresh = gϕ(h_fresh, z_t)`
  - `â_stale = gϕ(h_stale, z_t)`
- **双路径损失**：
  ```
  L = (1-λ) * ||â_fresh - a_t||₁ + λ * ||â_stale - a_t||₁
  ```
  - `L_fresh` 训练同步操作并给骨干提供直接动作监督；
  - `L_stale` 训练动作头利用实时视觉补偿陈旧规划特征；
  - `λ` 采用课程学习，在训练前 `n_warmup` 步内从 0 逐渐增加到 `λ_max`，先让骨干学到强表示再施压其延迟不变性。

### 2.3 部署协议

1. 边缘捕获当前观测 `o_t`，异步发送至云；
2. 云处理延迟观测 `o_{t-k}` 并返回规划特征 `h`；
3. 边缘收到后更新 `h_received`；
4. 边缘计算实时视觉特征 `z_t = vψ(o_t)`；
5. 边缘计算动作 `â_t = gϕ(h_received, z_t)`；
6. 执行动作；**机器人从不阻塞等待云**。

### 2.4 涌现表示特化（Emergent Representational Specialization）

- 随机延迟 `d` 下，仅与 `o_{t-d}` 瞬时状态相关的特征无法可靠预测 `a_t`，而任务身份、目标、粗略进度等信息更具稳定性；
- 该训练压力**鼓励（但不保证数学上）** 对时间位移的不变性，与 Achille & Soatto 的干扰变量与不变表示理论一致；
- 当前边缘特征 `z_t` 保留状态敏感信息，形成云-边互补的鲁棒性设计。

## 六、主要结论与发现

1. **延迟容忍性显著优于基线**：
   - dmax=40 时，CloudEdgeVLA 在 LIBERO 四个套件上保持 63.8–78.0% 成功率，而 VLASH 最高仅 6.4%，单路径基线最高 3.0%。
2. **延迟-保留性能**：
   - 四套件宏均值的归一化延迟 AUC 达 90.8%，VLASH 仅 32.4%；
   - 在 dmax=40 时保留同步成功率的 76.5%，VLASH 仅 1.8%。
3. **最差套件仍有显著优势**：
   - Long 套件在 dmax=40 下降最多（63.8%），但仍比最强基线高 63.3 个百分点。
4. **机制定位**：
   - 训练后骨干漂移在 d=20 时降低 59.2%（Dh 从 0.391 降至 0.160）；
   - 头部转移增益 κ 降低 72.7%（从 1.082 降至 0.295）；
   - 端到端动作漂移降低 88.9%，演示 MAE 降低 88.5%。
5. **视觉编码器消融结论**：
   - 添加冻结 SigLIP-Base 使成功率从 31.6% 提升至 95.1%（+63.5 点）——实时视觉接地是核心；
   - 换用更大的 SigLIP-SO400M 仅提升 0.7 点——编码器容量非瓶颈，支持轻量 Base 部署。
6. **损失路径消融结论**：
   - 仅陈旧监督（L_stale only）达 89.2%，比仅新鲜监督（54.8%）高 34.4 点——延迟暴露是鲁棒性的主要驱动力；
   - 联合监督进一步恢复至 95.1%——新鲜路径提供补充接地而不替代延迟暴露。
7. **真实机器人**：在 1000 ms 附加 RTT 下，CloudEdgeVLA 保持 80/70%（静态/动态）成功率，VLASH 降为 0/0%。
8. **反事实审计发现（重要负面结果）**：当前 120k 检查点中，边缘视觉对陈旧云特征的直接修复能力极弱（edge-rescue fraction 仅 0.03%），鲁棒性主要来自**更稳定的骨干**和**头部对残余漂移的衰减**，而非边缘视觉的直接修正。

## 七、优点

1. **问题重构视角新颖**：将延迟稳健性转化为表示学习问题，而非纯粹的调度或推理优化，为云-边VLA协同提供了新思路。
2. **非阻塞设计简洁实用**：边缘侧始终使用最新可用云特征，无需时钟对齐、频率匹配或延迟元数据，适用于真实网络环境。
3. **训练目标自然**：配对帧双路径训练无需额外的不变性损失或对抗训练，仅通过共享动作监督实现表示特化，方法简洁。
4. **课程学习调节**：λ 从 0 渐变，先学习新鲜路径再施加延迟压力，避免早期训练不稳定。
5. **系统-1/系统-2 类比清晰**：架构划分与理论框架一致，易于理解和推广。
6. **实验设计严谨且诚实**：
   - 包含多种子统计；
   - 消融实验逐一验证关键组件；
   - 机制诊断区分了骨干与头部贡献，并报告了负面结果（边缘视觉直接修复效果极小）；
   - 真实机器人实验明确标注为可行性检查，不夸大结论。
7. **实际系统意义强**：云模型可独立扩展（规模增长不增加边缘负担），边缘只需轻量编码器和动作头，适合移动机器人。

## 八、不足与局限

1. **延迟分布范围有限**：鲁棒性仅在测试的延迟分布（均匀 1–40 步）内得到验证；论文明确表示不适用于无限延迟或云断连情况。
2. **训练计算开销高**：配对帧训练需要两次骨干前向传播，训练成本约为单路径的两倍（针对骨干部分），对资源有限的研究者不友好。
3. **边缘视觉模态单一**：仅使用冻结 RGB 编码器，缺少深度、力觉、触觉等模态，可能限制对复杂接触操作的鲁棒性。
4. **真实机器人评估薄弱**：
   - 仅 10 次试验/条件，统计功效不足；
   - 仅单一平台（Franka）与单一任务；
   - 边缘设备为工作站级 RTX 5080，不能代表嵌入式或低功耗平台性能。
5. **机制声称与证据的差距**：
   - 作者承认不保证不变性，仅“鼓励”；
   - 反事实审计显示当前检查点的边缘视觉直接修正作用极小，削弱了“边缘路径提供状态敏感修正”的原始叙述（虽然整体鲁棒性仍然成立）。
6. **基线比较公平性存疑**：
   - 单路径基线被直接喂入延迟帧，未做任何异步适配；
   - VLASH 与 CloudEdgeVLA 在信息获取上不对称：CloudEdgeVLA 拥有当前边缘视觉，而 VLASH 可能没有同等实时信息。
7. **缺乏真实网络条件的验证**：实验使用均匀延迟窗口模拟，未覆盖实际网络中的突发抖动、丢包、非平稳延迟分布。
8. **缺少训练细节**：未报告 GPU 数量、训练时长、超参数敏感性（如 W、warmup、λ_max 的取值依据），可复现性信息不完整。
9. **超出训练窗口后的表现**：图中显示 dmax>20 超出训练窗口（训练窗口 W=21），虽然在 40 步时仍表现不错，但鲁棒性外推能力未被系统研究。
