## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略引发了系统层面的矛盾：语义推理受益于云端GPU，而闭环控制必须在网络延迟和抖动下于本地做出响应。现有的分层与异步策略虽能提升吞吐量，但其慢路径表征仍可能到达过时，或需要显式的调度与延迟提示。我们提出CloudEdgeVLA，一种将时间错位视为表征学习问题的云边策略。云端VLA将延迟观测编码为缓慢变化的任务特征，而轻量级边缘头部则将最新可用的云端特征与当前本地视觉相结合。训练过程中，当前帧与随机延迟帧在新鲜路径和过时路径中与相同的当前动作目标配对。这一目标鼓励云端表征保留任务级信息，同时由边缘路径提供状态敏感修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持63.8%–78.0%的成功率，而VLASH最高仅达6.4%，所评估的单路径基线最高仅达3.0%。通过从控制回路中移除阻塞式同步，该设计为可扩展的VLA部署提供了一条实用路径，使云端模型可以不断增长，而边缘计算保持轻量与响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 1. 核心问题与研究动机

- **背景冲突**：现代 VLA（视觉-语言-动作）模型（如 RT-2、OpenVLA、π0）具备强大的语义推理与操作能力，但模型规模达数十亿参数，难以部署在功耗和重量受限的移动机器人上。云端 GPU 可承担重计算，却引入了网络延迟、抖动与丢包。
- **核心矛盾**：语义推理适合放在云端，但闭环控制必须在本地快速响应。云端返回的特征描述的是“图像采集时刻”的场景，而非“动作执行时刻”的场景。
- **现有方案的不足**：
  - 分层/异步策略（MResT、DP-VLA、HiRT、SmolVLA）虽提升吞吐量，但慢路径表征仍可能过期到达，或需要显式调度与延迟提示。
  - 动作块重规划（action-chunk re-planning）假设环境在执行期间静止，加剧过时问题。
  - 同步快慢流水线需要固定频率比和有界延迟，在真实网络环境中难以满足。
- **论文立场**：延迟容忍不应仅被视为推理调度问题，而应被视为**表征学习问题**——设计跨网络传输的表征，使其在年龄可变且未知的情况下仍然有用。

## 2. 方法论：CloudEdgeVLA

### 2.1 核心思想

- 借鉴 Kahneman 的 System 1 / System 2 类比：
  - **云端（System 2）**：提供缓慢变化的**任务上下文**（做什么）——任务目标、操纵策略、物体语义。
  - **边缘（System 1）**：使用当前本地视觉进行**状态敏感控制**（现在怎么做）。
- 边缘**永不阻塞**等待云响应，始终使用最新收到的云端特征与当前边缘视觉结合。
- 通过**配对帧双路径训练**（Paired-Frame Dual-Path Training），促使云端特征在时间上更稳定、对观测年龄不敏感，同时由边缘视觉补充状态级细节。

### 2.2 系统架构（三个组件）

1. **云侧 VLA 主干 fθ（System 2）**：
   - 大规模 VLM（基于 OpenVLA-OFT，7B 参数，LoRA 适配）。
   - 输入观测 o 与语言指令 ℓ，输出规划特征 h = fθ(o, ℓ) ∈ ℝ^(L×D)，其中 L = T × A（动作块长度 × 动作维度）。
   - 设计目标：编码“做什么”而非“何时做”。

2. **边缘视觉编码器 vψ（System 1 感知）**：
   - 轻量级视觉编码器（默认 SigLIP-Base，对比更大模型 SigLIP-SO400M）。
   - 训练期间冻结，从当前观测 ot 提取实时特征 zt。
   - **始终无延迟**，捕捉环境瞬时状态。

3. **边缘动作头 gϕ（System 1 控制）**：
   - 融合（可能过时的）云端特征 ht-k 与实时边缘特征 zt，预测连续动作。
   - 结构：对规划特征按动作维度做平均池化 → 将视觉特征投影到相同潜空间 → 拼接 → 通过残差 MLP 预测动作块。
   - 作用：实时“落地”层，将云端高级意图转化为精确电机指令。

### 2.3 配对帧双路径训练

- **配对帧提取**：从同一 episode 中取长度 W 的观测窗口，构造：
  - 当前帧：ot
  - 延迟帧：ot-d，其中 d ~ Uniform(1, W-1)
- **双前向传播**：
  - h_fresh = fθ(ot, ℓ)，h_stale = fθ(ot-d, ℓ)
  - 两条路径均接收梯度（不 detached）。
- **视觉增强动作预测**：两组规划特征分别与同一实时视觉特征 zt 融合：
  - â_fresh = gϕ(h_fresh, zt)，â_stale = gϕ(h_stale, zt)
- **双路径损失**：
  - L = (1−λ)‖â_fresh − at‖₁ + λ‖â_stale − at‖₁
  - 使用**课程学习**：λ 从 0 渐增至 λ_max（经过 n_warmup 步），让主干先学强表征再被压力训练为延迟不敏感。

### 2.4 部署协议（完全异步）

1. 边缘捕获当前观测 ot → 发送至云（异步、非阻塞）。
2. 云返回 h（可能来自之前的 ot-k）→ 边缘更新 h_received。
3. 边缘计算 zt = vψ(ot)（实时、本地）。
4. 边缘计算 ât = gϕ(h_received, zt) 并执行。
5. **永不等待**特定云响应。

### 2.5 涌现表征特化

- 梯度分析：∇θL_stale = ∇θ‖gϕ(fθ(ot-d, ℓ), vψ(ot)) − at‖₁，随 d 随机变化，仅依赖于即时状态的云特征成为不可靠的动作预测器，而任务身份、目标、粗略进度更为稳定。
- 该目标**鼓励但不数学保证**时间位移不变性，与 Achille & Soatto 的干扰变量和不变表征理论一致。

## 6. 主要结论与发现

1. **主干结果**：在 dmax=40 时，CloudEdgeVLA 在四个 LIBERO 套件上保持 63.8%–78.0% 成功率；VLASH 最高仅 6.4%，单路径基线最高 3.0%。
2. **延迟保留**：归一化延迟 AUC 达 90.8%（VLASH 为 32.4%）；在 dmax=40 时保留同步成功率的 76.5%（VLASH 仅 1.8%）。
3. **套件差异**：Long 套件退化最大（27.9 个百分点下降），Goal 最稳定；最差情况下仍比最强基线高 63.3 个百分点。
4. **消融结论**：
   - 实时边缘视觉是决定性因素：无视觉编码器时成功率为 31.6%，加入 SigLIP-Base 后跃升至 95.1%（+63.5 点）；更大编码器 SO400M 仅再提高 0.7 点，支持轻量 Base 模型。
   - 延迟暴露是关键：仅 L_stale 训练达 89.2%，仅 L_fresh 仅 54.8%；联合训练最佳（95.1%）。
5. **机制发现**：
   - CloudEdgeVLA 在 d=20 时降低主干漂移 59.2%（Dh 从 0.391 降至 0.160）。
   - 降低头部传递增益 72.7%（κ 从 1.082 降至 0.295）。
   - 组合效果：动作漂移降低 88.9%（0.423→0.047），演示 MAE 降低 88.5%（0.421→0.048）。
   - **重要反事实发现**：在 120k 检查点中，当前边缘视觉对过期云端特征的直接修正作用极小（edge-rescue fraction 仅 0.03%），主要增益来自更稳定的主干+头部衰减，而非边缘视觉的直接“救援”机制。
6. **真实机器人**：1000ms RTT 下 CE-VLA 保持 80%/70%（静态/动态），VLASH 降至 0%/0%。

## 7. 优点

- **问题重构有新意**：将云边延迟问题从推理调度/动作块修正重构为表征学习问题，提出了新的视角。
- **非阻塞接口设计优雅**：边缘始终使用最新可用特征，无需时钟/频率对齐，实用性强。
- **训练目标简洁有效**：无需显式不变性损失或延迟元数据，配对帧双路径损失自然引导表征特化。
- **机制分析深入**：不满足于端到端成功率，通过离线诊断精确定位鲁棒性来源（主干稳定性 vs. 头部衰减），包括诚实的反事实负面结果。
- **消融设计严谨**：清晰分离了各组件贡献（视觉编码器 vs. 损失路径）。
- **课程学习设计合理**：先稳定主干再逐步引入延迟压力。
- **前沿基线对比**：与最新的 VLASH 和 UniVLA 对比，基准选择有代表性。
- **写作诚实**：明确承认局限（“不保证数学不变性”、“不暗示无界延迟鲁棒性”、“真实机器人实验是可行性检查而非硬件基准”）。

## 8. 不足与局限

- **延迟鲁棒性范围有限**：仅在均匀延迟分布（最大 40 步）下验证；无界延迟或云断连将使任务级上下文失效。作者明确承认需要时间戳特征和本地回退策略来处理断连场景。
- **计算成本**：配对帧双路径训练需要两次主干前向传播，训练成本约为标准单路径方法的约两倍；但论文未提供完整的训练效率分析。
- **感知模态有限**：冰冻 RGB 编码器无法捕捉深度、力觉或接触信息，可能限制在需要力控或 3D 感知的任务上的表现。
- **真实机器人实验证据弱**：仅 10 次试验/条件、单平台（Franka）、工作站级边缘设备（RTX 5080），不代表嵌入式效率或广泛硬件泛化能力。
- **机制声明的疑点**：反事实审计表明 120k 检查点的边缘视觉直接修正作用极小（0.03%），这与论文标题中“Emergent Representational Specialization”的机制叙述存在一定张力；真实机制主要是主干稳定性+头部衰减，而非边缘实时视觉的直接“救援”——这也意味着当前训练结果更接近“让云端特征更稳定”，而非真正实现系统 1/2 的互补分工。
- **基线比较的对称性不足**：基线为点估计，CloudEdgeVLA 报告了种子方差；VLASH 等方法的同种子公平对比缺失。
- **单一基准**：仅在 LIBERO 模拟环境验证；真实任务覆盖窄（单一拾放任务）。
- **时间错位的度量单位**：延迟以环境步（steps）为单位，其墙钟时长取决于控制频率和网络管线，无法直接转换为特定硬件下的毫秒级延迟，限制了与真实网络条件的直接对应。
- **方法对任务类型的泛化不足**：未验证复杂长程任务（如多步操作、动态环境交互）中的表现。
