## 摘要
在分层视觉-语言-动作（VLA）系统中，每当重新观察时，必须做出两个接口决策：何时终止当前子任务，以及执行提议的动作块到什么程度。这两个决策相互依赖——最优停止点取决于执行者计划做什么，而最优执行长度取决于子任务边界在哪里——然而现有架构孤立地评估它们，这种不对称性是任何单独模块都无法克服的。我们提出SparkVLA，一种停止感知的分层VLA，通过将这两个决策表述为单一排序来解决这种相互依赖：停止与每个动作前缀长度在统一候选集中竞争，系统选择得分最高的选项，消除了阈值调整，并且只需要离线序数偏好。一个锚定条件上下文编码模块缓存历史感知的子任务锚定编码、起始状态记忆和目标语义，指导视觉标记剪枝朝向任务相关区域；一个停止感知的动作前缀选择头在块边界通过全自注意力对所有候选进行评分，以提高效率。在RoboCerebra上，SparkVLA实现了47.12%的成功率，超过官方分层基线30.57%，超过最强的可复现方法26.83%。在多步骤任务上的真实机器人实验进一步验证了这些在物理硬件上的收益。

## Abstract
At every re-observation point in a hierarchical Vision-Language-Action (VLA) system, two interface decisions must be made: when to terminate the current subtask and how far to execute the proposed action chunk. These decisions are mutually dependent---the optimal stopping point depends on what the executor plans to do, while the optimal execution length depends on where the subtask boundary lies---yet existing architectures evaluate them in isolation, an asymmetry neither module can overcome alone. We present SparkVLA, a stop-aware hierarchical VLA that resolves this mutual dependency by formulating both decisions as a single ranking: Stop competes against every action-prefix length in a unified candidate set, and the system selects the highest-scoring option, eliminating threshold tuning and requiring only offline ordinal preferences. An Anchor-Conditioned Context Encoding module caches a history-aware subtask anchor encoding onset-state memory and goal semantics, guiding visual-token pruning toward task-relevant regions; a Stop-Aware Action-Prefix Selection head scores all candidates via full self bnattention at chunk boundaries for efficiency. On RoboCerebra, SparkVLA achieves 47.12% success rate, surpassing the official hierarchical baseline by 30.57% and the strongest reproducible method by 26.83% Real-robot experiments on multi-step tasks further validate these gains on physical hardware.

## 1. 论文的核心问题与整体含义

- **研究背景**：现代视觉-语言-动作（VLA）模型在短程操控任务上表现优异，但在长时程、多技能组合的任务中往往失败。分层 VLA 架构通过“高层 VLM 规划器 + 低层 VLA 执行器”来缓解这一问题，但接口设计成为关键瓶颈。
- **核心问题**：在每个重观测边界，系统必须同时决定“何时终止当前子任务”（停止决策）和“执行多长的动作块”（执行水平）。现有方法通常将这两个决策**孤立地**处理：
  - 终止侧：使用二分类检测器、VLM 预测长度或进展信号，但看不到即将执行的计划；
  - 执行水平侧：DEHP、ACH、AQC、AAC 等方法只优化动作块长度，却无法发出子任务完成信号。
- **关键洞见**：这两个决策**相互依赖**——最优停止点取决于执行器下一步计划，最优执行长度取决于子任务边界位置。因此，任何独立模块都无法同时解决两者。论文提出把二者统一为**同一候选集上的排序问题**，从而消除阈值调参，仅需离线序数偏好监督。

## 2. 论文提出的方法论

### 2.1 核心思想
- 构建统一候选集 \(\mathcal{C} = \{0, 1, \dots, H\}\)：
  - 候选 0 代表 `Stop`（终止当前子任务）；
  - 候选 \(n \geq 1\) 代表执行动作块 `At` 的前 \(n\) 个动作（动作前缀）。
- 用一个共享的评分头对所有候选打分，选择最高分：\(\hat{n}_t = \arg\max_{i\in\mathcal{C}} s_{t,i}\)。停止与执行长度由此被联合求解。

### 2.2 关键技术细节

1. **分层架构**：基于预训练 π0.5 VLA 派生出两个分支：
   - 高层分支：VLM 主干，负责生成子任务命令并承载选择器；
   - 低层分支：完整 π0.5（含动作专家），负责提出动作块。
2. **历史感知的子任务锚点（History-Aware Subtask Anchor）**：
   - 在子任务开始时，从规划器最后一层的最后 token 提取原始锚点 \(\hat{\alpha}_k\)；
   - 维护锚点历史池 \(\mathcal{A}_k\)，通过自注意力将当前锚点与历史锚点融合，得到 \(\alpha_k\)，缓存在整个子任务中。
3. **锚点引导的视觉 token 剪枝**：
   - 冻结的 SigLIP 视觉编码器产生 dense tokens；
   - 使用可微分的 Grid-Sampler，以锚点为条件预测 \(K\) 个二维坐标，再通过双线性插值采样任务相关视觉 token，将每相机序列从 \(N\) 减至 \(K\)。
4. **高层隐藏特征编码**：将剪枝后的视觉 token、本体感受状态和子任务命令嵌入拼接，经过高层 VLM 的前 \(\ell_m\) 层（带 LoRA）得到当前边界的高层特征 \(m_t\)。
5. **停止感知动作前缀选择头（Stop-Aware Action-Prefix Selection）**：
   - 用全自注意力 Transformer 对 `Stop`、所有动作前缀候选进行联合评分；
   - `Stop` 用可学习嵌入初始化（但通过自注意力变为上下文相关）；
   - 长度 \(n\) 的候选由该前缀最后一个动作的 MLP 表示加上可学习的长度嵌入构成；
   - 输出每个候选的标量分数，直接选择最大者。
6. **训练目标**：
   - **成对排序损失**：根据离线执行结果定义序数优先级 \(\rho_i\)，构造可比对 \((i,j)\)，使用二分类交叉熵（BCE）优化相对顺序。
   - **停止感知辅助损失**：用 \(\text{Stop}\) 分数与 log-sum-exp 聚合的延续分数之差做二分类，强化停止边界。
   - 总损失 \(L = L_{\text{rank}} + \lambda_{\text{stop}} L_{\text{stop}}\)，共享同一组分数，推理时仍用统一的 argmax 规则。

### 2.3 算法流程（文字描述）
- 初始化语义历史与锚点历史为空。
- 每个子任务开始：规划器生成子任务命令 → 提取并融合锚点 → 缓存。
- 每个决策边界：低层执行器提出动作块 → 锚点引导视觉剪枝并计算高层特征 → 选择器统一打分 → 若选 `Stop` 则更新历史并生成下一子任务；否则执行对应前缀的动作，重观测后进入下一决策边界。

## 6. 主要结论与发现

- **核心结论**：将子任务停止与执行水平统一为单一排序可显著提升长时程操控性能。
- **RoboCerebra 结果**：SparkVLA 平均 SR 47.12%，比 standalone π0.5 高 34.83%，比官方 HPE 基线高 30.57%，比复现的 Mem-0 高 26.83%。在 Dynamic Obs.（+34.78%）和 Memory Exp.（+47.69%）上增益最大。
- **执行器无关**：换用 OpenVLA-OFT 和 SmolVLA 作为低层执行器时，增益分别达 +22.47% 和 +22.52%，说明收益来自统一接口设计而非特定模型搭配。
- **LIBERO 结果**：平均成功率 98.5%，尤其在 LIBERO-Long 上优势明显（98.0% vs π0.5 的 92.4%）。
- **统一候选集的双向收益**：停止准确率从 80.37% 提升到 96.65%（+16.28%，精确率 94.3%，召回率 98.1%），SR 从 42.53% 提升到 47.12%。
- **真实机器人**：平均成功率 69.3%，超过 π0.5 的 48.0% 21.3 个百分点；随任务复杂度增加（12 子任务的泡茶任务）提升更明显（+30.0%）。
- **行为模式**：自适应动作前缀在接近接触事件时缩短、在自由空间运输时延长，与仿真中观察到的一致。

## 7. 优点

- **问题建模创新**：清晰识别停止与执行水平的相互依赖性，并用统一排序优雅解决，消除了阈值调参和在线奖励需求。
- **高效设计**：
  - 锚点只需每个子任务提取一次并缓存；
  - 选择器只在块边界调用（而非每步）；
  - 视觉 token 剪枝 + 浅层骨干 + 紧凑选择头，推理吞吐仅损失 12%。
- **训练范式实用**：仅需离线序数偏好，不使用在线 RL，易于复现；通过边界扰动增强鲁棒性。
- **消融设计与控制严谨**：每个消融只改变单一因素，并设有公共评估协议，支持结论的可靠性。
- **系统泛化性好**：高层系统可与不同低层执行器组合，且在仿真和真实机器人上一致提升。

## 8. 不足与局限

- **实验覆盖有限**：
  - 主要评估集中在桌面操作、固定物体类别和离线训练设置；
  - 未涉及开放世界、未知物体、动态环境变化下的在线适应。
- **依赖预训练模型与标注**：
  - 依赖 π0.5 主干和 RoboCerebra 的子任务标注；对无标注或弱标注场景的适应性未验证；
  - 失败 rollout 的优先级设定带有一定启发式成分。
- **偏差风险**：
  - 官方基线 HPE 的结果直接引用原文，虽按官方协议，但并非本地复现；

  - 需多相机配置和较高计算资源（A100 80GB ×4）；
  - 当前动作块最大长度 H=50，对更长、更复杂的任务可能需要扩展候选空间；
  - 安全性依赖外部机械限位和急停，系统本身无显式安全保证。
