## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略会产生系统冲突：语义推理受益于云GPU，而闭环控制必须在网络延迟和抖动下本地响应。现有的分层和异步策略提高了吞吐量，但其慢路径表示可能仍然过期到达，或需要显式的调度和延迟提示。我们提出了CloudEdgeVLA，一种将时间错位视为表示学习问题的云边策略。云端VLA将延迟观测编码为缓慢变化的任务特征，而轻量级边缘头结合最新的可用云特征与当前本地视觉。在训练过程中，当前帧和随机延迟帧在新鲜路径和过时路径中与相同的当前动作目标配对。这一目标鼓励云表示保留任务级信息，同时边缘路径提供状态敏感的修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持了63.8–78.0%的成功率，而VLASH最高仅达到6.4%，所评估的单路径基线最高仅为3.0%。通过从控制环路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 1. 核心问题与整体含义（研究动机与背景）

- **部署矛盾**：数十亿参数的VLA模型在移动机器人上部署面临系统级冲突——语义推理需要云端GPU算力，而闭环控制必须容忍网络延迟和抖动、在本地快速响应。
- **传统方案的不足**：分层/异步策略（如MResT、DP-VLA、HiRT、SmolVLA）虽提升了吞吐量，但慢路径表示仍可能到达时已过期，且通常需要显式调度、固定频率比或延迟提示，在真实网络环境中难以满足约束。
- **核心思路转变**：CloudEdgeVLA 将"时间错配"重构为**表示学习问题**，而非调度问题。云端VLA将延迟观测编码为**缓慢变化的任务级特征**（System 2，做什么），边缘头结合最新云端特征与当前本地视觉产生动作（System 1，怎么做），**边缘从不阻塞等待云端**，始终使用最新到达的云特征。
- **整体含义**：通过去除控制环路中的阻塞同步，使云端模型可无限扩展、边缘计算保持轻量低延迟，为可扩展VLA部署提供了一条实用路线。

## 2. 方法论：核心思想、关键技术细节与公式

### 2.1 核心思想：涌现表征特化（Emergent Representational Specialization）
- 受 System 1/System 2 认知双系统启发：云提供**慢变的任务上下文**，边缘提供**实时的状态修正**。
- 目标：云特征对观测龄期不敏感（保留任务级信息），边缘路径补充状态敏感细节。

### 2.2 系统架构（三个组件，时序不对称）
| 组件 | 位置 | 功能 | 延迟敏感性 |
|---|---|---|---|
| 云端VLA骨干 fθ | 云服务器 | 将观测与语言指令编码为高层规划特征 h = fθ(o, ℓ) ∈ R^(L×D)，L=动作chunk长度×动作维度，D=隐层维度；采用LoRA微调 | 延迟不敏感 |
| 边缘视觉编码器 vψ | 机器人本地 | 从当前观测提取实时特征 zt = vψ(ot)，使用**冻结的** SigLIP-Base | 延迟敏感（始终实时） |
| 边缘动作头 gϕ | 机器人本地 | 融合（可能过期的）云端特征与当前视觉特征，输出动作 ât = gϕ(ht−k, zt) ∈ R^(T×A)；先对规划特征做mean-pooling，投影视觉特征至同一潜在空间，拼接后经残差MLP输出 | 延迟敏感 |

### 2.3 配对帧双路径训练（Paired-Frame Dual-Path Training）
- **配对帧提取**：从同一episode的W窗口 {o_(t−W+1),...,o_t} 中提取当前帧 o_t 和延迟帧 o_(t−d)，其中 d ∼ Uniform(1, W−1)。
- **双前向传播**：两帧分别通过云骨干，得到 h_fresh = fθ(o_t, ℓ) 和 h_stale = fθ(o_(t−d), ℓ)；**h_stale 不脱离计算图**，骨干亦接收梯度。
- **视觉增强动作预测**：两路规划特征均与同一实时视觉特征 z_t 融合，产生 â_fresh 和 â_stale。
- **双路径损失**：
  \[
  \mathcal{L} = (1-\lambda)\|\hat{a}_{\text{fresh}} - a_t\|_1 + \lambda\|\hat{a}_{\text{stale}} - a_t\|_1
  \]
  使用**课程学习**：λ 在前 n_warmup 步从 0 逐步升至 λ_max。
- **目标效果**：由于原子在随机延迟 d 下的梯度 ∇θL_stale 不依赖瞬时状态，迫使云端特征保留跨时间共享的任务身份、目标和粗粒度进度信息，而将状态敏感信息留给边缘路径。

### 2.4 部署协议（非阻塞异步推理）
1. 边缘捕获 o_t → 发送至云端（异步、非阻塞）；
2. 云端返回 h 后，边缘更新 h_received ← h（可能来自较早帧）；
3. 边缘本地计算 z_t = vψ(o_t)；
4. 计算 â_t = gϕ(h_received, z_t)；执行动作，**从不等待特定云特征**。

## 6. 主要结论与发现

1. **延迟鲁棒性显著**：在 dmax=40 时 CloudEdgeVLA 保持 63.8–78.0% 成功率，而 VLASH 最高仅6.4%、单路径基线最高仅3.0%；归一化延迟AUC达90.8%（VLASH仅32.4%），dmax=40时保留同步成功率的76.5%（VLASH仅1.8%）。
2. **鲁棒性来源被分解为两个互补机制**：配对帧训练使云骨干表示时间漂移降低59.2%（d=20），训练后的动作头使每单位骨干漂移向动作漂移的传递降低72.7%——两端贡献叠加使端到端动作漂移降低88.9%；且**不牺牲新鲜精度**（d=0时演示MAE仅0.023 vs 0.020，并在d≥1时反转）。
3. **消融厘清各部件价值**：加入当前边缘视觉带来63.5个百分点的增益（31.6%→95.1%），远大于编码器规模提升（+0.7pt）；延迟曝光训练（仅L_stale）比仅新鲜训练（仅L_fresh）高34.4个百分点，联合训练再增5.9个百分点。
4. **重要负面结果**（来自反事实审计）：在120k检查点上，当前边缘视觉**并未**直接"修正"过期的云特征（边缘救援分数仅0.03%）；鲁棒性优势主要来自更稳定的骨干和头的去敏感化，而非边缘对旧云特征的显式纠正——这一发现约束了机制声明，但未削弱端到端鲁棒性。
5. **套件间差异**：Long套件退化最大（−27.9pt），Goal最稳定（−18.5pt），即使最差情况仍比最强基线高63.3个百分点。

## 7. 优点与亮点

- **接口设计的简洁性与实用性**：非阻塞异步接口无需时钟/频率对齐，不要求延迟元数据，直接匹配真实网络条件；
- **方法论创新**：将延迟容忍从"调度/推理工程"问题转化为"表示学习"问题，配对帧+课程学习的设计精巧——用同一动作目标监督不同龄期特征，自然诱导特征的时间特化，无需显式不变性损失；
- **严谨的机制归因**：通过 D_h、κ 等定量指标精确定位鲁棒性来源，并主动报告反事实审计的负面结果，避免"因果过度声称"，展现了良好的科学素养；
- **消融的完备性**：单独验证了实时视觉、编码器容量、损失路径的各自贡献，结论可操作（如骨干稳定性+头衰减双管齐下的可迁移洞见）；
- **兼容可扩展性**：云端骨干可独立增长（LoRA微调），边缘仅需冻结的轻量编码器+小型MLP头，实际部署门槛低。
- **小规模真实机器人验证**：虽统计效能有限，但验证了在1秒级额外延迟下方法仍可用（80/70% vs 0/0%），提供了物理可行性证据。

## 8. 不足与局限

- **延迟分布覆盖有限**：仅在均匀延迟窗口上验证，"不意味着对无界延迟或云断连的容忍"，长时间断连连任务级特征都可能失效。
- **训练开销翻倍**：配对帧双前向使训练成本约为常规两倍，对超大模型可能成为瓶颈（论文未讨论缓解方案）。
- **视觉模态单一**：冻结的RGB编码器无法利用深度、力觉、触觉等模态信号，在精细操作场景可能受限。
- **真实验证规模小**：单一Franka平台 + 工作站级边缘设备（RTX 5080），非嵌入式设备；每格10次试验不具统计充分性；未测试真实网络波动（RTT由人工模拟均匀添加）。
- **核心机制未达预期**：论文希望边缘视觉"供给状态敏感修正"，但反事实审计表明在120k检查点上边缘的直接修正作用几乎为零——鲁棒性几乎全部来自骨干稳定化与头的衰减。这意味着论文在Intro/摘要中的叙述（"edge path supplies state-sensitive corrections"）与实际机制存在张力，虽然作者主动披露，但仍属于一种叙述与证据间的偏差。
- **未报告训练算力与能耗**：无法完整评估方法的训练可行性。
- **未评估极端网络条件**：丢包、重连、带宽波动、云端排队延迟等真实因素未建模；也缺少端到端墙钟延迟统计（延迟以环境步计量，非毫秒）。
