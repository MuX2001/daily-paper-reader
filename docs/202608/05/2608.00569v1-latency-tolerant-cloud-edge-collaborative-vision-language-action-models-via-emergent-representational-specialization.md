## 摘要
在移动机器人上部署十亿参数的视觉-语言-动作（VLA）策略会产生系统冲突：语义推理受益于云GPU，而闭环控制必须在网络延迟和抖动的情况下本地响应。现有的层次化和异步策略提高了吞吐量，但其慢路径表示仍可能过时到达，或需要显式调度和延迟提示。我们提出了CloudEdgeVLA，一种将时间错位视为表示学习问题的云-边策略。云VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头将最新的可用云特征与当前本地视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和过期路径中与相同的当前动作目标配对。该目标鼓励云表示保留任务级信息，同时边缘路径提供状态敏感的修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口内保持63.8%至78.0%的成功率，而VLASH最多达到6.4%，评估的单路径基线最多为3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想
- 借鉴 System 1 / System 2 认知双系统类比：
  - **云侧主导（System 2）**：负责缓慢变化的“任务上下文”（做什么）——任务目标、操作策略、物体语义等，对延迟不敏感。
  - **边缘侧主导（System 1）**：负责实时控制（当前怎么做）——基于当前本地视觉进行状态敏感的精确动作修正。
  - 关键设计原则：**边缘端永远不做阻塞等待**，始终使用最新收到的云特征与当前的边缘视觉特征共同生成动作。

### 系统架构（三个组件，存在明确的时间不对称性）

| 组件 | 角色 | 说明 |
|---|---|---|
| 云侧 VLA 骨干 fθ（System 2） | 延迟不敏感 | 大规模视觉-语言骨干，LoRA 适配，在云端生成高层规划表示 h = fθ(o, ℓ) |
| 边缘视觉编码器 vψ（System 1 感知） | 延迟敏感 | 轻量级编码器（如 SigLIP-Base），计算当前的实时视觉特征 zt = vψ(ot)，训练时冻结 |
| 边缘动作头 gϕ（System 1 控制） | 延迟敏感 | 融合（可能过时的）云规划特征与当前边缘视觉特征，生成连续动作，包含特征拼接 + 残差 MLP |

### 配对帧双路径训练（Paired-Frame Dual-Path Training）
- 从同一演示轨迹中采样一个窗口 W 的连续观测。
- 构造当前帧 ot 与随机延迟帧 ot−d（d ~ Uniform(1, W−1)）。
- 两帧分别通过云骨干：
  - hfresh = fθ(ot, ℓ)，hstale = fθ(ot−d, ℓ)
  - 两条路径均回传梯度，不截断。
- 两个规划特征与同一个当前边缘视觉特征 zt 融合：
  - âfresh = gϕ(hfresh, zt)，âstale = gϕ(hstale, zt)
- 双路径损失：

  L = (1 − λ)‖âfresh − at‖₁ + λ‖âstale − at‖₁

- **课程学习**：λ 从 0 逐步升至 λmax，先让骨干学习强表征，再施加延迟不变性压力。

### 部署协议（完全异步）
1. 边缘采集当前观测 ot；
2. 异步发送到云端（非阻塞）；
3. 云端返回规划特征 h（可能来自较早的 ot−k）；
4. 边缘本地计算 zt = vψ(ot)；
5. 动作头计算 ât = gϕ(hreceived, zt)；
6. 执行动作，循环往复。**机器人从不等待云响应。**

### 涌现式表征特化
- 训练目标 ∇θLstale 在随机延迟 d 下，只有与“瞬时状态”无关的慢变任务特征才能稳定预测当前动作，从而促使云侧特征对时间位移产生鲁棒性（虽无数学保证）。
- 当前边缘特征 zt 则专门负责编码状态敏感信息，形成互补。

## 6. 主要结论与发现

- **端到端延迟鲁棒性**：在 dmax=40 时，CloudEdgeVLA 在四个 LIBERO 套件上保持 63.8%–78.0% 成功率，而 VLASH 最高仅 6.4%，单路径基线最高仅 3.0%。
- **延迟保留指标**：四套件宏平均的归一化延迟 AUC 达 90.8%（VLASH 仅 32.4%）；dmax=40 时保留同步成功率的 76.5%（VLASH 仅 1.8%）。
- **消融结论**：边侧视觉路径带来 +63.5 个百分点增益（31.6% → 95.1%）；朴素 SigLIP-Base 已足够，更大编码器（SO400M）仅多 0.7 个百分点；stale-only 监督提供主要鲁棒性（89.2%），联合监督再补充 5.9 个百分点。
- **机制分解发现**：
  - 骨干隐藏状态漂移在 d=20 时降低 59.2%（0.391 → 0.160）。
  - 动作头传递增益 κ 降低 72.7%（1.082 → 0.295）。
  - 端到端动作漂移降低 88.9%，演示 MAE 降低 88.5%。
  - **反事实审计的关键发现**：在 120k 步检查点上，当前边缘视觉对过期云特征的直接“修正”作用几乎为零（修正占比仅 0.03%），其主要贡献来自骨干稳定性和动作头的衰减作用——即“训练压出来的表征稳定性”，而非推理时的显式修正。
- **整体定位**：延迟容忍能力可以作为一个已学习的“接口属性”（learned interface property），而不是仅靠调度/同步策略。

## 7. 优点

- **问题建模新颖**：将网络延迟/时延问题从调度层提升到表征学习层，理论视角独特（借鉴不变性与混杂变异的联系）。
- **系统设计简洁实用**：非阻塞接口，无时钟对齐需求，无需延迟元数据，部署协议清晰可行，可直接落地。
- **训练方法优雅**：配对帧双路径训练不需显式不变性损失，而是通过“共享动作监督”自然涌现出时间特化表征；课程学习进一步稳定训练。
- **实验体系完善**：仿真 + 真机 + 离线机制诊断三层验证互不替代又互补；延迟扫描范围宽（至 40 步），超出训练窗口仍有泛化。
- **机制归因诚实**：通过反事实分析明确区分了“表征稳定贡献”与“边缘直接修正贡献”，没有夸大网络架构的作用，体现了较好的学术诚实度。
- **编码器选择理性**：基于实验数据（Base 与 SO400M 差异仅 0.7%）论证了轻量边缘编码器的合理性，有利于实际部署的算力约束。

## 8. 不足与局限

- **延迟分布覆盖有限**：仅测试均匀延迟窗口；未覆盖重尾分布、突发大延迟、断连等情况。模型在极端断连下可能连任务级上下文都失效。
- **训练开销偏高**：配对帧双路径训练每样本需两次云端骨干前向传播，LoRA 微调本身也是一种折中；大模型快照同步与训练成本未量化分析。
- **感知模态受限**：冻结的 RGB 编码器无法利用深度、力觉、触觉等信息，对精细操作或接触丰富的任务可能不足。
- **VLA 级扩展性未验证**：所有实验基于单一骨干族（OpenVLA/OpenVLA-OFT）；对 π0、Octo 等不同架构的通用性未知。
- **真实机器人验证规模很小**：单平台（Franka）、单任务（pick-and-place）、10 次/条件，作者明确承认是可行性检查而非统计性强的硬件基准，且边缘端为工作站级算力而非嵌入式设备。
- **机制层面的结论有所限定**：反事实实验表明“边缘直接修正”在检查点上作用微弱，这一结果可能受训练步数、骨干架构等影响，不能推广到整个训练曲线。
- **缺少硬件延迟真实模拟**：实验中的延迟为环境步计数，与真实毫秒级网络延迟的映射关系未标定；RTT 模拟在真机中为叠加延迟，原生延迟依然存在。
