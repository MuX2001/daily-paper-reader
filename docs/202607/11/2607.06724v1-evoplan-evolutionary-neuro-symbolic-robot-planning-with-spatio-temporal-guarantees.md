## 摘要
基于LLM的机器人规划器具有流畅性，但无法保证其规划是可执行或安全的。经典的PDDL规划器可以保证这些属性，但只有在问题被完全指定之后，并且它们没有充分利用LLM读取上下文和修复规划的能力。本文提出了一种神经符号框架，包含三个部分。所有LLM调用均使用本地托管的开放权重模型，因此整个流水线可以在机器人上部署，无需依赖云端。首先，一个离线过程，从演示数据中挖掘单个全局信号时态逻辑（STL）约束，该过程根据演示编码的内容，恢复编纂的规则（例如，在红灯前停车，从nuPlan驾驶日志中挖掘）或人群偏好（例如，社会导航舒适度，从SCAND远程操作中挖掘）。由于演示是单类信号，我们通过反事实扰动和LLM违规生成器生成缺失的负例，然后通过进化搜索拟合约束。我们使用挖掘出的约束来保护Bench2Drive上的视觉-语言驾驶策略和HA-VLN-CE上的两个离散动作导航策略。其次，一个进化PDDL规划器：LLM提出并修复规划，程序化验证器决定哪些规划存活，并且规划的验证部分在迭代中增长。我们在开放世界ALFWorld文本基准上测试该规划器，它超越了强基线，并且在目标词汇与动作模型词汇不匹配时保持鲁棒性。第三，一个受约束的执行循环：规划器的规划被编译为航点，航点与挖掘出的约束进行检查，规划器在违反时重新规划。我们通过使用Gazebo模拟器的演示来说明完整流水线。

## Abstract
LLM-based robot planners are fluent but cannot guarantee that their plans are executable or safe. Classical PDDL planners can guarantee these properties, but only after the problem is fully specified, and they make poor use of an LLM's ability to read context and repair plans. This paper presents a neuro-symbolic framework with three parts. All LLM calls use a locally-hosted open-weight model, so the pipeline can be deployed on-robot with no cloud dependency. First, an offline procedure that mines a single global Signal Temporal Logic (STL) constraint on mobility from demonstration data. The procedure recovers codified rules (e.g., stopping at red lights, mined from nuPlan driving logs) or population preferences (e.g., social-navigation comfort, mined from SCAND teleoperation), depending on what the demonstrations encode. Because the demonstrations are a one-class signal, we generate the missing negatives with counterfactual perturbations and an LLM violation generator and then fit the constraint by evolutionary search. We use the mined constraint to shield a vision-language driving policy on Bench2Drive and two discrete-action navigation policies on HA-VLN-CE. Second, an evolutionary PDDL planner: an LLM proposes and repairs plans, programmatic validators decide which ones survive, and the validated portion of the plan grows over iterations. We test the planner on the open-world ALFWorld Text benchmark, where it beats strong baselines and stays robust when the goal vocabulary does not match the action-model vocabulary. Third, a constrained execution loop: the planner's plan is compiled into waypoints, the waypoints are checked against the mined constraint, and the planner re-plans on a violation. We illustrate the full pipeline via demonstrations using the Gazebo simulator.

### 关键技术细节

#### （1）离线STL约束挖掘
- **输入**：专家演示轨迹（单类数据，全部可接受），无标注违规。
- **反事实负例生成**：通过十种程序化模式（超速、 reckless转弯、拥挤、闯红灯等）扰动信号，辅以LLM生成一个现实违规，形成正集 $D^+$ 和负集 $D^-$，将问题转化为监督分类。
- **进化STL拟合**：使用LLM驱动的进化搜索（借鉴AlphaEvolve），目标函数为：
  $$\max_{\Phi \in \mathcal{G}} \mathbb{E}_{\tau \in D^+} \rho(\tau, \Phi) - \lambda_- \mathbb{E}_{\tau \in D^-} \max(0, \rho(\tau, \Phi)) - \lambda_c \text{complexity}(\Phi)$$
  其中 $\rho$ 为STL鲁棒性，复杂度惩罚防止过拟合/琐碎公式。
- **输出**：一个全局STL公式 $\Phi_{mob}$，包含速度、间隙、社会距离、交通灯状态等原子，由17个 $\Box$ 约束组成（例如 $G(\text{speed} \leq 2.603), G(\text{min_clearance} \geq 0.483)$ 等）。

#### （2）进化式PDDL规划器（EvoPlan）
- **核心思想**：将PDDL规划搜索建模为“机器可评估的进化”过程。
- **循环流程**：
  - 初始化：LLM生成初始候选规划。
  - 每代：LLM根据父代的验证器反馈（哪个动作失败、哪个前提未满足）提出编辑（插入前提动作、修复对象绑定、换序、重采样后缀等）。
  - 四阶段验证级联：PDDL语法检查 → VAL模拟 → 目标可达性 → （连续执行时）STL鲁棒性预测。短路机制。
  - 精英保留：已验证前缀长度 $\frac{|\pi_{\text{valid}}|}{|\pi|}$ 单调增长（实验证明）。
- **开放世界与词汇不对齐**：
  - 开放世界：从信念状态 $B$ 构建问题 $P$；“对象未声明”失败触发探索。
  - 词汇不对齐（如目标“heated”vs动作“toast”）：一次LLM调用生成谓词符号映射 $\mu$，应用于 $P$ 的目标谓词后执行VAL。

#### （3）约束执行循环
- PDDL规划 $\pi = (a_1, \ldots, a_n)$，每个动作 $a_k$ 被导航层扩展为航点序列 $w_k$。
- 检查 $w_k$ 是否满足 $\Phi_{mob}$：满足则执行；否则提交已验证前缀 $a_1\ldots a_{k-1}$，更新世界状态，重新调用规划器。
- 实现：ROS 2适配器 + 差速驱动模型（Gazebo Jackal）+ Nav2 + 本地距离场、人体跟踪等。
- 故障事实接口：`route-blocked`、`no-safe-approach` 等反馈回符号规划器。

## 6. 论文的主要结论与发现

1. **STL约束挖掘有效**：从单类演示数据通过反事实负例+进化搜索，能恢复精确的规则（nuPlan→红灯停、间距）和偏好（SCAND→社交距离），且可零样本迁移到新基准（Bench2Drive、HA-VLN-CE），无目标域训练。
2. **屏蔽显著提升安全性**：
   - 驾驶：红灯违规-77%，碰撞-71%，驾驶分数提升（最佳α=0.30达到66.20 vs 无屏蔽62.96）。
   - 社交导航：PointNav可避免接触下降82%，MLP下降93%；个人区暴露显著压缩；成功率基本保持不变。
3. **进化PDDL规划器优于纯符号和纯LLM**：
   - 开放世界ALFWorld：Qwen3-32B达到98.5% SR，超过NL-PDDL的94%和所有LLM基线；在词汇不对齐情况下保持98.5%（NL-PDDL降到91%）。
   - 封闭世界Blocksworld：Plain上99.7%，Mystery上74.0%（超过NL-PDDL的70%），Misalignment上100%（Fast Downward为0%）。
4. **受约束执行循环可端到端运行**：Gazebo中5次任务4次无碰撞，个人区暴露<13% ticks，密集人群下优雅降级（亲密区暴露<2%）。
5. **软策略先验的必要性**：对循环策略（如DD-PPO PointNav），策略先验权重 α 必须非零以避免偏移训练分布；无状态MLP不需要。

## 7. 优点

### 方法创新
- **神经符号融合**：不是简单将LLM作为PDDL生成器，而是将LLM嵌入带形式化验证的进化循环，使LLM成为“候选人发生器”而非权威来源。
- **单类到监督学习**：通过程序化+LLM反事实生成，将无标注单类演示转化为分类问题，简洁有效。
- **全局STL约束**：不绑定于特定动作，适用于所有移动动作，可同时编码规则和偏好，与规划器解耦。
- **已验证前缀单调增长**：规划器无需显式冻结前缀，通过验证器反馈自然实现前缀增长，使LLM聚焦于未验证部分的修复。

### 实验设计
- **对比全面**：涵盖纯LLM、反思LLM、符号规划器、微调方法，基线强大。
- **词汇不对齐测试**：真实评估规划器鲁棒性（NL-PDDL在此场景下降3pp，EvoPlan保持）。
- **碰撞原因分解**：区分可避免接触与轨迹交叉，提供机制洞察。
- **端到端演示**：在Gazebo中展示完整流水线，验证从规划到执行闭环。

### 其他
- **本地可部署**：所有LLM调用使用Qwen3-32B等开源模型，无云端依赖，符合实际机器人需求。
- **代码和配置**：附录提供了详细算法伪代码、STL公式、屏蔽机制、实验配置，可复现性好。

## 8. 不足与局限

### 实验层面
- **模拟环境为主**：所有定量实验在模拟（CARLA、Habitat、TextWorld、Gazebo）中进行，真实机器人硬件验证缺失。论文自述“需要更广泛的硬件验证”。
- **Gazebo重复次数少**：每个任务仅运行1次，缺乏统计稳定性；人群密度消融虽有多种子，但未明确说明重复轮数。
- **单源约束挖掘**：仅使用了nuPlan和SCAND两个源数据集，未测试其他领域（如手术机器人、空中无人机等）的STL挖掘泛化性。
- **令牌成本高**：进化规划器令牌消耗约为NL-PDDL的1.9~69倍（取决于变体），虽给出解释但未与性能收益进行成本效益分析。

### 方法局限性
- **依赖演示质量**：STL约束挖掘效果取决于演示数据是否充分覆盖可接受行为边界。异常、噪声或偏斜数据可能导致过拟合或错误约束。
- **STL表达能力受限**：当前的STL语法主要是全局 $\Box$ 有界阈值，缺少复杂时序模式（如“当接近人行横道时减速”条件式）。论文承认“可表达性和可跟踪性”是局限。
- **感知不确定性**：在执行循环中，STL评估依赖于从感知堆栈获取的信号（人体检测、障碍物距离），感知错误会直接导致错误约束满足判断。论文未讨论感知鲁棒性。
- **LLM骨干敏感性**：不同LLM骨干（Qwen3-32B vs gpt-oss-120b）在Blocksworld Mystery上表现差异显著（74% vs 76.7%），表明进化规划器受限于LLM的推理能力。
- **复杂多人环境缩放性**：人群密度消融显示，超过约0.02人/m²时碰撞开始增加；更大密度下的行为未充分探讨。
- **全局约束不够精细**：单个全局STL约束适用于所有移动动作，但某些任务可能需要动作特定的约束（如搬运不同物体时速度限制不同）。论文将“每技能约束族”列为未来工作。

### 偏差风险
- **反事实负例生成依赖LLM暗示**：LLM作为违规生成器可能引入特定偏差（如生成不真实或过于简单的违规）。
- **策略先验权重调参**：α 在导航实验中需要针对每个策略调优（PointNav α=0.05 vs MLP α=0），未给出自动调参方法。
- **单次LLM谓词映射假设**：词汇不对齐时单次LLM调用生成映射，若映射错误可能导致整个规划失败，未讨论容错机制。
