## 摘要
在非结构化环境中构建持久化的具身智能体需要统一协调跨越网络（API、IoT）和物理（操作、导航）领域的异构工具，同时具备从长时间运行中不可避免的物理故障中自主恢复的能力。现有系统将这些视为分离的问题：基于VLM的规划器缺乏统一的网络-物理动作空间，智能体框架积累无边界上下文导致时间连贯性下降，而VLA策略执行开环操作而不检测自身故障。我们认为，持久自主性不需要一个单一模型，而需要一个层次化异步架构，明确分离规划、记忆和验证。为此，我们提出OmniAct，一个集成了多模态语义规划器（用于跨统一动作空间的技能路由）、自适应层次化记忆（具有事件边界驱动的压缩以实现次线性上下文增长）以及异步视觉抢占引擎（在物理执行期间闭合语义循环）的框架。在两个机器人平台协调四个物联网设备的40个真实世界长时域任务中，OmniAct在所有复杂度级别上实现了端到端成功率的持续提升，在超过10万累积交互令牌下保持近乎平坦的令牌消耗，并将中等规模的开源模型提升至专有级别性能。

## Abstract
Building persistent embodied agents in unstructured environments demands unified orchestration of heterogeneous tools spanning both cyber (APIs, IoT) and physical (manipulation, navigation) domains, coupled with autonomous recovery from physical failures that inevitably arise over extended operation. Existing systems treat these as separate problems: VLM-based planners lack a unified cyber-physical action space, agent frameworks accumulate unbounded context that degrades temporal coherence, and VLA policies execute open-loop without detecting their own failures. We argue that persistent autonomy requires not a monolithic model but a hierarchical asynchronous architecture with explicit separation of planning, memory, and verification. To this end, we present OmniAct, a framework integrating a multimodal semantic planner for skill routing across unified action spaces, an adaptive hierarchical memory with event-boundary-driven compression for sub-linear context growth, and an asynchronous visual preemption engine that closes the semantic loop during physical execution. Across 40 real-world long-horizon tasks on two robotic platforms coordinating four IoT devices, OmniAct achieves consistent improvements in end-to-end success across all complexity levels, maintains near-flat token consumption over under 100k+ accumulated interaction tokens, and elevates mid-scale open-weight models to proprietary-level performance.

## 1. 核心问题与整体含义（研究动机和背景）

现实世界中部署持久化具身智能体面临两大关键挑战：一是需要统一协调异构工具，跨越网络域（API、物联网设备）和物理域（机械臂操作、移动导航）；二是必须能够自主检测与恢复长时间运行中不可避免的物理故障（如抓取滑落、物体位置偏移）。现有系统存在三个根本局限：
- **动作空间割裂**：VLM（视觉语言模型）规划器将工具调用与物理控制视为分离的流水线，缺乏统一网络-物理动作空间；
- **上下文无限制增长**：智能体框架线性拼接交互历史，导致上下文迅速膨胀，丢失历史关键信息并引发语义冲突；
- **开环执行**：端到端VLA（视觉语言动作）策略无法自主检测执行失败，单个未检测错误会级联为不可逆故障。

作者认为，持久自主性不应依赖单一端到端模型，而需一种层次化异步架构，将规划、记忆和验证职责明确解耦为专门化、相互协作的模块。

## 2. 方法论：核心思想、关键技术细节

**OmniAct框架**由三个核心模块组成：

### （1）多模态语义规划器
- 接收多模态观测（语音、图像、状态），执行意图理解、任务分解与技能路由；
- 输出结构化JSON指令，支持单步内并行调度多个技能调用；
- 历史经验来自分层记忆，用于避免重复失败与遵循用户长期偏好。

### （2）闭环执行引擎与异步视觉抢占（Asynchronous Visual Preemption）
- 物理执行期间，异步视觉监视器周期性地采样当前帧并提交给VLM进行语义级进度评估；
- 若检测到异常（如物体仍在原位、抓取失败），立即中断VLA执行，将故障上下文打包回传给规划器进行重规划；
- 网络域命令通过确定性返回码验证，物理域命令通过视觉验证实现闭环；
- 发生失败时同时触发反射过程，将因果分析与纠正策略存入长期记忆。

### （3）自适应分层记忆
- **感觉记忆**：轻量FIFO队列，缓存最近视觉帧供控制策略和视觉监视器使用，独立于规划上下文。
- **情景记忆**：通过事件边界驱动压缩管理交互历史。检测到语义边界（如子任务完成、状态变化）时，将原始观测序列压缩为紧凑关键帧摘要，保留语义内容、状态转移和动作结果，丢弃过程冗余。上下文增长与不同语义事件数成正比，实现亚线性扩展。
- **反思记忆**：存储静态先验（工具模式、技能清单）和动态积累经验（失败根因与纠正策略）。后续规划时检索相关反思注入上下文，将孤立错误恢复转化为累积适应。

形式化问题定义：在统一网络-物理动作空间中，每个时间步接收多模态观测，基于记忆检索的历史轨迹和当前上下文，输出包含目标技能和技能特定参数的元组。

## 6. 主要结论与发现

1. **端到端成功率持续提升**：在所有复杂度级别上，OmniAct的E2E成功率显著优于基线，尤其是在L3复杂任务上（操作50.0%，导航54.2%），相比最好基线（SayCan操作43.8%，Code as Policy导航37.5%）有明显优势。
2. **亚线性上下文增长**：通过事件边界压缩，OmniAct的每次调用令牌消耗稳定在4k-8k范围内，而原始历史呈线性增长，在270轮后超过120k令牌。该特性实现了持久部署中推理成本与交互时长的解耦。
3. **跨模型泛化**：OmniAct能提升所有骨干模型的约束满足率，尤其对中规模开源模型（如Qwen3-VL-30B-A3B提升30个百分点至80%，达到Gemini-3.1-Pro的原始水平），表明结构化编排可弥补模型容量差距。
4. **失效恢复能力**：异步视觉抢占和反思记忆将单次失效从灾难性故障转化为可恢复的延迟，反映在子任务成功率的显著提升（L3操作Sub 80.5%，导航Sub 80.6% vs 基线最好60.9%/57.9%）。
5. **平台无关性**：在两种完全不同形态的机器人上取得一致改进，验证了框架核心组件（统一技能路由、分层记忆、视觉抢占）的抽象层次高于具体硬件。

## 7. 优点

- **架构设计清晰**：规划-记忆-验证的明确分离避免了单一模型的局限，模块间异步协作实现了持久化闭环。
- **实用化导向**：直面真实世界部署中的两大瓶颈（异构工具协调和物理故障恢复），解决方案工程落地性强。
- **记忆压缩机制创新**：事件边界驱动压缩优于固定间隔或逐轮压缩，完全利用物理交互的自然语义分割，同时保留时间戳和关键信息。
- **异步视觉抢占**：在控制频率之外引入VLM语义验证，不需要力传感器即可检测失败，且通过低频率采样控制推理开销。
- **广泛的实验验证**：涵盖双平台、三复杂度、多基础模型，消融和可扩展性实验充分支撑了方法有效性。
- **开源与可复现**：提供项目页面和代码仓库，便于社区复现和扩展。

## 8. 不足与局限

- **不对称适应能力**：高层规划器能利用反思记忆进行重规划，但无法改进冻结的下游VLA策略本身。当失败源于固有运动限制时，恢复受限于现有技能库。
- **视觉监控延迟窗口**：VLM推理频率远低于控制频率，在两次采样之间可能继续执行错误动作，在易碎物体或人机接近场景中存有残余安全风险。
- **实验范围有限**：虽然覆盖了两个平台，但环境局限于室内桌面和导航工作室，未在更复杂、更嘈杂的真实家庭或工厂场景中测试；任务套件规模为40个，虽有代表性但不足以覆盖所有任务变体。

- **对低容量模型效果有限**：当骨干模型（如Qwen3-VL-8B）能力不足时，无法可靠生成结构化输出，OmniAct的改进边际较小，存在应用下限。
