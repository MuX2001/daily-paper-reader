## 摘要
视觉-语言-动作模型和世界-动作模型在机器人领域已展现出令人印象深刻的能力，但泛化到未见任务仍然具有挑战性。最近，通用多模态智能体在零样本机器人任务求解方面显示出巨大潜力。然而，它们往往通过从零开始推理和探索物理世界而带来高昂的执行成本。为降低这些成本，我们提出 RoboSkill，一个通过“探索、执行、演化”循环连接技能获取与复用的框架。在该循环中，智能体进行探索以收集任务相关信息，在执行任务时适应反馈，并基于执行记录演化其技能库。随后，它复用这些技能来指导下一轮循环中的探索与执行，从而形成闭环。为提高循环效率，我们用触觉反馈补充视觉，以减少物理交互过程中的不确定性。我们进一步用可复用代码增强文本指导，以减少技能复用期间的推理开销。在 LIBERO-10 上，RoboSkill 将四个智能体的首回合成功率提高 12.5--25.0 个百分点，并将平均运行时间缩短 7.6--72.4%。在真实机器人上，它将成功率提高 8.3 个百分点，并将成功试验的平均运行时间至少缩短 14.4%。

## Abstract
Vision-language-action and world-action models have demonstrated impressive capabilities in robotics, yet generalization to unseen tasks remains challenging. More recently, general-purpose multimodal agents have shown great potential for zero-shot robotic task solving. However, they often incur high execution costs by reasoning and exploring the physical world from scratch. To reduce these costs, we introduce RoboSkill, a framework that connects skill acquisition and reuse through an Explore, Execute, Evolve loop. Within this loop, the agent explores to gather task-relevant information, executes tasks while adapting to feedback, and evolves its skill library based on execution records. It then reuses these skills to guide exploration and execution in the next cycle, closing the loop. To improve loop efficiency, we complement vision with tactile feedback to reduce uncertainty during physical interaction. We further augment textual guidance with reusable code to reduce reasoning overhead during skill reuse. On LIBERO-10, RoboSkill improves first-episode success rates by 12.5--25.0 percentage points and reduces average runtime by 7.6--72.4% across four agents. On real robots, it improves success rates by 8.3 percentage points and reduces average runtime for successful trials by at least 14.4%.

## 1. 核心问题与研究动机

- **背景**：视觉-语言-动作模型（VLA）与世界-动作模型（WAM）虽能快速执行任务，但其能力主要由训练数据与任务塑造，**泛化到未见任务仍是瓶颈**。
- **新机会**：通用多模态智能体（general-purpose multimodal agents）展现出跨多样机器人任务的**零样本求解潜力**，但代价高昂——每次执行几乎"从零开始"，需要反复感知、物理试错、失败恢复。
- **核心痛点**：软件环境（Web、GUI、编程智能体）可把交互历史蒸馏为可复用技能，但具身场景不同：观测是部分可观测的、场景动态变化、受本体约束，且**执行命令不等于产生预期物理效果**，因此技能复用不能只是"回放固定计划"，还需补全信息、验证物理结果、偏离计划时恢复。
- **整体含义**：论文提出把"技能获取"与"技能复用"用 **Explore–Execute–Evolve（探索—执行—演化）闭环**连接起来，让物理交互的成果沉淀为可迁移、可共享的技能，从而降低通用智能体在机器人任务上的执行成本。

## 2. 方法论

### 2.1 核心思想
- 智能体接收任务指令、被选中的技能包，并通过 SDK 访问环境；在信息不足时先解"探索子任务"，再用所得知识+技能生成并运行代码执行主任务，最后在退出时复盘会话记录，构建/更新技能，技能又反过来指导下一轮探索与执行，形成闭环。

### 2.2 关键设计选择（两个）
- **触觉反馈**：广义包含压力与力/力矩信号，与 RGB、深度互补，提供直接的接触/碰撞证据，缓解图像难以判断的物理不确定性。
- **技能内嵌可复用代码**：文本描述策略与适用条件，代码保留可被智能体适配到相关场景与任务的操作过程，减少技能复用时的推理开销。

### 2.3 流程细节
- **探索（Exploration，可选）**
  - 把"获取缺失信息"本身当作一个子任务，围绕与主任务相同的流程组织；求解过程可包含多轮执行—反馈循环，每轮决定下一步查什么。
  - 示例：移动奶油奶酪时抓取失败 → 演化识别出"桌面高度未解决" → 用 RGB-D 估计 → 深度不确定 → 下降到接触，测得高度约 0.446 m → 指导下一次抓取。
  - 探索所得作为"当前任务知识"保留在会话上下文中；若智能体退出，则由 harness 调用该智能体**自身作为 reviewer**，把会话记录与已执行代码整合成技能包。
- **闭环执行（Closed-loop Execution）**
  - 上下文包含：任务指令、机器人控制与传感 API 规范、探索知识、被选中的技能包。
  - 观测：RGB（场景状态与进度）、深度（空间估计）、触觉（接触证据），均通过 API 调用获取。
  - 交互方式：提供 **SDK 而非固定工具**，以便智能体自行组合出可复用程序（如 `depth_pointcloud.py`、`verify_table_height.py`）；全过程记录交互与代码，作为演化的输入。
- **演化（Evolution）**
  - 时机：理论上每个子任务完成即应总结，但逐子任务复盘开销大；实际做法是任务进行中保留记录，**任务结束/智能体退出时做一次统一复盘**。
  - 技能结构 = **文本指导**（策略、适用条件、失败教训）+ **可复用代码**（分层组织的程序）+ **支撑记录**（失败案例、完整轨迹、元数据；元数据含简短描述与视觉关键帧，便于检索时判断相关性）。
  - 若已有对应技能则补充更新，否则新建技能包。
- **技能使用**：智能体查看技能元数据，选择最多 **K 个**相关技能包（实验中 **K = 3**），放入新任务智能体的工作区；对比发现智能体自主选择优于规则式选择（多数模型首回合成功率提升，见 Table 16）。

## 3. 实验设计

- **仿真 benchmark**：**LIBERO-10** 的 10 个任务。
  - 主对比使用每任务 4 个评估种子（排除技能构建种子），每条件 40 个 task–seed 单元；跨任务/跨智能体迁移使用全部 5 个种子（0–4），每条件 50 单元；技能迭代实验另用种子 100–104，且所有条件（含 Baseline）重跑。
  - 每个单元 4 小时预算，可含多个 episode（首次尝试为 Episode 1，每次 `reset` 开始新 episode）；成功、智能体自行退出或超时即结束。
- **真机场景**：5 个并行工位，各含 Piper 机械臂（仅用右臂）、双指触觉传感器、腕部相机、外部俯视相机。
  - 12 个任务（6 简单 + 6 困难），如按按钮、提纸袋、开抽屉、取试管、袜子分拣、移鸭子与盘子；困难任务含叠毛巾、叠储物箱、从针眼抽线、用砝码倾斜天平、叠纸杯、装电池。
  - 每任务 10 次试验（Astra）/ 简单任务 5 次试验（Sol），每次试验 1 episode、1 小时预算，由现场志愿者人工判定成功。
- **对比条件**：
  - **Baseline**：不使用任何已保存技能。
  - **RoboSkill−**：只使用 1 个同任务技能（文本+代码）。
  - **RoboSkill**：从成功探索中选最多 3 个技能。
  - **Other-Task Skill**：只给一个来自配对源任务的技能（无目标任务技能），用于跨任务迁移。

- **评估智能体**：仿真用 GPT-6 Astra、GPT-5.6 Sol、Fable 5.1、Opus 5；真机用 Astra 与 Sol；跨智能体迁移的接收方为 **Kimi K3**。所有智能体使用高推理/思考设置，通过统一的薄 CLI 适配器共享工具。

## 6. 主要结论与发现

- **主效果**：仿真中 Final SR 从 82.5%→97.5%（Sol）、97.5%→100%（Fable），Astra 与 Opus 维持 100%；四个智能体首回合成功率均提升；Opus 的 SR@30m 从 17.5%→82.5%、平均耗时 80.9→22.3 分钟；Sol 平均 episode 数 9.2→2.9。
- **真机**：简单任务 91.7%→100%、困难任务 80.0%→88.3%；成功试验平均耗时分别 20.3→16.6 与 27.0→23.1 分钟。
- **多技能优于单技能**：RoboSkill 相比 RoboSkill−，Astra/Fable/Opus 首回合成功率提升 5.0/7.5/12.5 个百分点，Fable 与 Opus 耗时下降；但 Sol 首回合成功率反而从 67.5% 降到 52.5%（可靠性 vs 速度存在智能体相关的权衡）。
- **跨任务迁移可行**：只给源任务技能时，Sol 首回合 30%→44%、耗时 86.0→66.3 分钟；Opus 耗时 77.0→43.5 分钟（首回合略降）。
- **跨智能体迁移可行且收益显著**：四个源智能体技能均使 Kimi K3 大幅提升（首回合 12%→42–66%，耗时 180.8→52.4–101.2 分钟）；**首回合成功率最高的来源（Fable）与耗时最短的来源（Opus）并不相同**。真机上 Astra→Sol 使成功率 13.3%→70.0%。
- **技能演化可继续增益但非单调**：Sol 第 2 次更新最佳（首回合 58%→70%，耗时 47.1→30.2 分钟）；Opus 第 1 次更新最佳（78%→82%），第 2 次更新反而使 SR@30m 降至 74%、耗时升至 25.3 分钟。真机困难任务更新后成功率 88.3%→93.3%，但成功耗时略升。
- **消融**：加入可执行代码普遍提升效率（Sol 首回合 15.0%→67.5%，耗时 67.1→39.9 分钟）；触觉输入在仿真中把平均耗时 25.4→15.9 分钟（首回合略降 82%→78%），真机"取出试管"任务成功率 80%→90%、耗时 33.6→20.0 分钟。

## 7. 优点

- **问题切分清晰**：明确指出具身技能复用与软件技能复用的本质差异（部分观测、动态场景、本体约束、结果不确定），并据此设计"复用≠回放"的机制。
- **闭环设计完整**：探索、执行、演化三阶段互相供给信息，且把"探索"显式建模为可嵌套的子任务循环，工程可落地性强。
- **两个设计选择有针对性**：触觉补视觉降低物理不确定性；文本+代码双通道技能兼顾"何时适用"与"如何执行"，减少重复推理。
- **SDK 而非固定工具**：鼓励智能体生成可复用程序（如深度转点云、接触式高度验证），使经验以可执行形式沉淀。
- **技能包结构工程化**：文本指导、分层代码、失败案例、完整轨迹、含视觉关键帧的元数据，便于检索与适配。
- **实验矩阵较全面**：仿真+真机、跨任务+跨智能体、迭代更新+消融+选择策略分析，且多智能体交叉验证（含以 Kimi K3 作为迁移接收方）。
- **对自身结论的诚实披露**：论文主动指出 Avg. Time 口径问题、技能数量与相关性混淆、选择比较未追踪实际使用内容等局限，学术态度可取。

## 8. 不足与局限

- **算力与成本完全未披露**：无 GPU/训练信息尚可理解（方法不训练模型），但**推理调用成本、token 预算、API 开销**同样缺失，难以评估实际部署经济性。
- **性能提升非单调、存在反例**：
  - 跨任务迁移下 Sol 首回合成功率下降；Opus 第 2 次技能更新指标退化；真机"从针眼抽线"任务从 7/10 降到 5/10。
  - 触觉输入在仿真中使首回合成功率略降（82%→78%）。
  - 说明"更多技能/更多更新/更多传感"并不总是更好，缺少对何时退化的机制性解释。
- **归因不够干净**：技能数量与技能内容同时变化；未追踪被选技能中哪些文本/代码被实际调用及其单独贡献；缺少技能库规模、检索质量（如错误技能被选中）的系统研究。
- **评估口径不一致**：仿真 Avg. Time 含失败单元，真机仅含成功试验，两者不可直接比较；SR@30m 等指标对时间预算敏感。
- **真机证据偏弱**：每任务 5–10 次试验，成功由现场志愿者判定

成功率判定、无盲法、无重复测量，缺少统计显著性检验与置信区间，跨真机任务结论的稳健性有限。

- **仿真 benchmark 单一**：仅使用 **LIBERO-10** 的 10 个任务，缺少在更复杂长程操作基准（如多物体、多阶段、可变形物体、多臂协作）上的验证，结论的泛化边界不清。
- **缺少与替代方案的横向对比**：未与"技能库/记忆式"的其它技能复用范式（如显式检索记忆、程序库合成、示范回放）或"直接微调/适配"路线对比，难以判断 RoboSkill 相对现有方案的真实增量。
- **技能库的长期行为未研究**：技能库随任务增长后的**检索精度、冲突/冗余、错误技能污染**、以及规模效应（K 增大是否持续有益）均未系统考察。
- **探索阶段的开销未量化**：论文强调"探索子任务"能补全信息，但未报告探索本身消耗的时间/调用预算占比，也没有"有探索 vs 无探索"的对照，因此无法判断探索的净收益。
- **缺少失败模式分析**：没有对失败 episode 做分类归因（是感知错误、抓取失败、恢复失败还是技能误用），限制了机制的诊断与改进方向。
- **可复现性受限**：依赖闭源商用模型与统一薄 CLI 适配器，提示词、推理参数、技能包完整内容未公开，第三方难以严格复现。

## 9. 对领域的启示与可延展方向

- **范式层面**：论文把"具身技能复用"从"回放固定计划"重新定义为**信息补全 + 物理验证 + 偏离恢复**的三重职责，这一界定对后续具身记忆/技能研究具有概念价值。
- **表示层面**：**文本指导 + 可执行代码**的双通道技能包，为"何时用"与"怎么用"解耦提供了可操作的工程模板；可进一步探索技能的组合、参数化与层次化复用。
- **感知层面**：触觉作为"接触证据"补足视觉在物理不确定性上的盲区，提示多模态感知应围绕**任务所需的物理量**而非模态数量来设计。
- **迁移层面**：跨智能体迁移的成功（技能在模型间可共享）暗示技能包可能成为**模型无关的中间资产**，具备"技能市场/共享库"的潜在价值。
- **待探索方向**：探索开销的显式建模与预算分配、技能退化的机制性解释（何时"更多反而更差"）、技能检索的可靠性、以及成本/时延的经济性分析。

## 10. 总体评价

- **定位**：RoboSkill 是一篇**系统与框架导向**的工作，核心贡献不在新模型或新算法，而在于把"探索—执行—演化"闭环与"文本+代码"技能表示落地为一套可运行的智能体框架，并用仿真+真机、跨任务+跨智能体的较广实验矩阵验证其有效性。
- **最强证据**：仿真上 Final SR 提升至近饱和（最高 100%）、首回合成功率普遍上升、耗时显著下降（如 Opus 80.9→22.3 分钟）；跨智能体迁移使 Kimi K3 首回合 12%→42–66%、耗时 180.8→52.4 分钟，是最具说服力的结论之一。
- **最弱环节**：算力/成本与提示词等关键复现信息缺失；技能数量与内容混淆导致归因不干净；真机样本量小、人工判定、无显著性检验；部分结果非单调（存在退化反例）且缺乏机制解释。
- **适用建议**：适合作为**具身技能复用框架的参考设计与实验模板**，其"技能=文本+代码+记录"的结构与"探索即子任务"的思路可直接借鉴；但若要把其量化结论当作定论，需补做归因干净、统计严谨、覆盖更复杂基准的验证。
- **一句话总结**：RoboSkill 用"探索—执行—演化"闭环把物理交互沉淀为可迁移、可跨模型共享的技能包，在仿真与真机上取得了显著但非单调的收益，是一份工程完整、诚实披露局限、但复现性与归因严谨性仍待加强的框架型研究。
