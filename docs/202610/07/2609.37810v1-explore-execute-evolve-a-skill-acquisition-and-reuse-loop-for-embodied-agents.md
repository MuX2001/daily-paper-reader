## 摘要
视觉-语言-动作模型与世界-动作模型在机器人领域已展现出令人印象深刻的能力，但泛化到未见任务仍然具有挑战性。最近，通用多模态智能体在零样本机器人任务求解方面展现出巨大潜力。然而，它们往往需要从零开始推理和探索物理世界，从而导致高昂的执行成本。为降低这些成本，我们提出了 RoboSkill，一个通过“探索、执行、进化”闭环将技能获取与技能复用连接起来的框架。在该闭环中，智能体通过探索收集任务相关信息，在执行任务时适应反馈，并根据执行记录进化其技能库。随后，它复用这些技能来指导下一轮循环中的探索与执行，从而闭合整个循环。为提高闭环效率，我们利用触觉反馈补充视觉，以减少物理交互过程中的不确定性。我们进一步用可复用代码增强文本指导，以减少技能复用过程中的推理开销。在 LIBERO-10 上，RoboSkill 在四种智能体上将首回合成功率提高了 12.5--25.0 个百分点，并将平均运行时间降低了 7.6--72.4%。在真实机器人上，它将成功率提高了 8.3 个百分点，并将成功试验的平均运行时间至少降低了 14.4%。

## Abstract
Vision-language-action and world-action models have demonstrated impressive capabilities in robotics, yet generalization to unseen tasks remains challenging. More recently, general-purpose multimodal agents have shown great potential for zero-shot robotic task solving. However, they often incur high execution costs by reasoning and exploring the physical world from scratch. To reduce these costs, we introduce RoboSkill, a framework that connects skill acquisition and reuse through an Explore, Execute, Evolve loop. Within this loop, the agent explores to gather task-relevant information, executes tasks while adapting to feedback, and evolves its skill library based on execution records. It then reuses these skills to guide exploration and execution in the next cycle, closing the loop. To improve loop efficiency, we complement vision with tactile feedback to reduce uncertainty during physical interaction. We further augment textual guidance with reusable code to reduce reasoning overhead during skill reuse. On LIBERO-10, RoboSkill improves first-episode success rates by 12.5--25.0 percentage points and reduces average runtime by 7.6--72.4% across four agents. On real robots, it improves success rates by 8.3 percentage points and reduces average runtime for successful trials by at least 14.4%.

# RoboSkill 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：视觉-语言-动作模型（VLA）与世界-动作模型（WAM）虽在机器人执行速度上表现出色，但受训练数据限制，对未见任务的泛化能力有限。近年来通用多模态智能体（如具备强推理能力的 LLM 智能体）展现出零样本求解机器人任务的潜力。
- **核心问题**：通用智能体虽灵活，但每次执行几乎都"从零开始"——反复感知、试错、从失败中恢复，导致执行成本极高。软件环境（Web、GUI、编程智能体）已有将交互历史蒸馏为可复用技能的成功经验，但迁移到具身场景面临本质差异：
  - 物理交互依赖**部分可观测**、场景动态变化、受本体约束；
  - 执行结果**不确定**：发出指令不代表产生预期物理效果；
  - 因此技能复用不能是"固定计划回放"，智能体必须补全缺失信息、验证物理结果、偏离计划时能恢复。
- **整体含义**：论文提出 RoboSkill 框架，通过"**探索—执行—进化**"（Explore, Execute, Evolve）闭环，将技能获取与技能复用连接起来，让积累的技能反过来指导后续探索与执行，从而降低重复推理与物理试错成本。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想
- 构建一个**共享技能库**，使智能体在物理交互中产生可复用经验；技能在下一轮循环中同时指导"探索"和"执行"，执行结果又反过来更新技能，形成闭环。
- 两个关键设计选择应对复用难点：
  1. **触觉反馈**（压力、力/力矩信号）补充视觉，提供接触与碰撞的直接证据，降低交互不确定性；
  2. **可复用代码**补充文本指导：文本描述策略与适用条件，代码保存可迁移、可改编的操作流程，降低推理开销。

### 2.2 闭环三阶段流程

- **探索（Exploration，可选）**
  - 当执行缺少必要信息时，将"获取信息"本身视为一个探索子任务，其过程与主任务求解流程一致，可多轮执行—反馈迭代。
  - 示例：抓取奶酪失败后，进化阶段识别"桌面高度未知"这一未解决问题；智能体先用 RGB-D 估计，深度不确定时**下降至接触**，测得高度约 0.446 m，再指导后续抓取。
  - 探索发现作为"当前任务知识"保留在会话中；若智能体退出，则调用自身作为 reviewer，将记录与代码整合为技能包。

- **执行（Closed-loop Execution）**
  - 上下文包括：任务指令、机器人控制/感知 API 规范、探索知识、选中的技能包。
  - 观测：RGB + 深度 + 触觉（压力/力/力矩），通过 API 调用获取；触觉弥补图像难以判断的接触信息。
  - 交互方式：提供 **SDK 而非固定工具**，让智能体将 SDK 调用与数据处理组合成可执行程序（如 `depth_pointcloud.py` 转换点云、`verify_table_height.py` 接触验证高度），这些程序可被保留进技能包复用。
  - 全程记录交互与执行的代码，退出时作为进化输入。

- **进化（Evolution）**
  - 时机：原则上每个子任务完成即可总结，但逐子任务 review 开销大；实际做法是任务进行中保留记录，任务结束、智能体退出时做**一次统一 review**。
  - 技能组成：
    - **文本指导**：任务策略、适用条件、失败教训；
    - **可复用代码**：层次化组织的程序；
    - **支撑记录**：失败案例与纠正策略、完整执行轨迹、元数据（简短描述 + 视觉关键帧）。
  - 智能体充当自己的 reviewer，从会话记录与实际执行代码中提取整合；已有对应技能则补充更新，否则新建技能包。
  - 复用方式：新任务中智能体检视元数据，选择至多 **K=3** 个相关技能包放入工作区。实验显示，相比规则选择，智能体选择能提升多数模型的首试成功率（表 16）。

## 6. 主要结论与发现

- **主效果**：RoboSkill 在仿真与真实均提升成功率与效率。
  - 仿真：Sol 最终成功率 82.5%→97.5%，Fable 97.5%→100%，Astra 与 Opus 维持 100%；四者首回合成功率均提升（如 Astra 72.5%→97.5%，Opus 60.0%→80.0%）。
  - 效率：Opus 的 SR@30m 从 17.5% 提升到 82.5%，平均耗时从 80.9 降至 22.3 分钟；Sol 平均 episode 数从 9.2 降至 2.9。
  - 真实：Astra 简单任务 91.7%→100.0%，困难任务 80.0%→88.3%；成功试次平均耗时分别从 20.3→16.6 分钟、27.0→23.1 分钟。
- **跨任务迁移**：补充其他任务技能相比单一同任务技能，在 4 个智能体中的 3 个提升首回合成功率，3 个降低平均耗时；无同任务技能时，其他任务技能仍能带来时间收益（Sol 86.0→66.3 分钟；Opus 77.0→43.5 分钟），但首回合成功率改善依智能体而异。
- **跨智能体迁移**：Kimi K3 接收任一来源技能后，首回合成功率从 12.0% 升至 42.0–66.0%，平均耗时从 180.8 分钟降至 52.4–101.2 分钟；真实 Astra→Sol 成功率 13.3%→70.0%。**提供最高成功率的来源与提供最快执行的来源并不相同**。
- **技能进化**：连续更新可进一步改善表现但**非单调**——Sol 第二次更新最佳（1st SR 58%→70%，时间 47.1→30.2 分钟），Opus 第一次更新最佳，第二次反而 SR@30m 与耗时变差；真实困难任务第一次更新成功率 88.3%→93.3%，但成功耗时从 23.1 升至 26.2 分钟。
- **消融**：
  - 可执行代码整体有益，四者平均耗时均下降，三者首回合成功率提升或持平（Sol 最显著：15.0%→67.5%，67.1→39.9 分钟）。
  - 触觉输入显著降低仿真平均耗时（25.4→15.9 分钟），真实"取试管"任务成功率 80%→90%、耗时 33.6→20.0 分钟；但仿真首回合成功率略降（82%→78%）。
- **技能选择**：智能体自选 vs 规则 Top-K 各有胜负，不全面占优；四模型均将同任务技能列为第一项，平均选择数从规则的 2.6 降至 1.8–2.4。

## 7. 优点

- **问题定位清晰**：准确指出软件智能体技能复用与具身技能复用的本质差异（部分观测、结果不确定、需验证与恢复），并据此设计闭环而非简单计划回放。
- **框架完整闭环**：探索、执行、进化三者相互支撑，且探索本身被形式化为"带内部循环的子任务"，支持嵌套（如先验证桌面高度再恢复抓取）。
- **多模态与代码结合**：触觉补视觉、代码补文本，两个设计选择都有专门消融支撑，且解释合理（触觉提供接触证据、代码保留过程性知识）。
- **技能表征丰富**：技能包同时含文本、层次化代码、失败案例、完整轨迹与元数据，兼顾可迁移性与可检索性。
- **实验覆盖较广**：仿真 + 真实、跨任务 + 跨智能体、多智能体、连续进化、多组消融，且真实任务含 6 个接触密集的困难任务。
- **客观性意识**：论文主动指出 Avg. Time 受失败早退影响、技能数量与内容混淆、选择列表不等于实际使用等局限，态度较为诚实。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号/数量、训练或推理成本、API 调用量；虽为 agentic 框架，但多智能体、多轮交互的推理开销对可复现性与成本评估构成障碍。
- **智能体依赖性强**：效果高度依赖所接入的通用多模态智能体能力，且不同智能体间表现差异大（如 Sol 在部分指标上不如基线或出现退化），泛化性受限。
- **混淆因素未完全解耦**：
  - 跨任务对比中技能数量与技能内容同时变化；
  - 技能选择分析未分离"数量"与"相关性"的贡献；
  - 无法确认选中技能中哪些代码/文本被实际使用。
- **指标解释风险**：仿真 Avg. Time 在含失败的全体单元上平均，失败早退会人为降低耗时；跨任务与进化实验使用不同种子集，结果与主表不可直接比较。
- **进化收益非单调**：技能更新可能带来性能波动甚至下降（如 Opus 第二次更新、真实任务耗时上升），缺乏稳定的更新收敛保障机制。
- **探索的自动性与开销**：何时触发探索、何时结束探索仍依赖智能体自身判断；逐子任务 review 开销大，实际采用任务结束统一 review，可能错过中间阶段的技能固化时机。
- **真实实验规模有限**：真实场景仅在 Astra（12 任务）与 Sol（6 简单任务）上验证，困难任务样本较少（每任务 10 试次），跨智能体真实迁移仅覆盖简单任务；成功判定依赖人工志愿者，存在主观性。
- **应用限制**：需要带触觉传感器与 SDK 接口的机器人平台；技能库跨本体（embodiment）迁移未做深入验证；长期技能库膨胀、检索与冲突管理问题未讨论。
