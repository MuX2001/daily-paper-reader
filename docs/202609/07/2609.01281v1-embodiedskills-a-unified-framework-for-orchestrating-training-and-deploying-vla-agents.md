## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射到机器人动作，但长期任务需要的不仅仅是动作预测。智能体必须在物理状态演变过程中协调感知、规划、执行、进度验证和恢复。单个动作预测或模型生成的技能决策，本身并不能保证提议的操作在当前状态下有效，也不能保证其结果会得到验证。我们提出了EmbodiedSkills，一个统一的框架，将每个技能决策视为一个执行提议：运行时在执行前检查其前置条件，并在执行后验证结果。一个共享的可执行技能接口在单个智能体循环中连接了高层技能选择、有界低层VLA执行和动作后验证。由于此接口保持不变，低层VLA策略可以在不改变智能体循环的情况下被替换或调整。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督，并在有交互反馈时支持可选的在线适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化了EmbodiedSkills。任务适应的低层VLA策略在50个RoboTwin 2.0任务上实现了86.20%的平均成功率，在四个LIBERO套件上实现了97.40%的平均成功率。这些结果确立了EmbodiedSkills中使用的任务适应低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务适应执行方法实现了12.5%的平均成功率。该框架提供了一个可训练且可检查的智能体层，用于将这些策略转变为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长时程（long-horizon）机器人操作任务远不止"预测下一个动作"那么简单。一个完整的 VLA 智能体必须随着物理状态的变化，主动协调感知（perception）、任务规划（planning）、执行（execution）、进度验证（verification）与失败恢复（recovery）——这些能力共同构成了将 VLA 模型转化为可靠具身系统的"智能体层"（agentic layer）。
- **现有方法的局限**：
  - **端到端 VLA 策略**（如 π0、π0.5、OpenVLA 等）虽然具备统一的视觉-语言-动作学习接口，但中间任务决策往往被隐式压缩在模型中。一旦任务失败，很难判断问题出在物体定位、子目标选择、低层动作执行、进度验证还是恢复环节。
  - **基于 LLM 的机器人智能体**（如 SayCan、Inner Monologue 等）虽然显式地引入了中间推理与工具调用，但"显式决策"不等于"可执行决策"：候选技能可能与当前任务阶段不兼容、依赖过期的观测、缺少必要参数，或在执行后无法产生预期结果。在部分可观测、反馈延迟、接触丰富的场景下，仅靠提示（prompting）无法强制保证执行约束或验证物理结果。
- **核心洞察**：模型层面的决策与物理层面的执行之间存在一道鸿沟；要弥合这一鸿沟，必须在执行前检查提议操作的前置条件，在执行后验证其物理结果，并将这些证据反馈给后续决策与学习过程。
- **论文口号/方案定位**：提出 EmbodiedSkills——一个用于编排、训练和部署 VLA 智能体的统一框架。该框架不是要替代现有 VLA 策略，而是把策略包在一个"可执行技能"契约（executable skill contract）体系中，让高层智能体决策被当作"执行提议"（proposal），经由一套独立的运行时（runtime）做守卫（guard），从而实现闭环、可诊断、可训练的自主操作。

## 2. 论文提出的方法论

### 2.1 核心思想：技能决策 = 执行提议

- 框架将每一个技能决策视为**执行提议**（execution proposal），而不是实际状态变迁：
  - **执行前**：运行时（guarded runtime）检查其前置条件、相位兼容性、输入参数的合法性、动作数值有效性与状态转移的合法性。
  - **执行后**：验证器基于新获取的观测判断子目标是否真实推进。
  - **失败时**：被阻塞的决策与错误证据被显式记录到结构化轨迹中，供后续决策和学习使用。
- 这种**"策略提议 vs. 运行时执行"分离**的设计，是论文的核心方法论贡献。

### 2.2 系统整体架构

- 系统由以下核心模块组成：
  - **高层 VLM 智能体（High-level VLM Agent）**，例如 Qwen3-VL，负责任务分解、子目标选择、技能调度、进度验证的判断等符号决策。
  - **低层 VLA 策略（Low-level VLA Policy）**，例如 OpenPI/π0.5，将当前子目标、观测、机器人状态映射为有界（bounded）的动作块（action chunk）。
  - **受守卫的运行时（Guarded Runtime）**：负责前置条件校验、状态更新、证据失效（artifact invalidation）和合法转移判断。
  - **共享技能接口（Shared Skill Interface）**：连接高层选择、低层执行与事后验证的统一接口。
  - **机器人与环境适配器（Environment Adapter）**：将统一接口映射到具体仿真器或实体机器人。

### 2.3 状态表征与决策接口

- **方法级状态**：
  - \( s_t = (z_t, \mathcal{M}_t, \mathcal{H}_t) \)
  - 其中 \( z_t \) 为当前相位，\( \mathcal{M}_t \) 为可用任务工件（artifact）集合，\( \mathcal{H}_t \) 为有序循环轨迹。
- **策略上下文**：
  - \( C_t = \Psi(x, z_t, \mathcal{M}_t, \mathcal{H}_t) \)，仅保留完整计划、当前子目标、工件摘要、近期错误和有序的历史摘要；原始模拟器内部状态与无界日志不进入策略上下文。
- **决策空间**（三种控制类型共享一个接口）：
  - `RunSkill(k, q)`：执行某个可执行的技能及其负载；
  - `AdvanceStage`：推动循环相位前进；
  - `FinishRun`：终止整个回合。

### 2.4 可执行技能契约

- 每个技能被定义为五元组契约：
  - \( k = (X_k, Y_k, pre_k, exec_k, post_k, fail_k) \)，分别对应：输入模式、输出模式、前置条件、可执行操作、状态更新规则、失败映射。
- 工件（artifact）携带来源（provenance）与新鲜度（freshness）信息：当观测、活动子目标或执行结果改变时，**只失效依赖这些变化证据的工件**（而非全部清空），从而在避免陈旧预测授权新动作的同时最大化上下文复用。
- 该契约同时充当三种角色：**组合接口**（composition interface）、**运行时有效性边界**（runtime validity boundary）、**训练轨迹的结构化来源**（structured source of training traces）。

### 2.5 六相位技能空间

- 运行时使用有序相位集 \( Z = (Observe, Plan, Preflight, Execute, Verify, Recover) \)，具体功能：

| 相位 | 功能 | 代表操作 | 退出证据 |
|---|---|---|---|
| Observe | 获取当前视觉与任务相关证据 | 捕捉视图、任务条件视觉证据抽取、更新场景表征 | 当前任务证据 |
| Plan | 将任务转化为可验证子目标 | 构建有序语义计划、选择活动子目标、分配执行预算 | 计划和活动子目标 |
| Preflight | 判断子目标是否可执行 | 检查任务上下文、观测、机器人状态、VLA 策略可用性，必要时刷新证据 | 通过的准备度报告 |
| Execute | 生成并施加一个有界动作块 | 构建 VLA 策略请求、生成并验证动作块、在环境中执行 | 执行报告 |
| Verify | 基于新证据判断子目标是否取得进展 | 比较观测状态与活动子目标，选择下一语义路线 | 进度判断 |
| Recover | 在失败后修正执行 | 解读失败证据、修正子目标或计划、选择安全重入相位 | 修正后的执行上下文 |

- 需要注意：这六个相位**不是固定的一次性流水线**。策略可以随时回到之前的相位（如重新观察、重新规划），循环是状态条件化的。

### 2.6 守卫转移（Guarded Transition）

- **技能守卫**：
  \[
  G_{skill}(s_t, d_t) = \mathbb{1}[d_t=RunSkill(k,q)] \cdot \mathbb{1}[stage(d_t)=z_t] \cdot \mathbb{1}[k \in K_{z_t}] \cdot \prod_{r \in R(k,q)} \mathbb{1}[r(s_t)=1]
  \]
  保证技能与当前相位匹配、属于该相位的合法技能集合，且所有前置条件成立。
- **推进守卫**：
  \[
  G_{advance}(s_t,d_t) = \mathbb{1}[d_t=AdvanceStage] \cdot \mathbb{1}[\mathcal{R}_{z_t}(s_t)=1]
  \]
  保证当前相位确实产生了后继所需证据。
- **终止守卫**：\( G_{finish}(d_t) = \mathbb{1}[d_t=FinishRun] \)。
- **状态更新**：
  \[
  s_{t+1} = \begin{cases}
  U(s_t, k(q)) & G_{skill}=1 \\
  N(s_t) & G_{advance}=1 \\
  F(s_t) & G_{finish}=1 \\
  B(s_t, d_t) & \text{otherwise}
  \end{cases}
  \]
  其中 U 记录操作结果并使陈旧依赖失效，N 推进循环，F 终止回合，B 记录被阻塞的决策及其证据。

### 2.7 有界动作执行

- Execute 相位的映射：\( (g_t, O_t, F_t) \rightarrow a_t \rightarrow e_t \)，即活动子目标、观测、准备度证据映射为动作块，再得到观测到的执行结果。
- 动作块定义为 \( a_t = (τ_t, U_t, H_t, η_t) \)，其中 \( U_t=[u^1_t,...,u^{H_t}_t] \) 为动作序列，\( H_t \) 为水平（horizon），\( η_t \) 将动作块绑定到特定子目标与观测。
- 运行时仅接受满足以下条件的动作块：
  \[
  R_{act}(a_t, s_t) = \mathbb{1}[0<H_t≤H_{max}] \cdot \mathbb{1}[a_t \models Σ_p] \cdot \mathbb{1}[fresh(a_t;g_t,O_t)] \cdot \mathbb{1}[valid(U_t)]
  \]
  一个语义子目标可能需要多个动作块：每个动作块执行后，循环会获取新证据，再决定是继续当前子目标还是推进。

### 2.8 验证与恢复

- Verify 阶段基于最新证据预测语义路由 \( V = \{Advance, Continue, Reobserve, Replan, Recover, Finish\} \)。
- 恢复阶段使用同一显式任务状态与失败证据产生修正后的执行上下文，再次经运行时检查后才能执行物理动作。
- 全局任务成功始终由环境的评估协议决定，而非局部子目标判断。

### 2.9 训练机制

- **组件级监督适应**（主要训练方式）：
  - **规划器**：学习把任务指令与当前视觉上下文映射为有序可执行语义子目标。
  - **低层 VLA 策略**：通过子任务级演示独立适应（成对出现观测/机器人状态 → 活动子目标 → 对应动作序列）。
  - **高层调度器**：在低层 VLA 冻结的情况下，用部署一致的决策轨迹监督 Qwen3-VL。冻结低层策略，可隔离 SFT 阶段与连续控制学习，只改善状态条件化调度技能，不改变低层动作生成。
  - **验证器**：可用执行后观测与子目标完成标签独立适应。
- **部署一致样本**：训练样本与部署时的输入边界严格一致，并应用相同的历史压缩规则；损失只施加在组件生成的 token 上，环境消息与工具结果作为上下文而非预测目标。
- **可选在线闭环适应**：完整 AgentLoop 可收集交互轨迹 \( τ=(x_1,y_1,...,x_T,y_T,e_{1:T},R) \)，在可靠环境评估器存在时用 GRPO 风格（group-relative policy optimization）优化；文章中明确表示在线优化是可选精炼手段，**不是实验头条结果的主要来源**。

## 3. 实验设计

### 3.1 基准与数据集

论文在三个基准上评测：

1. **RoboTwin 2.0**：双机械臂操作仿真基准，含 50 个操作任务（如 Adjust Bottle、Hanging Mug、Stack Blocks、Turn Switch 等），每个任务 100 个 episode，共 5,000 个轨迹用于消融评估。
2. **LIBERO**：四个套件——Spatial（空间泛化）、Object（物体泛化）、Goal（目标泛化）、Long（长时程任务）——衡量不同维度的泛化能力。
3. **RMBench 的 M(n) 记忆依赖任务**（4 个任务：Battery Try、Blocks Ranking Try、Cover Blocks、Press Button）：用于评估"正确动作依赖先前交互历史"的执行场景。

### 3.2 对比方法

- **RoboTwin 2.0**：对比了两类方法：
  - 策略基线：ACT、DP（Diffusion Policy）、RDT、DP3；
  - 通用 VLA 基线：π0、X-VLA、π0.5（参考结果来自 LingBot-VA 报告的数据）。
  - 本文方法：每个任务单独微调一个 π0.5 策略（subtask-level demonstrations）。
- **LIBERO**：与官方 OpenPI 的 π0.5 参考结果对比。
- **RMBench**：对比 DP、ACT、π0.5、X-VLA 的公开 RMBench 结果。

### 3.3 AgentLoop 消融实验设计

在 50 个 RoboTwin 2.0 任务上（每任务 100 episode，共 5,000 个 episode）进行了三组受控消融，所有配置共用相同规划器、低层策略、初始状态与终止评估器，只改变循环机制的可见性：

1. **Full**：完整的"规划-执行-验证"循环（对应主结果 86.20%）。
2. **w/o Verify**：保留参考子目标序列与总动作预算，但无中间结果核查（48.2%）。
3. **w/o Subtask**：保留总预算，但每个动作块只接收完整的原任务指令（34.4%）。
4. **One chunk/subtask**：保留子目标序列，但给每个子目标只分配一个 32 步动作块，不进行任何中间重试（19.5%）。

## 5. 实验数量与充分性

### 5.1 实验数量

- **RoboTwin 2.0**：完整的 50 任务 × 100 episodes 主评测；另含 50 × 100 episodes 的四组消融实验，合计至少 25,000 个测试 episode 级别的评测量。
- **LIBERO**：四套件全部评测（官方协议）。

### 5.2 充分性评估

**充分与客观之处**：
- RoboTwin 2.0 任务覆盖面广（50 个任务，包含接触敏感、多阶段操作、双臂协同等）；
- 消融实验设计与结论非常清晰：逐步移出"验证"、"子目标语义"和"多块重试"后成功率显著衰减（86.20% → 48.2% → 34.4% → 19.5%），有力支撑了核心设计主张；
- LIBERO 对比使用了官方开源报告的参考值，RoboTwin 2.0 对比使用了已发表的 LingBot-VA 报告值，来源透明。
- 三个实验平台（RoboTwin 2.0、LIBERO、RMBench）覆盖了"通用操作 + 空间/物体/目标/长时程泛化 + 记忆依赖"等多个维度，具有较好的外部效度。

**不足与偏差风险**：
- **依赖他人报告的基线数字**：RoboTwin 2.0 的 π0.5 对比基准来自 LingBot-VA 论文报告，未在同一代码库、同一硬件条件下复测，可能引入环境版本、随机种子、domain randomization 差异造成的不公平性。
- **RoboTwin 2.0 上"任务单独微调"的对比对 π0.5 并不完全公平**：π0.5 是通用策略（同一策略处理多任务），而本文每个任务单独微调一个专用策略，比较优势的归因需要谨慎。论文在 Limitations 中部分承认了这一点。
- **缺少跨任务泛化评测**：没有展示一个通用策略在 50 个任务上的表现（只有 50 个任务特化策略）。
- **未量化验证模块自身的错误率**：验证器判断错误会如何影响循环成功率，未被系统评测。
- **RMBench 仅 4 个任务且成功率低（12.5%）**：作者将其

其归因于低层策略在准确记忆依赖动作上的不足，而非高层验证机制失效，但这一归因缺少直接的可视化或反事实实验支撑。

## 6. 主要实验结果与关键发现

### 6.1 闭环调度是性能提升的核心来源
- 消融实验清晰展示：当依次移除“验证”和“子目标语义”后，成功率从 86.20% 分别降至 48.2% 与 34.4%，说明二者共同构成了性能的主干。
- 更关键的是，即使保留子目标序列但将每个子目标压缩为单个 32 步动作块（无中间重试），成功率进一步暴跌至 19.5%。这说明**长时程任务的成功强烈依赖“执行—验证—再执行”的迭代闭环**，而非单纯依赖低层策略的单次动作质量。
- 该结果也反驳了“更强的端到端 VLA 足以解决长时程任务”的观点：在相同低层策略下，仅仅改变外层调度机制就能带来数倍的性能差异。

### 6.2 框架提升幅度与基线水平相关
- 在 LIBERO 这类已有高基线的任务上，EmbodiedSkills 带来的提升相对温和（+0.2~+1.2 个百分点），但仍保持领先。
- 在 RoboTwin 2.0 这类长时程、多阶段占主导的任务上，提升更为显著（+3.46 个百分点），表明循环调度收益随任务时程与阶段复杂度的增长而放大。
- 在 RMBench 记忆依赖任务上，尽管绝对成功率仍较低（12.5%），但相对当前基线实现了成倍提升，显示框架的调度与验证机制在一定程度上缓解了对交互历史的遗忘问题，但并未根治。

### 6.3 验证与恢复的实际行为模式
- 论文定性展示的成功轨迹中，验证器在物体错位、抓取落空等情况下触发了 Continue/Reobserve/Recover 等循环，说明验证器并非简单对照“模板答案”，而是在新证据基础上判断物理进展。
- 失败恢复不是盲目重试同样的策略，而是先回到 Observe/Plan 等前置相位刷新上下文，再重新进入执行，符合“守卫转移”的设计预期。

## 7. 论文局限性分析

### 7.1 方法论层面的局限
- **高层 VLM 仍是瓶颈**：规划、调度、验证全部依赖单一 Qwen3-VL 进行符号决策，该模型的幻觉、上下文遗忘或对失败证据的误读会直接传导至整个循环；论文未能给出验证器与规划器错误的独立度量。
- **技能库的封闭性**：技能集合需要预先用自然语言定义并映射到低层策略的请求格式，新技能或新任务需要人工撰写契约描述，不支持技能的自动发现或学习。
- **“守卫”本身依赖语义判断**：前置条件和状态更新规则虽然形式上做了结构化，但其真值来源仍可能是 VLM 生成的证据，因此“受守卫的转移”并不能像形式化方法那样提供硬保证。

### 7.2 实验层面的局限
- **训练/推理成本缺失**：没有报告微调低层策略所需演示条数、高层调度器 SFT 数据规模、训练 GPU 时数或推理时单次决策的 token 开销。
- **未进行真实机器人评测**：所有主实验均在仿真环境中完成，接触动力学、视觉噪声与执行器漂移等真实世界难点未被触及。论文虽提到框架可用于真实机器人，但没有提供物理平台上的验证案例。
- **对比基线未在同一管线中重训**：RoboTwin 2.0 的 π0.5 基线数字直接引用自 LingBot-VA 报告，LIBERO 对比直接引用 OpenPI 报告，未控制低层策略的微调数据与超参一致性。
- **每个任务单独微调 vs. 通用策略的不对称**：对任意新任务，EmbodiedSkills 的做法是额外微调一个专用 π0.5 策略；而基线 π0.5 是跨任务通用模型。这种不对称会高估框架在实际部署中面对新任务时的成本效益。

## 8. 可复现性评估

- **有利因素**：RoboTwin 2.0、LIBERO、RMBench 均为公开基准；低层策略 π0.5 与 OpenPI 开源可获取；高层组件 Qwen3-VL 公开可下载；机器人平台 Rosmo 有公开资料支持。论文对循环机制（工件失效规则、压缩策略、守卫公式）的数学描述较为精确，具备一定的复现基础。
- **不利因素**：缺少完整配置文件、Prompt/API 调用模板的全文、超参数设置表、动作块长度分布、各任务微调演示数量、数据生成代码与训练指令细节。论文没有提供代码仓库链接（从文本推断），这使复现需要大量自行实现工作。
- **综合判断**：框架概念可复现，但精确数字复现难度较大，尤其是高层调度器 SFT 的决策轨迹数据构造细节不透明。

## 9. 总体评价与学术定位

EmbodiedSkills 的核心贡献在于提出并验证了一个清晰的论点：**VLA 模型的物理执行能力需要被一个具备前置条件检查、结果验证与状态跟踪能力的运行时环境所包裹，才能稳定地转化为长时程任务的闭环成功**。它没有试图在低层策略架构上做创新，而是提供了一个与策略无关的“智能体层”设计。这种方法论取向与近年来从“更大更强的单模型”转向“模型 + 工具 + 运行时”的系统级智能方向一致。

在实证层面，论文通过设计干净的消融实验，令人信服地证明了“子目标语义 + 验证 + 多块重试”三者缺一不可，且每移出一个组件成功率都显著下降，这比单纯刷新 SOTA 更具说服力。同时，框架在三个异构基准上的整体一致性表现（均不低于或优于已有报告）也支持其通用性。

在创新性上，论文的主要新意并非某个单一算法或模型，而是将软件工程中成熟的契约化接口设计（前置条件/后置条件/证据失效）系统性地引入 VLA 机器人操作编排中，并配套了相应的训练范式（组件级监督适应 + 部署一致样本）。这种跨领域设计思路值得肯定。

然而，论文的局限也同样明显：所有论证建立在仿真环境中，基线对比依赖他人报告数字，训练成本与数据细节缺失，真实世界泛化性与工程可用性未能得到证明。因此，其当前定位更像是一个“架构方案 + 仿真验证”的阶段性工作，而非最终解决长时程操作问题的成熟系统。

总体而言，EmbodiedSkills 在方法论层面提供了有价值的系统设计参考，在实证层面给出了有力的消融证据，但在真实机器人验证和公平对比两个方面仍存在明显短板，后续工作应在这些方向加以补强。
