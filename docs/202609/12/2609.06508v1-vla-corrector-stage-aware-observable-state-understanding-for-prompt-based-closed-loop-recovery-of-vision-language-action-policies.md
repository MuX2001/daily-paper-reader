## 摘要
使用视觉-语言-动作（VLA）策略进行长时程机器人操作仍然容易受到执行时偏差的影响，因为最终任务成功与否几乎无法提供用于诊断和纠正由动作噪声、物体位移或目标错位所导致失败的信息。我们提出了一种阶段感知的失败验证与提示恢复框架，无需参数更新或特权仿真器状态即可对固定的VLA策略进行闭环纠正。该框架引入了一种基于可观测历史的学习型验证器，通过对多视角视觉观测、本体感受状态和已执行动作进行时序建模，联合估计操作进度与执行风险。为了提供可解释的任务理解，我们通过语义进度阶段来表示操作执行过程，包括接近、对齐、抓取、运输和放置，并识别各阶段特有的失败模式。在检测到异常执行时，该框架保留原始指令并生成以阶段为条件的恢复提示，使同一个冻结的VLA策略能够产生纠正动作。在LIBERO和LIBERO Plus上进行的大量多轮评估表明，所提方法在多种扰动下显著提高了闭环可靠性。在无法访问特权物体或目标坐标的情况下，学习型验证器在评估设置中达到了接近特权规则验证器的恢复性能。这些结果表明，可观测的视觉-本体感受-动作历史足以推断潜在任务状态，并为现有VLA策略实现实际的失败恢复。

## Abstract
Long-horizon robot manipulation with Vision-Language-Action (VLA) policies remains vulnerable to execution-time deviations, as final task success provides little information for diagnosing and correcting failures caused by action noise, object displacement, or goal misalignment. We introduce a stage-aware failure verification and Prompt Recovery framework that enables closed-loop correction of a fixed VLA policy without parameter updates or privileged simulator states. The framework introduces an observable-history-based Learned Verifier that jointly estimates manipulation progress and execution risk by temporally modeling multi-view visual observations, proprioceptive states, and executed actions. To provide interpretable task understanding, we represent manipulation execution through semantic progress stages, including approach, alignment, grasp, transport, and placement, and identify stage-specific failure patterns. Upon detecting abnormal execution, the framework preserves the original instruction and generates a stage-conditioned recovery prompt, allowing the same frozen VLA policy to produce corrective actions. Extensive multi-round evaluations on LIBERO and LIBERO Plus demonstrate that the proposed approach substantially improves closed-loop reliability under diverse perturbations. Without access to privileged object or goal coordinates, the Learned Verifier achieves recovery performance close to that of the privileged rule-based verifier in the evaluated settings. These results show that observable visual-proprioceptive-action history is sufficient to infer latent task states and enable practical failure recovery for existing VLA policies.

- **背景**：Vision-Language-Action（VLA）策略（如 RT-1/RT-2、OpenVLA、π0、π0.5）通过多模态预训练与在线重规划，已能生成"指令合规"的动作序列，但**缺乏对自身执行保真度的校验能力**——即"知道该做什么，却不知道是否做对了"。
- **核心痛点**：
  - 真实长时程操作中的失败多源于**执行阶段的累积偏差**（动作噪声、物体位移、抓取不完美、目标区域漂移），而非任务理解错误。
  - 最终任务成败是**稀疏、滞后**的信号，几乎无法用于诊断"在哪一阶段出错、如何纠正"。
  - 动作分块（action chunking）与滚动时域执行带来重规划延迟，期间过期动作仍会持续执行，进一步放大偏差。
- **研究问题**：机器人能否**仅从可观测的交互历史**推断自身执行状态，并在**不修改策略参数、不访问特权环境状态**的前提下提升闭环可靠性？
- **整体含义**：论文将"执行状态理解"定位为当前 VLA 系统缺失的关键能力，主张**把策略能力（policy competence）与执行可靠性（execution reliability）解耦**——VLA 负责生成动作，轻量验证器负责监控与恢复。这为已部署的冻结 VLA 策略提供了一条**免微调、非侵入式**的闭环纠错路径。

## 2. 方法论

### 2.1 核心思想

- 在**冻结的 VLA 策略（OpenPI pi05_libero）之上**叠加一个轻量监控-恢复模块，不改参数、不加动作头、不直接修改轨迹。
- 用**可观测历史**（双视角 RGB + 本体状态 + 已执行动作）训练一个 **Learned Verifier**，联合预测：① 执行风险（二分类）；② 当前操作阶段（5 类路由）。
- 检测到异常时，**保留原始指令**，仅追加阶段条件化的**恢复提示（recovery prompt）**，让同一个冻结策略生成纠正动作，恢复完成后立即回到原指令。

### 2.2 问题形式化

- 观测：$o_t = (I_t^{a}, I_t^{w}, s_t)$，其中 $I^a, I^w$ 为 agent-view 与 wrist-view 图像，$s_t \in \mathbb{R}^8$ 为本体状态；$u_t \in \mathbb{R}^7$ 为实际执行动作。
- 可观测历史：$h_t = \{(I_i^a, I_i^w, s_i, u_i)\}_{i=0}^{t}$（严格时序，不使用未来信息）。
- 策略：$U_t = \pi_\theta(q, h_t)$，仅执行动作块前缀后重新规划；$\theta$ 全程冻结。
- 风险估计：$p_t = \Pr(f_t=1 \mid h_t)$，$\hat f_t = \mathbb{1}[p_t \ge \tau]$。
- 恢复提示：$q_t^{rec} = q \oplus r_t$（原始指令保留 + 阶段路由的恢复片段）。

### 2.3 系统流程

```
观测与指令 → π0.5 策略 → 动作块 → 风险验证器 → 触发门控
          → Prompt Recovery → 任务恢复
```

- 每控制周期策略输出动作块，仅执行固定长度前缀（`replan_steps=5`）后重规划；验证器随后消费可观测历史。
- 门控抑制则不干预；触发则**丢弃待执行动作块**，用恢复提示查询同一策略生成纠正动作，恢复动作（`recovery_replan_steps=3`）完成后恢复原任务。

### 2.4 特权规则验证器（仅作上界）

- 基于仿真真值维护状态机：`APPROACH → ALIGN → GRASP → MOVE → PLACE → SUCCESS`。
- 使用物体/区域位姿、末端运动学、距离、夹爪状态、运动谓词、任务标志等**特权信息**，输出结构化恢复记录 `(stage, context)`。
- **不可部署**，仅作为效果上界与教师标签来源。

### 2.5 Learned Verifier（可部署模块）

- **输入**：双视角 RGB（验证器图像 112×112）、8 维本体状态、7 维实际执行动作；构成 **8 步历史窗口**，每 2 个环境步采样一次。
- **视觉分支**：**无参数**空间统计特征器——3×4×4 自适应平均池化 RGB 表示 + RGB 均值/标准差，每视角 54 维特征；双视角拼接后投影到 64 维。
- **状态-动作分支**：15 维向量投影到 32 维。
- **时序融合**：GRU（隐层 64）整合序列。
- **双预测头**：
  - 风险头：$p_t = \sigma(w_f^\top z_t + b_f)$
  - 阶段头：$\hat c_t = \arg\max_c \text{Softmax}(W_{stage} z_t + b_{stage})_c$，类别 $C = \{$APPROACH, ALIGN, GRASP, MOVE, PLACE$\}$（终态 SUCCESS 由环境判定，不归阶段头管）。
- **推理开销**：p50 = 0.457 ms，p95 = 0.589 ms，可在 CPU 上在线运行。

### 2.6 教师监督与标签构造

- 教师**不提供特权坐标回归目标**，而是把特权任务进度转化为**操作性标签**。
- 二分类风险标签（$E$ 为教师定义的失败事件步集合）：
  - $f_t = 1$，若 $\min_{e \in E} |e - t| \le 10$；
  - $f_t = 0$，若 $\min_{e \in E} |e - t| > 20$；
  - **中间模糊区（10~20 步）窗口从二分类训练中剔除**，以对齐阶段语义与执行风险。
- 阶段头仅作**路由**用途，不被视为五类风险检测器。

### 2.7 在线触发门控与恢复路由

- 阈值 $\tau = 0.40$，**连续 4 帧确认**，**10 步冷却期**，每 2 个环境步查询一次验证器。
- 触发后由预测阶段 $r_t$ 路由到上下文相关提示（如 approach、grasp 专用片段）。
- 阶段置信度 $< 0.9625$ 时回退到**通用恢复提示**；低置信度默认标记为 `UNKNOWN_FAILURE`。
- 门控参数验证集选定后固定；离线检测器阈值（0.03294）与在线门控阈值不同。

### 2.8 Prompt Recovery

- 形式为 $q \oplus r_t$：在原指令后追加 `"Immediate recovery: "` 与阶段指令。
- 所有执行均由冻结的 π0.5 完成，恢复后恢复原指令 $q$。
- 该设计保证**验证器触发通路是唯一变量**，性能差异只反映检测时机、路由与干预质量。
