## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射到机器人动作，但长时程任务需要的不仅仅是动作预测。代理必须在物理状态演变时协调感知、规划、执行、进度验证和恢复。动作预测或模型生成的技能决策本身并不能保证提议的操作在当前状态下有效，也不能保证其结果会被验证。我们提出了EmbodiedSkills，一个将每个技能决策视为执行提议的统一框架：运行时在执行前检查其前提条件，并在执行后验证其结果。一个共享的可执行技能接口将高层技能选择、有界低层VLA执行和动作后验证连接在单个代理循环中。由于该接口保持固定，低层VLA策略可以在不改变代理循环的情况下被替换或调整。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各个组件提供监督，并在交互反馈可用时支持可选的在线适应。我们使用Qwen3-VL和OpenPI/pi0.5在RoboTwin 2.0和LIBERO上实例化了EmbodiedSkills。任务适应的低层VLA策略在50个RoboTwin 2.0任务中平均成功率达到86.20%，在四个LIBERO套件中平均成功率达到97.40%。这些结果确立了EmbodiedSkills中使用的任务适应低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务适应执行方法实现了12.5%的平均成功率。该框架提供了一个可训练和可检查的代理层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

# EmbodiedSkills 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长时程机器人操作任务远不止“预测下一个动作”。一个可靠的 VLA 代理必须协调**感知、规划、执行、进度验证与恢复**等多个环节；而传统 VLA 模型仅输出动作，无法保证所提出的操作在当前物理状态下有效，也无法验证执行结果是否真正达成预期。
- **关键矛盾**：动作预测或模型生成的技能决策本身，**不等于该操作在当前状态下可执行**，也不等于其结果可被验证。在部分可观测性、延迟反馈和接触丰富的失败场景下，这一问题尤为突出。
- **既有方案不足**：
  - 端到端 VLA 策略：中间任务决策隐式化，任务失败时难以定位根因（物体接地点、子目标选择、低层执行、验证还是恢复环节出问题）。
  - LLM-based 机器人代理：虽然使中间推理和工具调用显式化，但“显式决策”并不保证其在当前物理状态中的有效性——可能与当前阶段不兼容、依赖过期观察数据、缺少必要参数，或执行后未能产生预期结果。
- **整体含义**：需要从“模型级决策”跨越到“物理级执行”，构建一个**将决策提议与执行验证分离**的框架，使提议在动作执行前被审查、输出在动作执行后被验证，并将验证结果反馈给后续决策与学习。这正是 EmbodiedSkills 的定位——一个用于**编排（Orchestrating）、训练（Training）与部署（Deploying）** VLA 代理的统一框架。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

- 将**每个技能决策视为“执行提案”（Execution Proposal）**：运行时在执行前检查其先决条件，在执行后验证其输出结果。
- 通过一个**共享可执行技能接口（Shared Executable-Skill Interface）**，将高层技能选择、有界低层 VLA 执行与事后验证连接在同一代理循环中。
- 核心设计原则为**策略与运行时分离（Policy–Runtime Separation）**：策略只“提议”，运行时“执行约束”；这样可防止无效决策被静默转化为物理动作，并使失败显式化、可追踪。

### 2.2 六阶段闭环 AgentLoop

方法定义了一个受防护的有限阶段控制器（Guarded Finite-Stage Controller），包含六个语义阶段：

| 阶段 | 角色与代表性操作 |
|---|---|
| **Observe** | 捕获当前视觉证据，更新场景表征 |
| **Plan** | 将任务转化为可验证的子目标序列，分配预算 |
| **Preflight** | 检查当前子目标是否可执行（上下文、观察、机器人状态、策略可用性） |
| **Execute** | 调用低层 VLA 策略生成并执行一个**有界动作块（Bounded Action Chunk）** |
| **Verify** | 基于动作后的新证据判断子目标是否推进 |
| **Recover** | 对不可继续的失败进行解释、修正与安全重入 |

> 注意：这些阶段**不是固定一次性流水线**，而是由策略根据演化中的任务状态动态路由——可重新观察、修订计划、继续当前子目标、前推下一子目标或进入恢复。

### 2.3 三层状态与决策建模

- **方法级状态**：`s_t = (z_t, M_t, H_t)`，其中 `z_t` 为当前阶段，`M_t` 为可用任务工件（artifacts）集合，`H_t` 为有序历史轨迹。
- **策略上下文**：`C_t = Ψ(x, z_t, M_t, H_t)`，采用与部署一致的紧凑上下文压缩策略，保留完整计划、活动子目标、工件摘要与近期错误，而**不将原始仿真器内部状态或无限日志注入上下文中**。
- **决策空间**：三种控制器类型——`RunSkill(k, q)`（执行技能）、`AdvanceStage`（推进阶段）、`FinishRun`（终止运行）。

### 2.4 可执行技能契约

每个技能定义为五元组：

```
k = (X_k, Y_k, pre_k, exec_k, post_k, fail_k)
```

- `X_k / Y_k`：类型化的输入/输出模式
- `pre_k`：先决条件
- `exec_k`：可执行操作
- `post_k`：执行后的状态更新
- `fail_k`：失败映射为显式状态与证据

工件（Artifacts）携带**来源与新鲜度信息**：上下文改变时，仅依赖已变证据的工件失效，需刷新后才能重新授权物理动作。模型生成的结果在模式与先决条件验证前一律视为“提议”。

### 2.5 防护式运行时转换（Guarded Runtime Transition）

- **技能门控**：检查阶段一致性、技能是否属于当前阶段可用集、所有先决条件（`r(s_t) = 1`）是否成立。
- **推进门控**：检查当前阶段是否已产生后继阶段所需的证据。
- **终止门控**：独立验证 `FinishRun` 控制信号。
- **受防护的状态更新**：
  - 通过技能门控 → 执行技能、记录结果、失效陈旧依赖；
  - 通过推进门控 → 进入下一阶段；
  - 通过终止门控 → 结束运行；
  - 否则 → 记录被阻止的决策及其证据。

### 2.6 有界动作执行（Bounded Action Execution）

- 低层 VLA 策略将 `(活动子目标, 当前观察, 机器人状态, 预检证据)` 映射为**有界动作块** `a_t = (τ_t, U_t, H_t, η_t)`（动作类型、动作序列、视野长度、子目标与观察的锚定）。
- 动作块有效性检查 `R_act(a_t, s_t)` 核验：视野长度不超过上限、符合策略动作模式、数值有效、与当前子目标和观察一致。
- 一个语义子目标**可能需要多个有界动作块**，而不是硬塞进单一动作视野中。

### 2.7 验证与恢复

- 验证仅针对当前活动子目标，使用最新动作块**之后**捕获的证据。
- 输出语义路由：`Advance / Continue / Reobserve / Replan / Recover / Finish`。
- 恢复过程使用相同显式任务状态与失败证据生成修订后的执行上下文，并同样经过执行前检查。
- 最终任务成败始终由**环境的评估协议**决定，而非局部子目标判断。

### 2.8 组件级训练（Component-Level Supervised Adaptation）

- **规划器**：训练输入为任务指令与当前视觉上下文，输出有序的可执行语义子目标序列。
- **低层 VLA 策略**：使用子任务级演示，将（观察、机器人状态、活动子目标）映射到动作序列。
- **高层调度器**：使用 Qwen3-VL，在冻结低层 VLA 策略的情况下，基于部署一致的决策轨迹进行 SFT。
- **验证器**（可选）：从执行后观察与子目标完成标签中学习。
- **部署一致的训练样本**：训练输入边界与部署完全一致；只对模型生成 token 施加 loss，提示词、图像、工具结果、环境消息仅作上下文。
- **可选的闭环在线优化**：支持组内归一化奖励的 GRPO 风格目标，以及带掩码的剪裁目标；但明确为可选细化手段，替代不了组件级监督。

## 3. 实验设计：数据集、Benchmark 与对比方法

### 3.1 RoboTwin 2.0（50 任务）

- **设置**：每任务单独微调一个 π0.5 策略，采用子任务级演示；每任务 100 个 episode。
- **对比基线**：
  - 策略基线：ACT、DP、RDT、DP3
  - 通用 VLA 基线：π0、X-VLA、π0.5（LingBot-VA 报告值）
- **结果**：任务适配策略宏平均成功率 **86.20%**，高于 π0.5 参考值 82.74%（+3.46 个百分点），在 50 个任务中 39 个优于参考值。

### 3.2 LIBERO（四套件）

- **套件**：LIBERO-Spatial、LIBERO-Object、LIBERO-Goal、LIBERO-Long。
- **对比**：官方 OpenPI 参考。
- **结果**：平均成功率为 **97.40%**，OpenPI 为 96.85%（+0.55 个百分点）。其中 LIBERO-Long 进步最大（92.4% → 93.6%，+1.2）。

### 3.3 RMBench（记忆依赖任务）

- **任务**：Battery Try、Blocks Ranking Try、Cover Blocks、Press Button。
- **对比**：DP、ACT、π0.5、X-VLA（均为已发表 RMBench 结果）。
- **结果**：四任务宏平均 **12.5%**，高于所有对比列（对比值为 5.0 / 4.8 / 5.5 / 7.3）。

### 3.4 AgentLoop 消融实验

- 在全部 50 个 RoboTwin 2.0 任务上，每任务 100 episodes，共 5,000 episodes。
- **四个配置**：
  - **Full**：完整规划—执行—验证闭环 → 平均成功率 86.2%
  - **w/o Verify**：保留子目标序列与总预算，但删除中间验证 → 48.2%
  - **w/o Subtask**：保留总预算，但每个 chunk 只接收整任务指令（无子目标分解）→ 34.4%
  - **One chunk/subtask**：保留子目标序列，但每个子目标只允许一个 32 步动作块且无中间重试 → 19.5%
- **结论**：三者共同贡献显著——语义子目标分解、动作后验证与自适应持续执行均不可或缺。

## 6. 主要结论与发现

1. **执行接口可支撑强动作策略**：任务适配的子目标条件化 VLA 策略通过同一执行接口在 RoboTwin 2.0（50 任务）与 LIBERO（4 套件）上分别达到 86.20% 和 97.40%，证明该接口与特定 Benchmark 或任务分类无关。
2. **闭环机制的各组件均有独立贡献**：从 Full（86.2%）到 w/o Verify（48.2%）、w/o Subtask（34.4%）、One chunk/subtask（19.5%）的阶梯式下降说明——语义子目标分解、中间验证与自适应多块执行是长时程操作不可替代的三种机制。
3. **“策略提议 + 运行时强制”的核心架构有效**：使无效决策无法静默转为物理动作，使组件级失败显式化，为诊断和学习提供了结构化轨迹。
4. **固定共享接口带来模块化红利**：低层 VLA 策略可替换/适应而不必修改 AgentLoop；高层组件可在冻结低层策略的情况下独立改进。
5. **在记忆依赖场景中仍有明显短板**：RMBench 上仅 12.5% 平均成功率，说明“正确动作取决于先验交互历史”时，任务适配的执行方法仍面临重大挑战。

## 7. 优点与亮点

- **问题定位精准**：清晰指出现有 VLA 和 LLM-agent 方法各自盲区——“决策 ≠ 有效执行”，并据此提出系统性解决方案。
- **架构设计优雅**：“六阶段环路 + 函数契约（pre/post 条件）+ 运行时守卫”将长期存在于机器人学的“规划—感知—执行—验证”循环以统一形式化契约实现，兼顾灵活性与健壮性。
- **策略与运行时的清晰界限**是工程上的一大贡献：政策只做“提案”，运行时负责“执法”，防止无效决策变成物理动作，令失败可解释、可追溯。
- **模块化 + 稳定性并重**：接口固定意味着策略可替换、可独立训练、可冻结。训练与部署的数据格式一致，避免了 Sim2Real 类不一致问题。
- **消融实验严谨且逐任务透明**：Table 5 完整列出所有 50 任务的三种消融结果，不仅报告宏平均，给读者充分的二次分析空间。
- **评估范围有意识地从“动作准确率”转向“闭环代理能力”**：代理成功不仅仅是低层策略的功劳，还可以用统一轨迹界面分析中间决策、验证错误、恢复行为与延迟。
- **坦白而克制的定位**：在线 RL 优化被明确定义为“可选机制”，不以之充当主要实验结果的来源，避免夸大贡献。

## 8. 不足与局限

- **低层策略泛化性受限**：RoboTwin 2.0 的实例化为每个任务单独维护一个 π0.5 专家，训练、存储与部署成本较高；作者承认需要更强的子目标条件化通用策略。
- **上限受制于 VLM 组件的质量与校准**：显式契约可以阻止非法状态转换，但无法保证语义合理的模型决策在物理上是正确的——错误的物体接地点或子目标选择如果能通过模式检查，仍可能导致错误物理状态。
- **验证环节的固有盲区**：当任务进度被遮挡、视觉模糊、或依赖于视图中不可推断的物理属性时，验证器同样受限。
- **延迟开销**：相比单遍闭合动作策略，守卫循环中的额外 VLM 调用与动作后观察会显著增加延迟。
- **长周期误差累积**：长时间 episode 中，小规模规划与执行误差会累积，导致更多观察、重试与模型调用才能完成，增加了系统延迟和累积风险。
- **模块化伴随协调成本**：规划器、调度器、验证器与 VLA 策略的适配器独立专用化后，必须保证其各自行为在共享接口边界上相容。
- **实验范围**：所有实验均基于仿真环境（RoboTwin 2.0、LIBERO、RMBench），不包含真实机器人平台（文中提及与 Deep Robotics 合作但实验无真实硬件结果）；RMBench 任务仅 4 个且成功率绝对值较低，对其结论的统计强度有限。
- **算力与延迟数据缺失**：没有报告任何量化算力指标、推理时间或

推理时间或部署闭环额外开销的具体计量，使得该框架在真实机器人上的运行效率与可扩展性难以被量化评估，也削弱了“可部署性”这一主张的可验证性。

## 9. 整体评价与前景

综合全文，EmbodiedSkills 的贡献重点不在于推出某一个更强的新策略模型，而在于提出了一套**结构化、可组合、带显式校验的 VLA 代理运行范式**。它将机器人学习社区长期默认的“策略直接输出动作”的线性假设，升级为“提议—审查—执行—验证—恢复”的闭环回路，并以技能契约和受防护状态转换的形式落地。这一转变在工程语义上更符合真实操作任务的需求，也为后续研究提供了一个清晰的共同接口：只要各组件遵守同一契约，训练数据、部署格式与失败诊断便有了统一的“语言”。

从证据强度来看，论文在任务适配场景下给出了高成功率的实证支撑（RoboTwin 2.0 与 LIBERO），并用消融实验清晰证明了闭环各组件的边际贡献；但在通用低层策略泛化、真实硬件验证、记忆依赖场景以及量化开销等方面，仍留有明确的开放问题。未来最有价值的延伸方向可能包括：以更强的基础 VLA 模型替代每任务专家以降低维护成本；在真实机器人上验证验证器与恢复机制的有效性；以及将本框架定义的统一接口推广为社区标准，使不同团队开发的规划器、策略与验证器可以即插即用地在共享运行时中协作。

总体而言，这是一项**面向系统架构的、问题意识清晰、实验受控且写作负责**的研究，适合作为长时程 VLA 代理设计的重要参考基线；但其工程收益仍需在真实物理平台和更广泛任务分布上进一步检验。
