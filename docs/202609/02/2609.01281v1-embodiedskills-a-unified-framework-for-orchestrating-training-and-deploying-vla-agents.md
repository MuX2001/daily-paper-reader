## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射为机器人动作，但长时程任务需要的不仅仅是动作预测。智能体必须在物理状态演变过程中协调感知、规划、执行、进度验证和恢复。动作预测或模型生成的技能决策本身并不能保证所提议的操作在当前状态下有效，也不能保证其后续结果会得到验证。我们提出EmbodiedSkills，一个统一框架，将每个技能决策视为一个执行提议：运行时在执行前检查其前置条件，并在执行后验证结果。一个共享的可执行技能接口将高层技能选择、受限的低层VLA执行和动作后验证连接在单个智能体循环中。由于该接口保持不变，低层VLA策略可以被替换或调整，而无需改变智能体循环。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，从而为各个组件提供监督，并在有交互反馈时支持可选的在线自适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL和OpenPI/pi0.5实例化了EmbodiedSkills。任务自适应的低层VLA策略在50个RoboTwin 2.0任务上达到86.20%的平均成功率，在四个LIBERO套件上达到97.40%。这些结果确立了EmbodiedSkills中使用的任务自适应低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务自适应执行方法达到了12.5%的平均成功率。该框架提供了一个可训练和可检查的智能体层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

### 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：视觉-语言-动作（VLA）模型通过视觉感知与自然语言指令的联合建模，将输入直接映射为机器人动作，虽在多种任务中表现出较强的多面性，但面对**长时程具身操作任务**仍存在根本性不足。长时程任务的完成远非"预测下一段动作"即可，还需在物理环境状态持续演变中协同完成**感知、规划、执行、进度验证、失败恢复**等多项能力。
- **需要解决的关键问题**：
  1. 即使模型给出一个"合理的"技能调用或动作决策，也无法保证该操作在当前物理状态下**真实有效**（可能存在过期观测、参数缺失、阶段不匹配等问题）；
  2. 动作执行完后，系统缺乏机制确认其**是否确实推进了子目标**；
  3. 端到端 VLA 与基于 LLM 的机器人智能体各解决一部分问题：前者将中间决策隐式化，失败时难以定位原因；后者虽将工具调用与推理步骤显式化，但"显式决策"不等于"可执行"，提示工程无法强制约束或验证物理结果。
- **核心命题**：应构建一个**统一框架**，在高层决策（如技能选择）与低层物理执行之间建立"策略—运行时"分离的结构，使技能提议在执行前受先决条件校验、执行后受物理结果验证，并将完整过程记录为可训练、可诊断的结构化轨迹——即把**动作模型转化为闭环具身智能体**的"智能体层"。

### 二、方法论：核心思想、关键技术细节与算法机制

- **整体思想**：受"动作预测或模型生成的技能决策不等于有效执行"这一洞察驱动，EmbodiedSkills 将**每一个技能决策视为一个"执行提案"**。高层 VLM（如 Qwen3-VL）负责技能选择与进度判断，低层 VLA 策略（如 π0.5）在受控边界内生成动作块，而一个**受保护的运行时（Guarded Runtime）** 负责校验、执行、记录与状态转换。该结构使组件可分别训练与替换，运行时语义不随具体策略或基准改变。

- **核心架构**：EmbodiedSkills 围绕一个**共享技能契约（Shared Skill Contract）** 展开，将每个可执行技能定义为五元组：

  `k = (Xk, Yk, pre_k, exec_k, post_k, fail_k)`

  即类型化输入/输出模式、前置条件、可执行操作、结果状态更新、失败状态映射。模型输出（如规划结果、验证结论）仅视为"提议"，经合法性校验后才成为可支撑后续技能的**类型化工件（Artifact）**；感知结果、规划、动作等工件都带**来源性与时效性标签**，当依赖证据变化时自动失效，防止陈旧预测授权新的物理动作。

- **六阶段受控状态机**：运行时以有序阶段集合组织智能体循环：

  `Z = (Observe, Plan, Preflight, Execute, Verify, Recover)`

  但**并非固定单向管线**——根据任务状态，策略可回退观察、重规划、继续当前子目标、推进下一子目标或进入恢复模式。六个阶段及职责如下：

| 阶段 | 功能 | 退出证据 |
|---|---|---|
| Observe | 获取当前视觉与任务相关证据，更新场景表示 | 当前任务证据 |
| Plan | 将任务拆解为可验证子目标并分配执行预算 | 计划与活动子目标 |
| Preflight | 检查子目标是否具备执行条件，必要时刷新证据 | 通过的准备报告 |
| Execute | 调用低层 VLA 策略生成并执行受限动作块 | 执行报告 |
| Verify | 基于动作后的新证据判断是否取得进展 | 进度判定 |
| Recover | 在不可继续的失败后修订重试上下文 | 修订后的执行上下文 |

- **策略-运行时分离与受保护转换**：策略在其状态相关动作集合中选择三类控制决策之一：

  `d_t ∈ {RunSkill(k,q), AdvanceStage, FinishRun}`

  运行时分别以独立门控函数进行守卫：
  - **技能门控** `G_skill`：校验所在阶段、技能是否在该阶段许可集合中、所有前置条件与载荷参数是否满足；
  - **推进门控** `G_advance`：仅当当前阶段已产生后继阶段所需证据时才允许状态推进；
  - **终止门控** `G_finish`：独立于其他门控。
  
  未通过门控的决策被记录为**受阻决策（含证据）**，而不会静默转化为物理动作，从而使失败显式化、可审计。

- **受限动作执行**：低层 VLA 策略将 `(活动子目标, 当前观测, 机器人状态, 预检证据)` 映射为**有界的动作块**：

  `a_t = (τ_t, U_t, H_t, η_t)`

  其中 `τ` 为动作类型、`H_t ≤ H_max` 为有限视界、`η` 将该块锚定到特定子目标与观测上下文；运行时检查动作模式合法性、数值有效性、维度和目标一致性。一个语义子目标可能需多个动作块，每块执行完成后收集新证据再决定是否继续、推进或恢复。

- **验证与恢复**：仅在最新动作后的新鲜证据上评价**当前活动子目标**，输出语义路由 `V = {Advance, Continue, Reobserve, Replan, Recover, Finish}`；整体任务成功仍以环境评估器为准，而非局部子目标判断。

- **训练机制**：
  1. **组件级监督自适应**为核心方式：规划器以指令与视觉上下文→可执行子目标序列为训练目标；低层 VLA 策略利用子任务级示范进行独立微调；高层调度器在低层策略冻结情况下从"部署一致性轨迹"中学习阶段感知的技能选择。
  2. **部署一致性样本构造**：模型训练输入与部署时输入边界完全一致（同一压缩规则、同一历史上限），只对组件自身生成的 token 施监督，避免用测试时不存在的证据训练。
  3. **可选的闭环在线优化**：支持下述群组相对策略优化目标。给定同任务 M 条 rollouts，以 `A_i = (R_i − μ_G)/(σ_G + ϵ_norm)` 做组内归一化优势，用掩码裁剪目标优化生成 token 的似然比。论文明确将其视为**可选精化机制而非头号结果的来源**。

- **算法流程**：AgentLoop 在步骤 t 先生成紧凑上下文 `C_t = Ψ(x, z_t, M_t, H_t)`，计算合法动作集合 `A_t`，查询策略获得决策，运行时依据三种门控判定：通过则执行并更新状态，否则记录受阻决策与证据，统一追加至有序轨迹。

### 三、实验设计

- **数据集与基准环境**：
  - **RoboTwin 2.0**：含 50 个双臂操作任务的双臂操作基准，涵盖多物体构型、域随机化等设置；
  - **LIBERO**：四个套件——LIBERO-Spatial（空间泛化）、LIBERO-Object（物体泛化）、LIBERO-Goal（目标泛化）、LIBERO-Long（长时程任务）；
  - **RMBench**：四种依赖记忆的 M(n) 任务（Battery Try、Blocks Ranking Try、Cover Blocks、Press Button），用于检验跨历史交互记忆的条件执行能力。

- **对比方法**：
  - 策略级基线：ACT、DP（扩散策略）、RDT、DP3；
  - 通用 VLA 基线：π0、X-VLA、π0.5；LIBERO 上对比官方 OpenPI 参考值；
  - 基线数值取自 RoboTwin 2.0 基准、LingBot-VA 研究、OpenPI 官方与 RMBench 已发表结果。

- **实验任务设置**：
  1. RoboTwin 2.0 每任务微调独立 π0.5 策略（子任务级示范），每任务 100 个回合，报宏平均；
  2. LIBERO 报四个套件成功率与宏平均；
  3. RMBench 四个记忆任务报宏平均；
  4. **受控 AgentLoop 消融实验**：在全部 50 个 RoboTwin 2.0 任务、每任务 100 回合、共 5 000 个回合上与基线共用规划器、低层策略与初始状态，消融变量为是否保留中间验证、是否保留语义子目标、是否限制每子目标仅一个 32 步动作块。

- **主要数值结果**：
  - **RoboTwin 2.0**：自定义策略宏平均 86.20%，显著优于 LingBot-VA 报告的 π0.5 参考值 82.74%（+3.46 个百分点）；50 个任务中 39 个提升、1 个持平、10 个略降。
  - **LIBERO**：四套件宏平均 97.40%，优于 OpenPI 官方参考 96.85%（+0.55 个百分点），最大增益出现于 LIBERO-Long（92.4%→93.6%，+1.2）。
  - **RMBench**：四任务宏平均 12.5%，高于已发表的 DP（5.0%）、ACT（4.8%）、π0.5（5.5%）与 X-VLA（7.3%）。
  - **消融实验**：完整闭环管线 86.2%，无中间验证 48.2%，无语义子目标 34.4%，每子目标单动作块 19.5%——三个机制贡献显著递减。

### 六、论文主要结论与发现

1. **把技能决策视为执行提案并经过"受保护的运行时"验证**，是衔接模型级推理与物理执行的关键设计。将高层 VLM 的动作限制为"方案"，而非直接命令，可显著减少陈旧/非法动作执行从而提升整体成功率。
2. **受控闭环管理带来的增益巨大**：在相同低层策略与预算下，Full 闭环配置（86.2%）较无中间验证（48.2%）、无语义子目标（34.4%）、单动作块限制（19.5%）分别提升 38.0、51.8、66.7 个百分点——说明"语义子目标分解 + 动作后验证 + 自适应延续"三要素缺一不可。
3. **固定执行接口下的低层策略可替换**：相同接口支持 π0.5 在 RoboTwin 2.0（86.20%）、LIBERO（97.40%）两大异构基准上获得稳定表现，验证了框架层面的任务跨基准可移植性。
4. **训练路径的模块性**：冻结低层 VLA 策略单独训练高层调度器是可行的；部署一致性轨迹的监督足以训练规划、技能选择、验证等组件，无需端到端共训。
5. **任务记忆（RMBench）仍是重大挑战**：即使有子目标条件执行支撑，四任务宏平均仅 12.5%，揭示依赖交互历史的策略执行仍是开放课题。

---

### 七、优点

- **概念清晰、角色分层明确**：明确定义"策略提议 vs. 运行时执行"与"模型提案 vs. 类型化工件"，解决了现存 VLA 系统中"决策不等于有效可执行动作"的核心矛盾，工程概念与理论分离度好。
- **统一接口设计精巧**：以技能契约为单一抽象，贯穿**编排（Orchestration）、训练（Training）、部署（Deployment）** 三端；允许各组件独立训练和替换、部件级监督与可选的在线优化在同一轨迹结构上并存，而且不需要改变 AgentLoop。这一设计对工程实现与后续科研迭代均友好。
- **失败诊断性强**：每个技能的调用、验证、恢复等事件都被记录为结构化轨迹，可定位失败层（接地、规划、执行、验证或恢复），而非笼统成败。
- **消融实验严谨**：三组消融分别剥离三个关键机制，并保持 5000 回合的受控设置，方案干净利落；定量结论差异巨大，显著增强了核心设计主张的可信度。
- **多基准验证覆盖面广**：从仿真操作任务（RoboTwin 2.0）、长期泛化任务（LIBERO），到记忆任务（RMBench）均有评测，且对泛化性能提供了相对客观和全面的刻画。

---

### 八、不足与局限

- **低层策略为任务独立的专家模型**：每任务单独微调 π0.5（50+ 专家）在资源与部署成本上明显高于单一通用策略，研究者在实际中难以大规模维护；论文将此放到"Limitations"中承认——缺少对通用 VLA 低层策略的控制性测试。
- **长时程记忆类任务表现依然偏弱**：RMBench 的 M(n) 四任务仅 12.5%，虽优于基线但绝对值很低，说明跨状态历史推理能力远未解决，规划/验证器在高记忆负荷场景下的可靠性并未得到论证。
- **效率开销未被量化**：相较单通 action 策略，增加多轮观测、VLM 调度调用与验证推理会引入额外 **延迟与计算成本**，但论文未就平均单任务耗时、VLM 调用频率或整体预测开销给出数据。
- **验证器内在可信度受限**：当前验证依赖后验视觉观测，对遮挡、模糊或无法从当前视角观察到的物理性质（如力觉、温度等）缺乏判断力；错误的接地或语义合理的次优子目标仍可通过模式验证。论文自身亦承认"契约防止非法转换，但不保证语义决策正确"。
- **在线适应仅为主线之外的"可选"**：组级相对优势归因粗粒度（同回合内多个决策共享同一奖励），缺少端到端在线优化对整体任务成功率的实证显示。
- **算力资源与训练时长未报告**：导致难以评估工程可复现性和使用门槛。
- **实验公平性的微妙偏斜**：RoboTwin 主对比中"每任务单个模型"与"单位通用模型"相比的方式存在结构性倾向；RMBench 的四个比较参考值来源渠道不同，可能存在一定口径差异。
