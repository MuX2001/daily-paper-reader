## 摘要
视觉-语言-动作模型（VLA）已成为通用机器人学习的一种有前景的范式，其性能随模型和数据集的规模扩大而提升。然而，扩大机器人数据收集仍然具有挑战性，因为数据天然分布在不同的机器人、任务和地点上，使得集中式收集成本高昂或不可行。联邦学习提供了一种在去中心化机器人数据上进行训练的方式，但将其应用于 VLA 需要考虑异构的机器人客户端数据分布。我们提出 Co-VLA，将使用交替方向乘子法（ADMM）的共识优化应用于联邦 VLA 训练。我们表明，同一算法同时支持全模型训练和参数高效微调，并适用于固定秩和秩自适应适配器。Co-VLA 这一名称体现了共识与协作：拥有不同本地机器人数据集的客户端在不共享数据的情况下协作训练一个共享模型。我们的实验表明，在全模型训练和参数高效微调设置下，Co-VLA 均能达到与集中式训练相当的性能。

## Abstract
Vision-language-action models (VLAs) have emerged as a promising paradigm for general-purpose robot learning, with performance improving as models and datasets scale. Scaling robot data collection, however, remains challenging because data are naturally distributed across robots, tasks, and locations, making centralization costly or impractical. Federated learning offers a way to train on decentralized robot data, but applying it to VLAs requires accounting for heterogeneous robot client data distributions. We present Co-VLA, which applies consensus optimization using the Alternating Direction Method of Multipliers~(ADMM) to federated VLA training. We show that the same algorithm supports both full-model training and parameter-efficient fine-tuning with both fixed-rank and rank-adaptive adapters. The name Co-VLA reflects both consensus and collaboration: clients with different local robot datasets collaboratively train a shared model without sharing their data. Our experiments demonstrate that Co-VLA achieves performance comparable to centralized training in both full-model training and parameter-efficient fine-tuning settings.

## 2. 方法论

### 2.1 核心思想
- 为每个机器人客户端引入本地参数副本 xᵢ，服务器维护全局共识变量 z，求解约束优化：

  min_{x₁…x_N, z} Σᵢ fᵢ(xᵢ)  s.t.  xᵢ = z, i = 1,…,N

- fᵢ 为客户端 i 的本地动作监督损失（如交叉熵、ℓ1 回归、扩散/流匹配损失）。
- 与仅做参数平均的 FedAvg 不同，ADMM 通过**二次邻近项 + 对偶变量更新**显式推动本地与全局一致。

### 2.2 算法流程（Algorithm 1：过松弛 ADMM）
每一通信轮次 k：
1. **客户端（i = 1…N）**
   - 对偶更新：uᵢᵏ = uᵢᵏ⁻¹ + x̂ᵢᵏ − zᵏ（uᵢ 为累积共识间隙的拉格朗日乘子）
   - 原始更新：xᵢᵏ⁺¹ = argmin_{xᵢ} fᵢ(xᵢ) + (ρ/2)·‖xᵢ − zᵏ + uᵢᵏ‖²₂（实际用固定步数的本地梯度下降近似）
   - 过松弛：x̂ᵢᵏ⁺¹ = α·xᵢᵏ⁺¹ + (1−α)·zᵏ
2. **服务器**
   - zᵏ⁺¹ = (1/N)·Σᵢ (x̂ᵢᵏ⁺¹ + uᵢᵏ)，并广播 z 给所有客户端

- 超参数：ρ > 0 控制共识耦合强度；α ∈ (0,2) 为过松弛系数（α = 1 退化为标准 ADMM），可加速收敛。
- **开销**：客户端每轮仅增加一次对偶变量更新与一个二次正则项；服务器仅对 x̂ᵢ + uᵢ 求平均；通信量与 FedAvg 同量级。

### 2.3 联邦 LoRA 的共识化
- LoRA 更新：ΔW = BA，A ∈ ℝ^{r×k}，B ∈ ℝ^{d×r}。
- 传统联邦 LoRA 的问题：服务器分别聚合 A、B，无法还原平均后的更新（双线性聚合失配）。
- **Co-VLA 做法**：直接在低秩因子上施加共识约束，即 Aᵢ ≈ A、Bᵢ ≈ B（xᵢ = {Aᵢ, Bᵢ}，z = {A, B}）。
- 与已有方法对比：
  - FLoRA：服务器收集/堆叠因子再重分发，通信量随客户端数增长；
  - FlexLoRA：服务器重建完整更新并用 SVD 重新分解，计算重且引入近似误差；
  - Co-VLA：不平均独立漂移的适配器，而是让客户端就共享全局因子达成一致，从根本上缓解失配，同时保留低秩适配器的通信效率。

### 2.4 联邦稀疏 LoRA（SoRA）扩展
- SoRA 引入可训练门控 g ∈ ℝʳ：ΔWs = B(g ⊙ (As))，通过 ℓ1 惩罚自动选择有效秩，剪枝零门控行列后得到紧凑适配器。
- Co-VLA 将门控纳入共识变量：xᵢ = {Aᵢ, Bᵢ, gᵢ}，z = {A, B, g}，目标为

  min Σᵢ fᵢ(xᵢ) + λ‖g‖₁  s.t.  xᵢ = z

- **关键设计**：ℓ1 只施加在**全局门控**上，因此客户端本地更新与 Algorithm 1 完全一致；服务器端对 A、B 仍为平均，对门控做软阈值：

  gᵏ⁺¹ = S_{λ/(Nρ)} ( (1/N)·Σᵢ (ĝᵢᵏ⁺¹ + u_{g,i}ᵏ) )

  其中逐元素软阈值 S_ξ(v) = v−ξ (v>ξ)、0 (|v|≤ξ)、v+ξ (v<−ξ)。
- 即联邦稀疏 LoRA 仅增加服务器端软阈值操作，客户端训练流程不变。

## 3. 实验设计

### 3.1 模型与基准
- **模型**：SmolVLA（0.45B，冻结预训练 VLM 主干 + 流匹配动作专家）；X-VLA（0.9B，流匹配，可学习软提示）。均基于 LeRobot 实现，默认使用 bf16。
- **仿真基准**：LIBERO 四个任务套件（Spatial / Object / Goal / Long），每套件 10 个语言条件操作任务；每套件报告 500 次评估试验的平均成功率（每任务 50 次）。
- **联邦设置**：每套件模拟 10 客户端，一个任务一个客户端；每通信轮本地 100 步。

### 3.2 对比方法
- 通用联邦基线：**FedAvg**、**DiLoCo**（Nesterov 动量外优化器）
- 联邦 LoRA 专用基线：**FLoRA**、**FlexLoRA**
- 上界参考：**集中式训练（Centralized）**
- 定性对比（Table I）显示 Co-VLA 是唯一同时支持通用 VLA、LoRA 感知聚合、SoRA、非 i.i.d. 的方法。

### 3.3 真实世界实验
- **数据**：从 Open X-Embodiment 选取 4 个数据集混合（Berkeley Bridge / FMB / Jaco Play / Fractal），动作统一为末端位姿空间；共 402,753 条训练转移；4 个客户端各持一个数据源，分布严重不均衡（Fractal 46.94%、Bridge 23.46%、Jaco Play 15.66%、FMB 13.94%）。
- **开环评估**：预测动作与真值的 ℓ1 误差（相对集中式基线），比流匹配训练损失更能反映下游性能。
- **闭环评估**：SO-101 机械臂上 4 个任务（堆叠、抓放、分类、折叠），每任务 50 条示范；每任务 40 次试验（20 次 × 2 轮重复），物体位置相对训练示范平移 1–2 cm。

### 3.4 主要超参数
- Co-VLA：ρ = 10⁻⁴，α = 1.8；DiLoCo：外学习率 0.7，动量 0.9（在 LIBERO-Long 训练集上网格搜索）。
- SmolVLA 从零训练：batch 64，lr 10⁻⁴，100k 步；LoRA 微调：batch 32，rank 64，lr 10⁻³，100k 步，LoRA 施加于**所有线性层**（作者发现优于 LeRobot 默认只加在 q、v 与状态-动作投影上）。
- X-VLA：rank-8 LoRA 施加于所有线性层，并微调软提示、动作编码器/解码器；基础 lr 10⁻⁴。
- SoRA：λ = 10⁻⁵，门控参数保持 float32（bf16 会导致门控塌缩为零）。
