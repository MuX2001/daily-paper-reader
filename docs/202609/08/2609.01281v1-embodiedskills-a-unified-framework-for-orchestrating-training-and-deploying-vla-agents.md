## 摘要
视觉-语言-动作（VLA）模型直接将视觉观察和语言指令映射为机器人动作，但长期任务需要的不只是动作预测。智能体必须随着物理状态的变化协调感知、规划、执行、进度验证和恢复。动作预测或模型生成的技能决策本身并不能保证所提出的操作在当前状态下有效，也不能保证其结果会被验证。我们提出EmbodiedSkills，一个统一框架，将每个技能决策视为一个执行提议：运行时在执行前检查其前置条件，并在执行后验证结果。一个共享的可执行技能接口将高层技能选择、受限的低层VLA执行和动作后验证连接在一个单一智能体循环中。由于该接口保持不变，低层VLA策略可以被替换或适应，而无需改变智能体循环。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，这些轨迹为各个组件提供监督，并在交互式反馈可用时支持可选在线适应。我们用RoboTwin 2.0和LIBERO上的Qwen3-VL和OpenPI/pi0.5实例化了EmbodiedSkills。任务自适应的低层VLA策略在50个RoboTwin 2.0任务中平均成功率为86.20%，在四个LIBERO套件中平均成功率为97.40%。这些结果确立了EmbodiedSkills中使用的任务自适应低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务自适应执行方法实现了12.5%的平均成功率。该框架提供了一个可训练和可检查的智能体层，将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

## 二、方法论：核心思想与关键技术细节

### 1. 核心思想
- 将技能决策视为**受守卫的“提议”**（guarded proposal），而不是直接可执行结论：
  - 策略（policy）负责提出结构化的技能动作；
  - 运行时（runtime）负责执行“前置条件–合法性–状态转移”的守卫检查，并在执行后产生结果验证信号；
  - 两者通过**共享技能契约/接口**（shared skill interface）解耦。
- 这一设计的优越性：低层 VLA 策略可被替换或单独适配，而无须重写整个智能体循环，由此为“编排（orchestration）—训练（training）—部署（deployment）”提供了统一且可演化的系统结构。

### 2. Agent 状态与决策表示
- **方法级状态**：st = (zt, Mt, Ht)，其中
  - zt 表示当前**阶段**（phase）；
  - Mt 表示**任务工件集**（artifacts，如当前观测、物体绑定结果、世界状态、活跃子目标、预检证据、执行报告、验证报告等）；
  - Ht 表示有序的**循环历史轨迹**（loop trace）。
- 策略看到的上下文为经过压缩的部署一致表示：
  - Ct = Ψ(x, zt, Mt, Ht)，即保留完整计划、活跃子目标、当前工件概要、近期错误与有界历史，而将原始模拟器内部量和无界日志排除在外。
- **策略动作有三种控制类型**：
  - RunSkill(k, q)：调用可执行技能并携带结构化参数；
  - AdvanceStage：阶段前移；
  - FinishRun：结束整个回合。
- 潜在假设：不同控制类型对应不同守卫，运行时以相异的不变量分别执行 Gskill、Gadvance 与 Gfinish 判断。

### 3. 可执行技能契约
每个技能用五元组定义：
k = (Xk, Yk, prek, execk, postk, failk)，即张量化的输入输出模式、前置条件、可执行操作、结果状态更新及失败映射。
- 契约同时适用于模型技能与确定性操作；
- 工件带**来源（provenance）与新鲜度（freshness）标记**，防止在依赖变化后继续复用过期观察或计划；
- 模型产生的输出在**验证通过前仅为“提议”**，验证后成为正式工件或显式失败证据。

### 4. 六阶段受守卫循环
运行时例用有序阶段集：
Z = (Observe, Plan, Preflight, Execute, Verify, Recover)
- **Observe**：获取当前视觉证据并提取任务相关线索；
- **Plan**：将任务转换为可验证的有序子目标计划并分配执行预算；
- **Preflight**：检查任务文本、当前观测、机器人状态、环境与 VLA 策略可用性，必要时刷新观察；
- **Execute**：低层 VLA 策略在“有界动作块”内生成并执行动作块（horizon 有上限，例如 32 步）；
- **Verify**：以执行后的新鲜证据判断进度，得到语义路由 V={Advance, Continue, Reobserve, Replan, Recover, Finish}；
- **Recover**：修订上下文并选择安全再入场阶段。
**注意**：以上不是固定单程流水线——新证据可能使计划回退到 Observe/Plan 等更早阶段。

### 5. 有界动作执行与验证
- 执行层框架：
  (gt, Ot, Ft) → at → et
- 动作块定义为 at = (τt, Ut, Ht, ηt)，其有效条件为：
  - 0 < Ht ≤ Hmax；
  - 符合策略自身的动作模式 Σp；
  - 动作块新鲜且与当前子目标/观测一致；
  - Ut 动作值有效。
- 一个语义子目标可能对应多个动作块；Verifier 只在最新证据上评估当前子目标是否推进，并返回语义路由。整体任务成功仍由环境评测器判定。

### 6. 模块化接口与训练环路
- EmbodiedSkills 允许 Planner、Verifier、Skill Selector、低层 VLA 策略等组件共享同一个基础视觉‑语言模型 + 各自阶段适配器，也可用不同模型，仅要求输入输出遵循相同技能/状态契约。
- 训练以**组件级监督（component-level supervision）**为主；在线闭环优化为可选补充（经同一结构化轨迹接口收集数据并支持如 GRPO 式目标的可选更新）。
- 其对高层调度器用 Qwen3‑VL 做部署一致监督，同时低层 VLA 策略冻结，便于隔离优化目标。

## 三、实验设计

### 1. 数据集 / 场景与评测基准
- 主实验一：**RoboTwin 2.0**（双机械臂操纵基准）
  - 覆盖 50 个操纵任务（操作、堆叠、放置、按钮、开关等）；

  - 每个任务 100 个 episode，报告宏平均成功率。
- **LIBERO** 基准：
  - 四个套件：LIBERO-Spatial（空间）、LIBERO-Object（物体）、LIBERO-Goal（目标）、LIBERO-Long（长时程）；
  - 平均成功率作为数值指标。
- 补充实验：**RMBench** 中的四个记忆依赖 M(n) 任务（如 Battery Try、Blocks Ranking Try、Cover Blocks、Press Button）——用于考察“正确动作依赖先前交互历史”的挑战。

### 2. 低层 VLA 策略与对比方法
- 低层策略：基于 **OpenPI/π0.5** 微调，对每个 RoboTwin 2.0 任务训练独立任务适配策略；
- 高层组件：基于 Qwen3‑VL；
- 对比方法包括两类：
  - 传统专有策略基线：ACT、DP（扩散策略）、RDT、DP3；
  - 通用 VLA 基线：π0、X-VLA、π0.5、OpenPI 官方参考；
  - 另对比 LingBot‑VA 报告的 π0.5 结果与 RoboTwin 2.0 benchmark 官方基线。

### 3. AgentLoop 消融实验设置
在全部 50 个 RoboTwin 2.0 任务上、每任务 100 episodes（总计 5,000 episodes），进行三种受控变体对比：
- **Full**：完整“计划–执行–验证–重试”闭环；
- **w/o Verify**：保留参考子目标和总执行预算，但不进行中间验证；
- **w/o Subtask**：保留总预算，但每块只给原始完整任务指令；
- **One chunk/subtask**：保留子目标序列，但每子目标恰好执行一个 32 步动作块且不进行中间重试。

### 4. 评测打分机制
- 只使用各基准提供的终止评测器（terminal evaluator）判断是否成功；
- 不将任务级正确性判断塞进高层模型提示，而在运行时层面区分“本地子目标验证”与“全局终止成功”。

## 六、主要结论与发现

1. **RoboTwin 2.0 结果**：任务适配 π0.5 策略达到 **86.20%** 宏平均成功率，较 LingBot‑VA 报告的 π0.5 参考结果 82.74% 提升 **3.46 个百分点**；在 50 任务中 39 个提升、1 个持平、10 个下降；最大增益出现在接触敏感/多阶段任务并伴有高成功率任务的有限回退。
2. **LIBERO 结果**：VLA 策略实例在四个套件平均 **97.40%**，超过 OpenPI 官方参考的 96.85%（+0.55 个百分点），其中 LIBERO-Long 增益最大（+1.2 个百分点）。
3. **RMBench 记忆依赖任务**：任务适配执行方式只达到 **12.5%** 行为平均值，说明“需要历史记忆才能正确决定动作”的任务仍是显著短板。
4. **AgentLoop 消融**：
   - Full（闭环）86.2%；
   - 去掉中间验证 → 48.2%（−38.0 点）；
   - 去掉子目标语义（全任务指令）→ 34.4%（−51.8 点）；
   - 每个子目标仅一个动作块 → 19.5%。
   - 结论互相印证：显式子目标、行为后验证与自适应连续多个动作块三种机制缺一不可。
5. 框架层面的发现：策略–运行时分离、可替换低层策略和结构化轨迹能较好地把“强低层执行”转化为“闭环可诊断系统”，实现跨基准的迁移和部署诊断统一。

## 七、优点

1. **设计清晰**：每个技能决策被当作受守卫的提议，由运行时负责安全与状态一致性，这使高度不可控的 LLM/VLA 输出能在物理动作之前得到系统化校验。
2. **模块化与可替换性**：共享技能接口让 Planner、Verifier、低层 VLA 和适配器可独立训练、更换或外包给确定模块，而主循环保持不变。
3. **统一训练/部署边界**：训练样本与部署一致，组件不依赖测试时不可见的证据；结构化执行轨迹可服务于“组件监督”“失败归因”“可选在线优化”三个用途。
4. **消融设计质量较高**：三个变体分别剥离“验证、子目标语义、多块重试”，能较精确说明闭环设计中每个机制的贡献。
5. **跨基准验证充分**：同时给出 RoboTwin 2.0 大任务集、LIBERO 泛化套件与 RMBench 挑战性指标，展示接口跨任务、跨场景的一致性。
6. **诚实报告局限**：显式承认 50 个任务单独微调的现实成本、记忆型任务短板以及模块化协调开销，未过度声称通用性。

## 八、不足与局限

1. **低层策略的“任务专化”悖论**：RoboTwin 2.0 中每任务各自微调 π0.5，训练/存储/部署成本高，与“通用 VLA 智能体”目标存在差距；作者也承认更需要“更强子目标条件化的通用策略”。
2. **运行时并不能纠正语义错误**：运行时只检查“合法转移”和“格式条件”，若模型错误地识物或选择了语义上合理但物理目标错误的子目标，验证仍可能被通过。
3. **验证与可视性制约**：在结果被遮挡、视觉歧义或依赖不可见属性时，验证失效，整体仍依赖底层视觉‑语言组件的校准质量。
4. **模块整合成本与误差累积**：组件级适配在接口边界须保持兼容；长时程 episode 中小误差可能逐级累积，越来越多的重试与模型调用会增加观测数、时延和开销。
5. **缺少真实机器人实验**：所有定量结果均来自仿真，贴近真实世界的可迁移表现仍待验证。
6. **记忆与长期历史建模薄弱**：RMBench 四个任务仅有 12.5% 成功率，说明系统对“需记忆的前序交互”支持有限；论文对记忆机制没有专门处理。
7. **资源开销与算力透明度不足**：无 GPU 统计；高层模型每轮多一次 VLM 调用、每个子目标多次验证，相对单遍动作策略增加了时延；未给出端到端总训练成本。
8. **实验外部效度限制**：LIBERO 四套件已接近饱和，区分度低；在线强化学习仅作为“可选机制”提出，未提供独立实验证据。
